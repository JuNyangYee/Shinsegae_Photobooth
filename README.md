# 신세계 크리스마스 - 포토부스

스크린 앞 스윗스팟(발자국 매트)에 서면 자동으로 3·2·1 카운트다운 후 사진을 찍어 보여주는 **비접촉 웹 포토부스**다.

```text
스크린 앞에 서요 → 3·2·1 자동 촬영 → 특별한 사진으로 변해요 → 사진을 받아요
```

## 현재 상태

- 1단계(개발용 정적 서버, 9:16 좌우 반전 카메라 미리보기, 카메라 상태·자동 회복)와 2단계(로컬 MediaPipe 얼굴 감지, "인식됨 / 인식 안됨" 임시 표시, 운영자용 인식 범위 조절·저장)가 끝났다.
- 3단계(촬영 한 사이클)가 끝났다. 인식 영역에 사람이 인식되면 자동으로 3·2·1 카운트다운 → 한 장 촬영(반전·9:16 원본 해상도) → 결과 10초 → 쿨타임 5초 → 대기로 돈다. 카운트다운 중 사람이 떠나면 취소하고, 쿨타임이 끝날 때 계속 서 있으면 바로 다음 회차를 시작한다. 운영자 키(`S`)로 수동 촬영도 할 수 있다.
- 4단계(안정화·현장 실행) 진행 중: 감지기 장애 안내·자원 누적 방지(4-1), 현장 실행 스크립트(4-2), 조절값 파일 저장·자동 촬영 일시정지 `P`(4-3)까지 구현했다. 브라우저 확인 도구와 장시간 실측(4-4)까지 했다. 남은 것은 현장 실측이다.
- 5단계(사진 효과) 진행 중: 사진 효과는 **"유화 · 획 (세부 보존)"**으로 정했다(2026-10-16). 5-1에서 필터를 WebGL2로 이식해 **카메라 미리보기에 실시간으로** 보인다(초당 24장, 스톱모션 느낌). 5-2에서 **촬영 결과(1080×1920)도 셔터 순간 미리보기와 같은 그림**으로 만들고, 운영자 조절 화면(`E`)과 조절값 파일을 붙였다. 효과를 쓸 수 없으면 미리보기는 원본으로, 결과는 원본 사진으로 대신한다.
- 6단계 진행 중: 6-1에서 유화 뒤에 **감열지 흑백 시뮬레이션**을 붙였다(사용자 결정 2026-10-19). 미리보기와 촬영 결과 모두 80mm 용지(가로 576점, 9:16이면 576×1024)의 1비트 점 그림이고, **화면에 보이는 것이 곧 출력물**이다. 결과에는 인쇄용 1비트 데이터(래스터 비트·1비트 PNG)가 메모리에만 붙는다. 인쇄 연동은 아직 없다.
- 7-1에서 1비트로 바꾸는 방식("흑백 스타일")을 더했다: 톤 점(6-1) / 질감 강조 점 / 흐름 선 / 붓 결 선. 미리보기가 덜 꿈틀거리게 획 다시 그리기 기본값을 0.05로 낮췄다.
- 8단계에서 화면 기본값을 **회색조 유화**로 바꿨다(사용자 결정 2026-10-19, "흑백 유화가 너무 심하다"): 카메라 영상 → 단순 흑백 → 유화(`oil2f` 그대로) → 화면. 미리보기와 결과(1080×1920 JPEG)는 무채색 유화이고, 감열지 인쇄용 1비트 데이터(576×1024)는 결과 사진에서 따로 만들어 메모리에만 둔다. 6·7단계의 감열지 1비트 화면(붓 결 선 등)은 `E`에서 고를 수 있게 남겨 두었다.
- 7-2: 관람객·운영자 화면을 **미니멀(무채색, 미리보기가 주인공)**으로 다시 디자인했다(6-2의 크리스마스 장식 톤은 폐기). 글자·3·2·1 숫자는 화면 아래 가장자리(영역 아래 15% 안)에만 있어 얼굴을 가리지 않는다. 서체는 Pretendard·Noto Serif KR(SIL OFL 1.1, `src/web/assets/fonts/`)이고 관람객 문구는 `src/web/config/guest-text.js`에 모여 있다.
- 현재 개발 범위는 **카메라 촬영부터 결과 화면 표시까지**다. 인쇄는 이후 범위다.
- PC 한 대에서 로컬 웹 서버(`localhost`)를 띄우고, 같은 PC의 브라우저를 전체화면으로 사용한다.

## 개발용 실행

저장소 루트에서 Windows PowerShell 5.1로 서버를 띄운다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File bin\server\serve.ps1
```

- Chrome에서 `http://localhost:8765/`를 연다. 포트를 바꾸려면 `-Port 8800`처럼 붙인다.
- `127.0.0.1`이 아닌 `localhost`로 접속한다(`127.0.0.1`은 400). 루프백(같은 PC)이 아닌 주소로 들어온 요청은 403으로 거절한다.
- `OBS Virtual Camera`가 있으면 그 장치를, 없으면 기본 카메라를 사용한다.
- `D` 키: 개발용 정보 표시 토글(구역별 표, 정상·주의·오류 색, 6-3). 카메라 상태·오류 원인·재시도 횟수, 카메라 라벨, 실제 영상 크기, 9:16 영역 크기와 함께 감지 정보(delegate, 감지 시간·빈도, 얼굴 수·인정 수, 안정화 진행), 사진 효과 상태(`effect` 줄: 처리 해상도, 초당 그림 수, 그리기 시간, 장애 원인, `output` 줄: 출력 모드·인쇄 해상도·점 방식, `print` 줄: 마지막 결과의 인쇄 데이터)를 보인다. 인식 영역(흰 점선)과 감지 박스(인정 초록, 제외 빨강)를 겹쳐 그린다.
- 카메라가 끊기거나 열리지 않으면 화면에 "준비 중입니다" 문구를 띄우고 자동으로 다시 연결한다.
- 외부로 나가는 요청은 `index.html`의 CSP로 막는다. 콘솔에 MediaPipe 사용 통계 전송(`odml.pa.googleapis.com`)이 차단됐다는 오류가 한 번 찍히는 것은 정상이다.
- 종료: 서버 창에서 Ctrl+C

## 현장 실행

| 파일 | 하는 일 |
|---|---|
| `Launch.bat` | OBS(가상카메라, 꺼져 있을 때만) → 로컬 서버(창 없이) → Chrome 키오스크 순서로 띄운다. 다시 실행하면 이 프로젝트의 서버와 키오스크 Chrome을 닫고 새로 띄운다 |
| `Shutdown.bat` | 키오스크 Chrome(전용 프로필)과 로컬 서버만 종료한다. 일반 Chrome은 종료하지 않는다. OBS는 `obs_stop_on_shutdown=true`일 때만 종료한다 |
| `Setup-Startup.bat` | 현재 사용자의 시작 프로그램 폴더에 `Launch.bat` 바로가기를 만든다. `Setup-Startup.bat -Remove`로 제거한다. 관리자 권한은 필요 없다 |

- 실패하면 콘솔 창이 멈춰 있고, 원인은 `logs\launch_*.log`(서버 출력은 `logs\server_*.log`, 종료는 `logs\shutdown_*.log`)에 남는다. 종류별로 최근 20회분만 남긴다.
- 키오스크 화면은 `Shutdown.bat`으로 닫는다. 키보드(`Alt+F4`)로 닫히는지는 아직 키오스크 화면에서 확인하지 않았다.
- `Launch.bat`은 콘솔에서 실행한다. 출력을 파이프로 받으면 서버가 끝날 때까지 기다린다.

### 첫 설치 (현장 PC)

1. Google Chrome과 OBS Studio를 설치한다. 확인한 버전은 Chrome 155, OBS 32.2.1이다.
2. OBS에서 웹캠 소스, 9:16 크롭·회전·보정, 출력 해상도(화면 해상도에 맞춤)를 설정하고 가상카메라를 한 번 켜 본다. 반전은 OBS에서 하지 않는다(웹에서 한다). 트레이로 시작하려면 OBS 설정의 "시스템 트레이 사용"을 켜 둔다.
3. 저장소를 받은 뒤 `Launch.bat`을 한 번 실행한다. `settings.ini`가 없으면 `settings.example.ini`에서 만들어진다. 다른 값이 필요하면 `settings.ini`를 고치고 다시 실행한다.
4. **카메라 권한:** 키오스크 화면에 카메라 권한을 묻는 창이 뜨면 마우스로 "허용"을 누른다. 전용 프로필에 저장되어 다음부터는 묻지 않는다. 포트(`server_port`)나 프로필 폴더를 바꾸면 다시 한 번 허용해야 한다.
5. **인식 범위:** 카메라와 발자국 매트를 설치한 뒤 키오스크에서 `R`로 인식 범위를 조절하고 "저장"을 누른다. 개발 PC의 값은 쓰지 않는다(카메라·매트 위치가 다르다).
6. 부팅 시 자동 실행이 필요하면 `Setup-Startup.bat`을 실행한다. 바로가기는 Windows에 로그인할 때 실행되므로, 무인 운영이면 자동 로그인을 따로 설정한다.

### `settings.ini` 키

값을 비우면 자동·기본값을 쓴다. 경로에는 `%LOCALAPPDATA%` 같은 환경 변수를 쓸 수 있다. 실행할 때 빠진 키만 예시에서 덧붙이고, 있는 값은 바꾸지 않는다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `server_port` | `8765` | 로컬 서버 포트. 카메라 권한은 포트별로 저장된다 |
| `chrome_path` | (자동 탐색) | `chrome.exe` 경로 |
| `chrome_profile_dir` | `%LOCALAPPDATA%\ShinsegaePhotobooth\ChromeProfile` | 키오스크 전용 Chrome 프로필. 저장소 밖이어야 한다 |
| `kiosk` | `true` | `true`면 전체화면 키오스크, `false`면 일반 앱 창(시험용) |
| `window_position` | (없음) | 띄울 모니터의 좌표 `x,y`. 예: 오른쪽 두 번째 모니터면 `1920,0` |
| `window_size` | (없음) | 창 크기 `너비,높이`. `kiosk=false`일 때만 쓴다 |
| `obs_path` | (자동 탐색) | `obs64.exe` 경로 |
| `obs_autostart` | `true` | OBS가 꺼져 있으면 가상카메라를 켜고 트레이로 시작 |
| `obs_stop_on_shutdown` | `false` | `Shutdown.bat`이 OBS도 종료할지 |

자세한 동작과 Chrome 플래그의 이유는 [docs/SYSTEM.md](docs/SYSTEM.md) 1절 "현장 실행 스크립트"를 따른다.

## 운영자 단축키 (관람객용 아님)

| 키 | 동작 |
|---|---|
| `D` | 개발용 정보와 감지 박스 겹쳐 그리기 켜기·끄기 |
| `R` | 인식 범위 조절 화면 열기·닫기 (`Esc`로도 닫음). 열려 있는 동안은 인식에 의한 자동 촬영을 막는다 |
| `E` | 사진 효과 조절 화면 열기·닫기 (`Esc`로도 닫음). 유화: 강도·붓 크기·획 다시 그리기·초당 그림·색 보정·세부 보존 문턱·미리보기 처리 해상도. 출력(6-1·8단계): 출력 모드(회색조 유화·감열지·회색조·끔)·점 방식·용지 폭(80mm 576점·58mm 384점)·밝기·대비·감마. 흑백 스타일(7-1): 스타일·질감 세기·선 간격(쓰지 않는 항목은 막힌다). 저장·닫기 규칙과 자동 촬영 막기는 `R`과 같다. `R`과 동시에 열리지 않는다 |
| `S` | 수동 촬영 시작 (대기 상태이고 카메라가 준비됐을 때만. 진행 중·쿨타임 중에는 무시). 수동 회차는 사람이 없어도 끝까지 찍는다 |
| `X` | 강제 초기화: 카운트다운·결과·쿨타임 어디서든 사진을 정리하고 바로 대기로 (쿨타임 없음). 촬영 중지 수단은 아니다. 사람이 인식된 채 서 있으면 곧바로 다시 자동 촬영이 시작되므로, 자동 촬영을 막으려면 `P`를 누른다 |
| `P` | 자동 촬영 일시정지·다시 켜기. 멈추면 인식으로 시작된 카운트다운도 취소된다. `S` 수동 촬영은 그대로 된다. 화면 오른쪽 위에 "자동 촬영 일시정지 (P)"가 작게 보인다. **저장되지 않으므로** 새로고침하거나 `Launch.bat`으로 다시 시작하면 자동 촬영이 다시 켜진다 |

`Ctrl`·`Alt` 등 수정 키와 함께 누르면 무시한다. `D` 화면의 `session`·`capture`·`resources` 줄에서 촬영 상태, 실제 캡처 크기, 남은 이미지 자원 수를 볼 수 있다.

인식 범위 조절(`R`)은 마우스를 연결해 쓴다.

- 흰 사각형("인식 영역")을 끌어 옮기고, 모서리·변의 작은 사각 핸들로 크기를 바꾼다.
- 슬라이더로 최소·최대 얼굴 크기, 최소 신뢰도, (고급) 판정 시간을 바꾼다. 영역 가운데의 파란·붉은 사각형이 최소·최대 얼굴 크기 기준이다.
- 바꾸는 즉시 인식 판정에 반영되고, 감지된 얼굴은 초록(인정)·빨강(제외)으로 보인다.
- **저장**을 눌러야 조절값 파일 `config\presence.local.json`(저장소 폴더 안)에 남는다. 서버가 실행 중이어야 저장된다. 실패하면 패널에 이유가 보이고 저장되지 않은 상태로 남는다. 저장하지 않고 닫으면 저장된 값으로 돌아간다. "취소"는 저장된 값으로, "기본값으로"는 기본값으로 되돌린다.
- 파일은 브라우저 프로필과 무관하다. 다른 프로필로 열어도 같은 값을 쓴다.
- **현장 PC를 옮기거나 저장소를 새로 받을 때는 `config\presence.local.json`을 복사해 둔다.** Git에 올라가지 않는 파일이다. 파일이 없으면 기본값으로 시작한다(예전에 브라우저 `localStorage`에 저장한 값이 있으면 처음 시작할 때 파일로 옮기고 브라우저 쪽은 지운다).
- 파일을 지우면 기본값으로 돌아간다. 파일을 직접 고칠 수도 있지만, 범위를 벗어난 값은 불러올 때 고쳐진다. 고친 내용은 `D` 화면 `settings` 줄에 보인다.
- "현재값 JSON"을 열어 값을 복사해 둘 수 있다.

자세한 규칙은 [docs/SYSTEM.md](docs/SYSTEM.md) 5절 "인식 범위 조절"을 따른다.

사진 효과 조절(`E`)도 같은 방식이다.

- 슬라이더를 움직이면 바로 미리보기에 보인다. **저장**을 눌러야 `config\effect.local.json`(저장소 폴더 안, Git 제외)에 남는다. 저장하지 않고 닫으면 저장된 값으로 돌아간다.
- 파일이 없으면 기본값(사용자가 고른 세팅)으로 시작한다. **현장 PC를 옮길 때는 `config\presence.local.json`과 함께 `config\effect.local.json`도 복사한다.**
- 현장 PC가 느리면(`D` 화면 `effect` 줄의 초당 그림 수가 설정보다 적거나 화면이 끊기면) **먼저 초당 그림을 낮추고, 그래도 느리면 미리보기 처리 해상도를 낮춘다.** 처리 해상도를 낮추면 미리보기가 결과 사진보다 부드럽게 보인다.
- 출력 모드 기본값은 **회색조 유화**다(8단계). 감열지는 화면도 1비트 점(6-1·7-1), 회색조는 컬러 유화를 회색으로, 끔은 컬러 유화(예전 결과, JPEG)다. 조절값 파일에 모드가 저장돼 있으면 그 값을 쓴다(7단계 이전 파일은 감열지). 점 방식 기본값은 **블루 노이즈**(GPU)이고, 회색조 유화에서는 결과의 인쇄 데이터에 쓴다. Atkinson·Floyd–Steinberg(CPU 오차 확산)는 점이 그림마다 크게 바뀌어 감열지 미리보기가 지글거리고 메인 스레드를 더 쓴다(로그 2026-10-19-01). 밝기·대비·감마는 끔이 아니면 쓴다.
- 흑백 스타일 기본값은 **붓 결 선**(사용자 결정)이고, 감열지 모드를 고를 때만 쓴다. 톤 점은 6-1과 같고, 질감 강조 점은 점 방식을 함께 고른다. 흐름 선·붓 결 선은 점 방식을 쓰지 않는다(`docs/SYSTEM.md` 6절 "흑백 스타일").
- 감열지 화면의 종이색·잉크색은 `src/web/config/config.js`의 `thermalDisplay`이고 화면에서만 쓴다. 인쇄 데이터는 순수 1비트다.
- 자세한 규칙은 [docs/SYSTEM.md](docs/SYSTEM.md) 6절 "사진 효과(유화 · 획)"·"회색조 유화"를 따른다.

인식 판정·설정, 조절값 불러오기, 감지기 재생성·상태, 안내 규칙, 로그 제한, 영역 끌기, 촬영 상태 기계, 자동 시작·일시정지, 캡처 영역 계산, 사진 효과(획 목록·해상도 비례·설정·미리보기 상태), 감열지 출력 단계(레벨·인쇄 해상도·축소·디더링·인쇄 비트·1비트 PNG), 회색조 유화(입력 회색조 계수·렌더 경로·결과와 인쇄 데이터), `src/web/core/` 의존 규칙의 Node 테스트다(`test/`, 하위 폴더는 `src/web/`과 같은 이름). npm test

## 브라우저 확인 (개발 PC 전용)

실제 앱을 임시 프로필의 headless Chrome으로 띄워 주요 흐름을 확인한다. Windows, Chrome, Node 22 이상이 필요하고 의존성 설치는 필요 없다. 한 번에 약 100초 걸린다.

```powershell
npm run check:browser                              # 가짜 카메라
npm run check:browser -- --camera real             # 실제 카메라(OBS 가상카메라 우선)
npm run check:browser -- --soak --camera real      # 장시간 실측 기본 10분 (20초마다 S, 1분마다 기록 → logs\soak_*.csv)
npm run check:browser -- --soak 60 --camera real   # 더 길게: 분을 준다
```

- 확인하는 것: 페이지 로드·카메라·감지기, `S` 한 사이클과 사진 자원 정리, 사진 효과 미리보기(초당 그림 수, 컨텍스트 손실 → 원본 미리보기 → 복구, WebGL2 생성 실패 → 원본 미리보기), 촬영 결과(회색조 유화 기본값: 1080×1920 JPEG가 셔터 순간 미리보기와 같은 그림, 미리보기·결과 무채색, 인쇄 데이터 576×1024 1비트, 결과 폭 1/2), 출력 모드 3단계·점 방식·용지 폭 저장 → 새로고침 유지, GPU 디더 = CPU 비트 단위·1비트 PNG 왕복, 흑백 스타일 GPU = CPU·결정성·스타일 4가지 전환과 결과 일치·저장 유지, 효과 조절 `E` 저장 → 새로고침 유지, 결과 효과 실패 → 원본 사진에 CPU 입력 회색조와 인쇄 데이터, 조절값 API 왕복, 카메라 권한 거절 → 허용 회복, 모델을 막았을 때 장애 안내와 `S`, 외부 요청·CSP 위반·페이지 예외 0. 결과 표가 나오고, 하나라도 실패하면 종료 코드 1이다.
- 가짜 카메라에는 얼굴이 없어 자동 촬영은 확인하지 않는다. `S` 사이클은 `P`(자동 촬영 일시정지)를 켜고 돌리므로 실제 카메라 앞에 사람이 있어도 된다.
- 남는 포트로 자체 서버를 띄우고 끝나면 자신이 띄운 Chrome·서버·임시 프로필만 정리한다. 사용 중인 Chrome·OBS는 건드리지 않는다.
- 조절값 API 확인 중 몇 초 동안 `config\presence.local.json`·`config\effect.local.json`에 시험 값을 쓰고 원래대로 되돌린다. **현장 키오스크가 돌고 있는 PC에서는 실행하지 않는다.**
- 사진은 저장하지 않는다. 자세한 구조는 [docs/SYSTEM.md](docs/SYSTEM.md) 1절 "브라우저 확인 도구"를 따른다.

## 라이브러리 갱신 방법 (개발 PC 전용, 현장 불필요)

MediaPipe 런타임·모델은 `lib/mediapipe/`에 커밋되어 있다. 현장 PC는 clone만 하면 되고 Node·npm·인터넷이 필요 없다. 버전을 바꿀 때만 개발 PC(Node 18 이상)에서 실행한다.

```powershell
npm install
npm run vendor:mediapipe
```

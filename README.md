# 신세계 크리스마스 - 포토부스

세로 스크린 앞 발자국 매트(스윗스팟)에 서면 자동으로 3·2·1 카운트다운 뒤 사진을 찍어 보여 주는 **비접촉 웹 포토부스**다. PC 한 대에서 로컬 웹 서버(`localhost`)를 띄우고 같은 PC의 Chrome을 전체화면으로 쓴다. 관람객은 화면을 만지지 않는다.

```text
스크린 앞에 서요 → 3·2·1 자동 촬영 → 회색조 유화 사진으로 변해요 → 사진을 받아요
```

**현재 상태:** 카메라 → 회색조 유화 미리보기 → 자동 촬영·결과 표시까지 구현, 인쇄 연동은 예정.

> **15단계(간단 검수 전):** 눈벽을 압설 블록으로 바꾸고, 장면 전체에 유화를 한 번 입히고, 눈 바닥 글씨·숫자를 발자국처럼 파인 홈으로 그린다. [15단계 로그](docs/logs/2026-11-06-11-snow-relief.md).
>
> **14단계(간단 검수 후 master 반영):** 관람객 화면을 눈 마을 장면으로 바꿨다. 생성 장면의 나무 창틀·캐릭터 사이 4:5 사진 창, 위 띠에는 관람객 UI 없음, 안내와 3·2·1은 눈 바닥에 새긴 글씨. 감열지 톤 점에 유화 획을 섞는다. [구현 로그](docs/logs/2026-11-06-06-snow-frame-ui-filter.md). 이전 WISHFUL HOLIDAY 판은 태그 `backup/wishful-filter-2026-11-06`, IMPRINT는 `backup/imprint-2026-11-05`에 보존한다. 유화·흑백 독립 시험 조합(`E` 필터 섹션)은 그대로다.

9:16 화면 안에 4:5 사진 틀을 두며 글자는 틀 밖에 표시한다. 기존 시간·유화 세부 수치·인식·카메라 기본값과 현장 저장값(`config/*.local.json`)을 유지한다. [시스템](docs/SYSTEM.md).

## 실행

**현장 PC** (Windows, Chrome, OBS Studio. Node·인터넷 필요 없음)

| 파일 | 하는 일 |
|---|---|
| `Launch.bat` | OBS(가상카메라, 꺼져 있을 때만) → 로컬 서버(창 없이) → Chrome 키오스크 순서로 띄운다. 다시 실행하면 이 프로젝트의 서버·키오스크를 닫고 새로 띄운다 |
| `Shutdown.bat` | 키오스크 Chrome(전용 프로필)과 로컬 서버만 종료한다. OBS는 `obs_stop_on_shutdown=true`일 때만 |
| `Setup-Startup.bat` | 로그인할 때 `Launch.bat`이 실행되도록 시작 프로그램 바로가기를 만든다(`-Remove`로 제거) |

첫 설치 절차(OBS 설정, 카메라 권한 허용, 인식 범위 조절)와 실패 시 로그 위치는 [docs/SYSTEM.md](docs/SYSTEM.md) 1절 "현장 실행 스크립트"를 따른다.

**개발 PC** (저장소 루트, Windows PowerShell 5.1)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File bin\server\serve.ps1   # -Port 8800 처럼 포트 변경
```

Chrome에서 `http://localhost:8765/`를 연다(`127.0.0.1`은 400). 종료는 서버 창에서 Ctrl+C.

**카메라 없는 시안 데모 (검토용, 관람객 화면 아님):** 같은 서버에서 `http://localhost:8765/demo/index.html`. (패널의 "필터 시험 조합"으로 네 조합·흑백 방식·현장 저장값 대조본을 바꾸고, "4조합 비교 촬영"으로 같은 합성 장면의 네 결과를 나란히 본다.) 도형으로 그린 합성 장면을 실제 효과·촬영·인쇄 데이터 경로에 넣어 대기 → 3·2·1 → 결과 → 쿨타임을 자동으로 되풀이한다. 오른쪽 패널(세로로 긴 창이면 아래)에서 사람 들어옴/나감, 수동 촬영·초기화, 준비 중·직원 문의 흉내, 동작 줄이기, 인쇄 연동 뒤 흐름 흉내(가상), 마지막 인쇄 데이터를 본다. 조절값 파일을 쓰지 않고 프린터 연동은 없다. 9:16 화면을 크게 보려면 창을 가로로 넓게(예: 1920×1080 이상) 연다.

## 운영자 단축키 (관람객용 아님)

| 키 | 동작 |
|---|---|
| `D` | 개발용 정보와 감지 박스 겹쳐 그리기 켜기·끄기 |
| `E` | 운영자 조절 화면 (`Esc`로도 닫음, 마우스 사용). 섹션 넷: **카메라**(장치·해상도·반전·회전·확대·이동·색 보정, 원본 창) · **인식**(영역·얼굴 크기·신뢰도, 원본 창) · **시간**(카운트다운·결과 표시·쿨타임, 인식까지·이탈까지, 카메라 회복 시간) · **필터**(효과·출력). 섹션마다 저장. 열려 있는 동안 자동 촬영을 막는다 |
| `S` | 수동 촬영 (대기 중이고 카메라가 준비됐을 때만). 사람이 없어도 끝까지 찍는다 |
| `X` | 강제 초기화: 어느 상태든 바로 대기로. 촬영 중지 수단이 아니다(멈추려면 `P`) |
| `P` | 자동 촬영 일시정지·다시 켜기. 저장되지 않아 재시작하면 다시 켜진다 |

`Ctrl`·`Alt` 등과 함께 누르면 무시한다. `R`은 9-2부터 없다(인식 범위는 `E` 인식 섹션). 조절 화면은 섹션마다 **저장**을 눌러야 파일에 남고, 닫으면 저장하지 않은 섹션만 저장된 값으로 돌아간다. "기본값으로"는 그 섹션 값만 바꾼다. 카운트다운·결과·쿨타임을 바꾸면 다음 회차부터 쓰인다(진행 중인 회차는 그대로). 자세한 규칙은 [docs/SYSTEM.md](docs/SYSTEM.md) 4절 "운영자 단축키".

## 카메라 유화 업데이트

`E` → 필터 → **업데이트 확인 → 후보 시험 → 필터 적용·저장**. 확인만으로 실행판이나 미저장 조절값은 바뀌지 않는다. 시험 중 다시 확인해도 화면은 유지하며, 새 후보는 다시 시험한 뒤 적용한다. 22개 조절 항목과 원본 수치·범위를 함께 받으며 기존 현장값을 보존한다. 원본 수치 전체는 **가져온 기본값 적용**, 복원은 **이전판 복원**이다. 시험 중 닫으면 저장판으로 돌아간다.

확인할 때만 공식 서버에 접속하고 사진·프레임은 보내지 않는다. 평상시 촬영과 저장판 재시작은 오프라인으로 동작한다. 서버도 원문에서 수치·엔진을 독립 재추출한다. 지원하지 않는 원본 변경은 기존판을 유지하며 검토 필요로 안내한다. [지원 범위·전체 수치·복원 절차](docs/SYSTEM.md#카메라-유화-수동-업데이트-13단계).

## 설정 파일

- `settings.ini` — 현장 실행 설정(포트, Chrome·OBS 경로, 키오스크 등). 첫 실행 때 `settings.example.ini`에서 만들어지고 Git에서 제외된다. 키 표는 [docs/SYSTEM.md](docs/SYSTEM.md) 1절 "현장 실행 스크립트".
- `config/camera.local.json`, `config/presence.local.json`, `config/timing.local.json`, `config/effect.local.json` — `E`의 카메라·인식·시간·필터 섹션에서 저장한 값(Git 제외). **현장 PC를 옮길 때 이 파일들과, 있다면 `config/filter.local.json`도 복사한다.** 필터 업데이트 적용 후에는 `filter.local.json`의 엔진·수치·이전판이 효과 파일보다 우선한다. 없으면 기본값으로 시작한다. 형식은 [docs/SYSTEM.md](docs/SYSTEM.md) 1절 "조절값 파일 API", 3절 "카메라 처리 경로", 4절 "시간 설정", 5·6절.
  - 예전에 `E`에서 저장한 좌우 반전은 처음 시작할 때 카메라 파일로 옮겨진다.
  - 예전 인식 파일의 반응 속도·카메라 회복 시간(9단계까지)은 처음 시작할 때 시간 파일로 옮겨지고 인식 파일에서는 빠진다. 옮기지 못하면 그 값으로 돌고 시간 섹션에 "저장 필요"가 보인다(시간 섹션에서 저장하면 된다).
  - 크롭·회전·색 보정은 OBS와 웹(`E` 카메라 섹션) 중 **한 곳에서만** 한다. 권장은 웹(OBS는 원본만 넘김). OBS 가상카메라의 해상도는 `auto`.
  - 저장한 파일이 있으면 그 값이 기본값보다 우선한다. 기본값이 바뀌어도(예: 2026-10-27 반응 속도 0.5·1초 → 0.25초) 그 PC에는 반영되지 않으므로, 시간 섹션 "인식 반응"을 0.25초로 옮기고 **다시 저장**한다("기본값으로"는 시간 섹션의 다른 값까지 기본값으로 바꾼다).

## 테스트 (개발 PC 전용)

```powershell
npm test                                            # Node 테스트 (Node 22 이상, 설치 필요 없음)
node tools/filter-api-check.mjs                     # 원문 검산·schema·적용/재시작/복원 HTTP (카메라 없이)
node tools/filter-browser-check.mjs --capture       # 수동 업데이트·GPU·API·합성 촬영 검증 (확인 때 인터넷 사용)
node tools/filter-browser-check.mjs --real --capture # 같은 검증 + 실제 카메라 (프레임 파일 저장 없음)
npm run check:browser                               # 임시 프로필 headless Chrome으로 실제 앱 확인 (가짜 카메라)
npm run check:browser -- --camera real              # 실제 카메라 (OBS 가상카메라 우선)
npm run check:browser -- --soak --camera real       # 장시간 실측, 기본 10분 (--soak 60 처럼 분 지정)
npm run check:browser -- --only "시험 조합|WISHFUL" --screens artifacts\wishful\screens   # 4조합·관람객 화면·데모 PNG (가짜 카메라·합성 장면, Git 제외)
npm run check:browser -- --only "관람객 화면(14단계|시안 데모|흑백 스타일 4가지" --screens artifacts\stage14\screens   # 14단계 장면·톤 점 × 유화 (가짜 카메라·합성 장면, Git 제외)
```

`check:browser`, `filter-browser-check.mjs`, `filter-api-check.mjs`는 검증 중 `config/*.local.json`에 시험 값을 썼다가 되돌리므로 **현장 키오스크가 도는 PC에서는 실행하지 않는다.** MediaPipe 라이브러리는 `lib/mediapipe/`에 커밋되어 있고, 버전을 바꿀 때만 `npm install` → `npm run vendor:mediapipe`를 쓴다([docs/SYSTEM.md](docs/SYSTEM.md) 5절 "MediaPipe 로컬 라이브러리").

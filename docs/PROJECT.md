# PROJECT — 체험 기획과 범위

> 지금 유효한 기획·결정·계획만 둔다. 결정이 바뀐 경위와 측정·검수 기록은 [logs/](logs/)에 있다. 시스템 동작은 [SYSTEM.md](SYSTEM.md).

## 1. 체험 개요

세로형 스크린 앞에 관람객(가족 등 여러 명 가능)이 서면, 화면에 거울처럼 비친 자신의 모습이 보이고 자동으로 촬영된다. 관람객은 화면을 만지지 않으며, 마지막에 출력물만 받는다.

```text
1. 스크린 앞에 서요        발자국 매트(스윗스팟)에 서면 감지
2. 3·2·1 자동 촬영         카운트다운 후 한 장 촬영
3. 특별한 사진으로 변해요   회색조 유화 (미리보기에서부터 결과와 같은 그림이 보인다)
4. 사진을 받아요           출력물 수령 (인쇄는 이후 범위)
```

## 2. 결정 현황

### 확정 (사용자 결정)

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 기반. PC 한 대에서 `localhost` 웹을 띄우고 같은 PC의 브라우저·화면으로 운영 |
| 전체 구조 방향 | 이전 프로젝트 PickPod_FaceReading과 비슷한 로컬 실행 구조를 따르되 뼈대만 단순하게 만든다 ([SYSTEM.md](SYSTEM.md) 1절) |
| 현재 범위 | 카메라 촬영 → 결과 화면 표시까지. 인쇄는 최종 체험에 포함되지만 현재 개발 범위에서 제외 |
| 조작 방식 | **완전 비접촉.** 관람객용 버튼·터치·다시 찍기 없음. 관람객은 출력물만 받음 |
| 촬영 위치 | 바닥 발자국 매트로 스윗스팟 고정. 감지 거리는 스윗스팟 기준 약 2m 이내면 충분 |
| 화면 | PC 화면을 세로로 돌려 사용. **화면 비율 9:16 고정.** 해상도는 FHD~4K(현장 PC에 따라). 사진(촬영 이미지·사진 틀) 비율은 9:16일 필요가 없고 디자인 시안에서 정한다(사용자 2026-11-03, 그 전까지 사진도 9:16). 최종 결과는 감열지 흑백 출력 |
| 카메라 입력 | 웹캠 → OBS 가상카메라 → 브라우저(웹캠 직접도 가능). 9:16 크롭·회전·보정은 OBS와 웹의 카메라 옵션 중 **한 곳에서만** 한다. **기본 안내는 웹(OBS는 원본만 넘김)**, 최종은 현장에서 정한다. OBS 가상카메라의 해상도는 `auto`(다른 비율은 잘려서 온다) (2026-11-02) |
| 카메라 옵션 (9단계) | 운영자 옵션을 **카메라 / 카메라 인식 / 필터** 세 섹션으로 나눈다. **카메라** = 미디어파이프가 인식하는 카메라 원본을 고치는 값: 카메라 선택, 해상도, 색 보정(밝기·대비·채도·감마·색온도·색조), 좌우 반전, 위치(이동)·회전·확대. **카메라 인식** = 카메라 회복 설정(연결 재시도 간격 등)과 기존 인식 옵션(영역·얼굴 크기·신뢰도·반응 속도). **필터** = 기존 `E` 효과·출력. 카메라 보정·변환은 **전부에 같게 적용**한다(미디어파이프 인식, 필터 미리보기, 원본 미리보기, 촬영 결과, 인쇄 데이터 — "카메라 원본 자체를 고치는 것"). 운영자 화면은 **키 하나 `E`**로 열고(`R`은 없앰) 그 안에서 세 섹션으로 나누며, 카메라·인식 섹션을 조절하는 동안 **구석에 필터 없는 원본 창**(보정 적용, 감지 박스 포함)을 띄운다. **섹션 = 파일 하나**, 저장·취소·"기본값으로"(그 섹션 값만)는 섹션마다, 닫으면 저장하지 않은 섹션만 되돌린다. 카메라 섹션에 받은 크기·지원 범위·"OBS 가상카메라는 자동 권장"과 "OBS 보정과 중복 적용 주의"를 보인다 (2026-11-02). 9-1 카메라 처리 경로([로그 2026-11-02-01](logs/2026-11-02-01-stage9-camera-pipeline.md)), 9-2 통합 패널·원본 창([로그 2026-11-02-02](logs/2026-11-02-02-stage9-operator-panel.md)). 10단계에 **시간** 섹션을 더해 카메라 / 인식 / 시간 / 필터 넷이 되었고, 반응 속도·카메라 회복 시간은 인식 섹션에서 시간 섹션으로 옮겼다(아래 "시간 설정") |
| 시간 설정 (10단계) | `E`에 **시간 섹션**(카메라·인식·시간·필터 순서): 촬영 흐름(카운트다운 길이·결과 표시 시간·쿨타임), 인식 반응(인식까지·이탈까지), 카메라 회복 4개. **인식 섹션에는 시간 설정이 남지 않는다.** 섹션 = 파일 하나(`config/timing.local.json`), 저장·취소·"기본값으로"는 다른 섹션과 같다. 예전 `presence.local.json`의 반응·회복 값은 처음 시작할 때 시간 파일로 옮긴다. 촬영 흐름 값은 **다음 회차부터**(진행 중인 회차는 시작할 때의 값으로 끝까지), 인식 반응은 바로, 카메라 회복은 다음 재시도·판정부터 (사용자 요청 2026-11-03, [로그 2026-11-03-01](logs/2026-11-03-01-stage10-timing-settings.md)) |
| 감지기 | MediaPipe Face Detector(short-range)로 "인식됨 / 인식 안됨"을 판정 |
| 라이브러리 관리 | npm은 개발 PC에서 라이브러리를 받는 데만 쓴다. 런타임 파일은 저장소 `lib/`에 커밋하고, 현장 PC는 Node 없이 clone만으로 오프라인 동작 |
| 좌우 반전 | 기본은 미리보기와 **결과(출력) 사진 모두 반전(켬)**. 현장 카메라 배치·OBS 설정에 따라 필요 없을 수 있어 운영자가 켜고 끌 수 있고, 저장하면 재시작 뒤에도 유지된다. 미리보기·결과·인쇄용 데이터·인식 영역 판정이 모두 이 한 값을 따르고, 반전은 웹에서만 한다 (2026-10-26, [로그 2026-10-26-02](logs/2026-10-26-02-mirror-toggle.md)). 9-1부터 값은 **카메라 설정**(`config/camera.local.json`, `E` 카메라 섹션)에 있고, 예전 `effect.local.json`의 값은 처음 읽을 때 옮긴다 |

### 가안 (진행을 위한 제안, 변경 가능)

| 항목 | 내용 |
|---|---|
| 자동 시작 인식 | 좌표 스무딩 대신 판정 단계의 시간 필터로 안정화. 시작은 평가 시점의 인식 상태로 판단(레벨 판정). 인식으로 시작한 회차만 카운트다운 중 "인식 안됨"이 되면 취소(별도 유예 없이 인식 판정의 유예 시간을 쓴다). `E` 운영자 화면(어느 섹션이든)이 열려 있는 동안, `P` 일시정지 중, 시작할 때 인식 조절값·시간 설정을 불러오는 동안은 자동 시작을 막는다 ([SYSTEM.md](SYSTEM.md) 4절) |
| 인식 범위 | 얼굴이 **화면 영역(스윗스팟)** 안에 있고, 크기가 **최소 이상·최대 이하**(거리 대신, 9:16 화면 높이 대비)이며, 신뢰도가 최소값 이상이면 인정. 운영자가 `E` 인식 섹션에서 영역·크기·신뢰도를, 시간 섹션에서 반응 속도(판정 시간)를 조절 |
| 인식 기준 기본값 | 영역 가운데 0.8×0.8, **최소 얼굴 크기 0.185, 최대 0.47, 최소 신뢰도 0.65**(개발 PC 저장값), 인식됨·인식 안됨까지 0.25초(확정 표). 현장 실측 후 조정 |

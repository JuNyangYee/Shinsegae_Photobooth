# PROJECT — 체험 기획과 범위

## 1. 체험 개요

크리스마스 장식이 된 세로형 스크린 앞에 관람객(가족 등 여러 명 가능)이 서면, 화면에 거울처럼 비친 자신의 모습이 보이고 자동으로 촬영된다. 관람객은 화면을 만지지 않으며, 마지막에 출력물만 받는다.

```text
1. 스크린 앞에 서요        발자국 매트(스윗스팟)에 서면 감지
2. 3·2·1 자동 촬영         카운트다운 후 한 장 촬영
3. 특별한 사진으로 변해요   사진 효과 적용 (TBD)
4. 사진을 받아요           출력물 수령 (인쇄는 이후 범위)
```

## 2. 결정 현황

### 확정 (사용자 결정)

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 기반. PC 한 대에서 `localhost` 웹을 띄우고 같은 PC의 브라우저·화면으로 운영 |
| 전체 구조 방향 | 이전 프로젝트 PickPod_FaceReading과 비슷한 로컬 실행 구조를 따르되, 뼈대부터 단순하게 만든다 (`docs/SYSTEM.md` 1절) |
| 현재 범위 | 카메라 촬영 → 결과 화면 표시까지 |
| 인쇄 | 최종 체험에는 포함되나 현재 개발 범위에서 제외 |
| 조작 방식 | **완전 비접촉.** 관람객용 버튼·터치·다시 찍기 없음. 관람객은 출력물만 받음 |
| 촬영 위치 | 바닥에 발자국 매트를 두어 촬영 스윗스팟을 고정 |
| 화면 | PC 화면을 세로로 돌려 사용. **화면·사진 비율 9:16.** 해상도는 FHD~4K 사이(현장 PC에 따라 결정) |
| 카메라 입력 | 웹캠 → OBS 가상카메라 → 브라우저. 9:16 크롭과 보정은 OBS에서 처리. OBS 출력 해상도는 PC 화면 해상도에 맞춤 |
| 감지 거리 | 스윗스팟 기준 약 2m 이내면 충분 |
| 감지기 | MediaPipe Face Detector(short-range)로 "인식됨 / 인식 안됨"을 판정한다 (2단계) |
| 라이브러리 관리 | npm은 개발 PC에서 라이브러리를 받아오는 용도로만 쓴다. 런타임 파일은 저장소 `lib/`에 커밋하고, 현장 PC는 Node 없이 clone만으로 오프라인 동작한다 |
| 좌우 반전 | 미리보기를 좌우 반전(거울)으로 표시하고, **결과(출력) 사진도 반전된 상태**로 만든다 |
| 카운트다운 | 3·2·1 후 사진 한 장 (설정값 `countdownSeconds`로 분리, 3단계 지시 2026-10-15) |
| 쿨타임 | 결과 화면이 끝나고 대기로 돌아온 뒤 **5초 동안 감지를 받지 않는다.** 스윗스팟이 비어 있는지는 보지 않는다 (사람이 계속 오가며 비우기 어렵기 때문) |
| 결과 표시 시간 | 참고 프로젝트 방식: 출력 요청 중에는 "출력 중"을 표시하고 종료 시계를 멈춘다. 인쇄 서비스가 출력 완료를 알리면 그때부터 10초 뒤 대기로 복귀. 인쇄 연동 전에는 결과 표시 시작부터 10초 |
| 사진 효과 | TBD. 어떤 형식의 필터·변환을 할지 미정 |
| 디자인 | 최종 콘텐츠·디자인 없이 기본 UI로 개발하고 작은 단위로 조율 |
| 식별 금지 | 신원 식별, 나이·성별·관계 추정은 하지 않음 |

### 가안 (진행을 위한 제안, 변경 가능)

| 항목 | 내용 |
|---|---|
| 자동 시작 인식 | Face Detector 결과를 좌표 스무딩 대신 판정 단계의 시간 필터로 안정화 |
| 인식 범위 | 얼굴이 **화면 영역(스윗스팟)** 안에 있고, 크기가 **최소 이상·최대 이하**(거리 대신, 9:16 화면 높이 대비)이며, 신뢰도가 최소값 이상이면 인정한다. 운영자가 숨김 화면(`R` 키)에서 영역·최소/최대 크기·최소 신뢰도·판정 시간을 조절한다 |
| 인식 기준 기본값 | 영역 가운데 0.8×0.8, 최소 얼굴 크기 0.05, 최대 얼굴 크기 0.6, 최소 신뢰도 0.7, 인식됨까지 0.5초, 인식 안됨까지 1초 (2026-10-15 결정. 현장 실측 후 조정) |
| 조절값 저장 | 브라우저 `localStorage`(`photobooth.presence.v1`)에 "저장"을 누를 때만 기록한다. 4단계에서 파일 저장(`settings.ini` 등)으로 바꿀지 다시 검토한다 |
| 인식 대안 | 실측에서 얼굴 누락이 잦으면 Object Detector(`person`)나 Pose Landmarker를 비교 |
| 로컬 서버 | PowerShell `HttpListener` 정적 서버, 빌드 없는 바닐라 ES 모듈 (`docs/SYSTEM.md` 1절) |
| 개발·운영 입력 | 관람객용이 아닌 키보드 단축키로 수동 촬영(`S`)·강제 초기화(`X`, 쿨타임 없이 바로 대기) (개발 및 현장 운영자 전용) |
| 사진 처리 | 브라우저 메모리에서만 현재 회차용으로 유지. 외부 전송·자동 저장 없음 |
| 오프라인 | 외부 서비스 없이 로컬에서 처리. MediaPipe 라이브러리·WASM·모델도 저장소 `lib/`에 둔다. MediaPipe 1.x가 보내는 사용 통계는 `index.html`의 CSP(`connect-src 'self'`)로 막는다 (사용자 결정 2026-10-15, `docs/SYSTEM.md` 1절) |

## 3. 범위

**포함 (현재):** 로컬 웹 실행, 카메라 미리보기, 자동/개발용 촬영 시작, 카운트다운, 한 장 캡처, 결과 표시, 쿨타임 후 대기 복귀, 기본 예외 처리, 현장 실행 스크립트의 최소 구성.

**제외 (현재):** 프린터 연동·인쇄 대기열·출력 규격, 생성형 AI 사진 변환, 계정·결제·갤러리·QR 공유, 클라우드·NAS 보관, 다중 기기 제어, 자동 업데이트·야간 스케줄·워치독 같은 운영 자동화, 최종 디자인.

사진 효과와 인쇄는 기본 웹이 준비된 뒤 별도로 결정하고 작업 범위를 정한다.

## 4. 단계별 계획

| 단계 | 세부 작업 | 완료 기준 |
|---|---|---|
| **0. 문서 초기화** | 저장소 확인, 문서 작성, 확정·가안·TBD 구분 | 다음 세션이 목표·범위·첫 구현 작업을 이해할 수 있음 |
| **1. 카메라 웹 기반** | 정적 로컬 서버, 최소 페이지, OBS 가상카메라 선택, 9:16 반전 미리보기, 권한·오류 안내 | 실제 카메라 영상이 9:16 세로 화면에 반전되어 표시됨. 권한 거절·카메라 없음도 확인 |
| **2. 얼굴 감지** | 2-1 MediaPipe 로컬 라이브러리 설정, 2-2 감지와 인식 상태(인식됨 / 인식 안됨), 2-3 운영자용 인식 범위 조절(화면 영역·최소 얼굴 크기, `localStorage` 저장) | 외부 요청 없이 로컬 라이브러리로 감지한다. 실제 카메라로 인식 상태가 바뀌는 것과 범위 조절이 반영되는 것을 확인 |
| **3. 촬영 한 사이클** | 키보드 입력과 감지 결과로 시작, 카운트다운, 한 장 캡처(반전·9:16 유지), 결과 10초 표시, 쿨타임 5초 후 대기 복귀 | 반복 촬영 가능. 중복 시작 무시와 취소 확인. 키보드 시작 완료와 감지 시작 완료를 구분해 보고 |
| **4. 안정화·현장 실행** | 반복 촬영, 중간 이탈, OBS 단절, 화면 비활성화, 자원 정리, 감지 부하 확인, 조절값 저장 방식 재검토, Chrome 하드웨어 가속(WebGL) 점검(없으면 감지 불가), 실행 스크립트(OBS·서버·브라우저 순서 실행) | 진행이 꼬이지 않고 이전 사진이 다음 체험에 남지 않음. 스크립트 하나로 현장 실행 가능 |

- 각 단계는 여러 세션으로 나눌 수 있다. 예: 1단계 = "서버와 미리보기" + "권한·오류 처리".
- 필수 예외 처리는 해당 기능을 만들 때 넣고, 4단계에서 묶어 재검증한다.
- **개발용 입력 촬영 완료와 자동 감지 촬영 완료는 별도로 판정한다.** 현장은 비접촉이므로 최종 목표는 자동 촬영이다.
- 각 단계를 마치면 검수를 거쳐 병합한다 (`AGENTS.md` "Git").

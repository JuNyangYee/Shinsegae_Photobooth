# PROJECT — 체험 기획과 범위

> 지금 유효한 기획·결정·계획만 둔다. 결정이 바뀐 경위와 측정·검수 기록은 [logs/](logs/)에 있다. 시스템 동작은 [SYSTEM.md](SYSTEM.md).

## 1. 체험 개요

세로형 스크린 앞에 관람객(가족 등 여러 명 가능)이 서면, 화면에 거울처럼 비친 자신의 모습이 보이고 자동으로 촬영된다. 관람객은 화면을 만지지 않으며, 마지막에 출력물만 받는다.

```text
1. 스크린 앞에 서요        발자국 매트(스윗스팟)에 서면 감지
2. 3·2·1 자동 촬영         카운트다운 후 한 장 촬영
3. 특별한 사진으로 변해요   회색조 유화 (미리보기에서부터 결과와 같은 그림이 보인다)
4. 사진을 받아요           출력물 수령 (인쇄는 이후 범위)
```

## 2. 결정 현황

### 확정 (사용자 결정)

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 기반. PC 한 대에서 `localhost` 웹을 띄우고 같은 PC의 브라우저·화면으로 운영 |
| 전체 구조 방향 | 이전 프로젝트 PickPod_FaceReading과 비슷한 로컬 실행 구조를 따르되 뼈대만 단순하게 만든다 ([SYSTEM.md](SYSTEM.md) 1절) |
| 현재 범위 | 카메라 촬영 → 결과 화면 표시까지. 인쇄는 최종 체험에 포함되지만 현재 개발 범위에서 제외 |
| 조작 방식 | **완전 비접촉.** 관람객용 버튼·터치·다시 찍기 없음. 관람객은 출력물만 받음 |
| 촬영 위치 | 바닥 발자국 매트로 스윗스팟 고정. 감지 거리는 스윗스팟 기준 약 2m 이내면 충분 |
| 화면 | PC 화면을 세로로 돌려 사용. **화면·사진 비율 9:16.** 해상도는 FHD~4K(현장 PC에 따라) |
| 카메라 입력 | 웹캠 → OBS 가상카메라 → 브라우저. 9:16 크롭·회전·보정은 OBS, OBS 출력 해상도는 화면 해상도에 맞춤 |
| 감지기 | MediaPipe Face Detector(short-range)로 "인식됨 / 인식 안됨"을 판정 |
| 라이브러리 관리 | npm은 개발 PC에서 라이브러리를 받는 데만 쓴다. 런타임 파일은 저장소 `lib/`에 커밋하고, 현장 PC는 Node 없이 clone만으로 오프라인 동작 |
| 좌우 반전 | 기본은 미리보기와 **결과(출력) 사진 모두 반전(켬)**. 현장 카메라 배치·OBS 설정에 따라 필요 없을 수 있어 **운영자가 `E` 화면 "카메라"에서 켜고 끌 수 있고**, 저장하면 재시작 뒤에도 유지된다(`config/effect.local.json`). 미리보기·결과·인쇄용 데이터·인식 영역 판정이 모두 이 한 값을 따르고, 반전은 웹에서만 한다 (2026-10-26, [로그 2026-10-26-02](logs/2026-10-26-02-mirror-toggle.md)) |
| 촬영 시간 | 3·2·1 카운트다운 후 한 장(`countdownSeconds`). 결과 표시 10초: 인쇄 연동 뒤에는 출력 중 "출력 중"을 보이고 종료 시계를 멈췄다가 출력 완료 확인부터 10초, 그 전에는 결과 표시 시작부터 10초 |
| 쿨타임 | 대기로 돌아온 뒤 **5초 동안 시작 요청을 받지 않는다.** 스윗스팟이 비었는지는 보지 않으며, 쿨타임이 끝났을 때 사람이 계속 서 있으면 바로 다음 회차가 시작된다 |
| 운영 입력 | 관람객용이 아닌 키보드 단축키: 수동 촬영 `S`, 강제 초기화 `X`(쿨타임 없이 바로 대기), 인식 범위 조절 `R`, 사진 효과 조절 `E`, 자동 촬영 일시정지 `P`(인식으로 시작한 카운트다운 취소, `S`는 계속 가능, **저장하지 않아** 재시작하면 다시 켜짐, 화면 구석에 작은 운영자 표시) |
| 조절값 저장 | 운영자 조절값은 저장소 안 파일 `config/presence.local.json`·`config/effect.local.json`(Git 제외)에 둔다. 로컬 서버의 고정 경로 API로만 읽고 쓰며 다른 웹페이지가 쓰지 못하게 막는다. 예전 `localStorage` 인식 값은 파일이 없을 때 한 번 옮긴다. 현장 PC를 옮길 때 두 파일을 복사한다 |
| 하드웨어 가속 | 실행 스크립트가 Chrome 하드웨어 가속을 켠다. 소프트웨어 WebGL로 동작하면 감지가 되므로 장애로 보지 않고 D 화면 표시와 콘솔 경고 1회만 둔다 |
| 사진 효과 | **"유화 · 획 (세부 보존)"** 필터. 출처는 사용자가 지정한 필터 갤러리 `https://nau-filter-gallery.vercel.app/`의 프리셋 `oil2f`. **최종 출력에 쓸 그림을 WebGL로 실시간 미리보기**하고, 촬영 결과도 같은 그림이다. 수치는 `E`에서 조절할 수 있다. 기본값: **강도 0.3, 붓 크기 1.3, 획 다시 그리기 0.05, 초당 12장, 보완 층(세부 보존) 문턱 0.3**, 색 보정 1, 붓 층과 보완 층의 나머지 값은 `oil2f` 그대로(개발 PC에서 조절·저장한 값, `oil2f` 원본은 0.1·1.25·0.1·24·0.22). 조절값 파일이 있으면 그 값 ([로그 07](logs/2026-10-19-07-saved-defaults.md), [로그 2026-10-26-01](logs/2026-10-26-01-saved-defaults-2.md)) |
| 화면 출력: 회색조 유화 | 화면 기본값은 **카메라 영상 → 단순 흑백(회색조) → 유화 `oil2f`(원본 그대로) → 화면**이다. 미리보기와 결과(1080×1920)는 무채색. **감열지 인쇄용 1비트 데이터(576×1024)는 결과 사진에서 따로 만들어** 메모리에만 둔다. 감지는 원본 컬러 영상으로 한다. 감열지·회색조·컬러(끔) 모드는 비교·출력 확인용으로 `E`에 남긴다. 감열지 1비트 화면 → 회색조 유화로 바뀐 경위는 [로그 2026-10-19-06](logs/2026-10-19-06-stage8-gray-oil.md) |
| 감열지 모드 | `E`에서 고를 때만 쓴다. 1비트 점이고 **화면에 보이는 것이 곧 출력물**(미리보기·결과가 같은 점 그림). 1비트로 바꾸는 방식("흑백 스타일")은 유화 느낌이 나야 하며 기본값은 **붓 결 선, 선 간격 4점, 질감 세기 1** ([로그 2026-10-19-04](logs/2026-10-19-04-stage7-painterly-bw.md)) |
| 용지 | 감열지 **80mm, 가로 576점(203dpi)**, 설정으로 바꿀 수 있다(58mm는 384점) |
| 효과 결과 해상도 | **짧은 변 1080 기준**(결과 1080×1920). 4K 입력은 효과를 입히기 전에 1080 기준으로 줄인다. 결과는 셔터 순간 미리보기와 같은 그림(같은 프레임·그림 번호·seed) |
| 효과 미리보기 처리 해상도 | 기본 **0.5**(결과 크기 대비, 개발 PC 저장값). 결과는 늘 1080 기준으로 그리므로 0.5에서는 **미리보기가 결과 사진보다 조금 부드럽게 보일 수 있다**(1이면 화소까지 같다). 현장 PC가 느리면 **먼저 초당 그림(`fps`)을 낮추고, 그다음 처리 해상도를 낮춘다** |
| 디자인 | 관람객 화면은 **미니멀·에디토리얼(갤러리 느낌)**: 주인공은 회색조 유화 미리보기이고 UI는 거의 보이지 않을 만큼 절제. 무채색(오프화이트·차콜·회색), 장식 없음, 큰 글자는 세리프·작은 안내는 산세리프. **숫자와 글자는 얼굴·가운데를 가리지 않게 9:16 영역 아래 15% 안에만** 둔다. **크리스마스 표현은 넣지 않고, 카운트다운 숫자 크기는 영역 폭의 9.6%**. 그 밖의 세부는 가안. 최종 콘텐츠 없이 개발하고 작은 단위로 조율한다 ([로그 2026-10-19-05](logs/2026-10-19-05-stage7-minimal-ui.md)) |
| 식별 금지 | 신원 식별, 나이·성별·관계 추정은 하지 않음 |
| 현장 브라우저 | Chrome을 전용 프로필과 **`--kiosk`**로 띄운다 |
| 현장 실행·종료 | `Launch.bat` 하나로 OBS → 서버 → Chrome 순서 실행, `Shutdown.bat`으로 키오스크 Chrome·서버 종료(OBS 종료는 설정, 기본 안 함), 부팅 시 자동 실행은 시작 프로그램 폴더 바로가기 |

### 가안 (진행을 위한 제안, 변경 가능)

| 항목 | 내용 |
|---|---|
| 자동 시작 인식 | 좌표 스무딩 대신 판정 단계의 시간 필터로 안정화. 시작은 평가 시점의 인식 상태로 판단(레벨 판정). 인식으로 시작한 회차만 카운트다운 중 "인식 안됨"이 되면 취소(별도 유예 없이 인식 판정의 유예 시간을 쓴다). `R`·`E` 조절 화면이 열려 있는 동안, `P` 일시정지 중, 시작할 때 인식 조절값을 불러오는 동안은 자동 시작을 막는다 ([SYSTEM.md](SYSTEM.md) 4절) |
| 인식 범위 | 얼굴이 **화면 영역(스윗스팟)** 안에 있고, 크기가 **최소 이상·최대 이하**(거리 대신, 9:16 화면 높이 대비)이며, 신뢰도가 최소값 이상이면 인정. 운영자가 `R` 화면에서 영역·크기·신뢰도·판정 시간을 조절 |
| 인식 기준 기본값 | 영역 가운데 0.8×0.8, **최소 얼굴 크기 0.185, 최대 0.47, 최소 신뢰도 0.65**(개발 PC 저장값), 인식됨까지 0.5초, 인식 안됨까지 1초. 현장 실측 후 조정 |
| 감지기 재시도·장애 기준 | 재시도 15초부터 두 배·최대 300초, 연속 3회 실패부터 장애, 반복 오류 로그 요약 60초. 현장 운영 뒤 조정 |
| 촬영 안전값 | 결과 만들기 제한 5초, 촬영 실패 뒤 자동 시작 쉬기 5초부터 두 배·최대 60초, 촬영 직전 새 프레임 0.5초 이내 |
| 조절값 파일 | 시작할 때 읽기 제한 3초(넘으면 기본값), 쓰기 본문 상한 16KB, 일시정지 표시 켬. 효과 조절값은 불러오는 동안 기본값으로 그리고 자동 촬영을 막지 않는다 |
| 인식 대안 | 실측에서 얼굴 누락이 잦으면 Object Detector(`person`)나 Pose Landmarker를 비교 |
| 로컬 서버 | PowerShell `HttpListener` 정적 서버, 빌드 없는 바닐라 ES 모듈 |
| 사진 처리 | 브라우저 메모리에서만 현재 회차용으로 유지. 외부 전송·자동 저장 없음 |
| 카메라 권한 | 키오스크 전용 Chrome 프로필에서 운영자가 처음 한 번 "허용"을 누른다. 자동 수락 플래그(`--use-fake-ui-for-media-stream`)는 경고 막대가 화면을 가려 쓰지 않는다 |
| 효과 장애 | WebGL2를 만들지 못하거나 컨텍스트를 잃으면 원본 미리보기로 돌아가고 D 화면에만 표시. 카메라·감지·촬영은 계속. 결과 사진에 효과를 그리지 못하면 원본 사진(결과 크기)에 같은 출력 단계를 CPU로 적용해 대신하고(회색조 유화: 회색조 + 인쇄 데이터, 감열지: 점 그림 + 인쇄 데이터), 그것도 실패하면 원본 컬러 사진. 촬영 실패로 처리하지 않는다(관람객은 다시 찍을 방법이 없다). 회색조 유화에서 인쇄 데이터만 실패하면 사진은 그대로 보인다 |
| 회색조 유화 세부 | 입력 회색조 계수 **Rec.709 luma**. 무채색은 **마지막에 다시 회색조**로 만든다(색 보정 기본값과 유화 패스는 그대로). 결과 형식 1080×1920 **JPEG**. 인쇄 데이터는 같은 합성 그림을 톤 점 방식(면적 평균 + 점 방식)으로 만들고, 점 방식·용지 폭은 `E`에서 바꾼다. 인쇄 데이터 미리보기는 두지 않는다(D 화면 숫자만). 결과 출력물 폭은 영역의 1/2(1080 화면 1/2·4K 1:1, 감열지 1비트 사진만 576/1080) |
| 점 방식·레벨 | 점 방식 기본값 **블루 노이즈**(GPU 문턱값, 사용자 결정이지만 실제 프린터 비교 전까지 가안). Atkinson·Floyd–Steinberg·Bayer도 고를 수 있다. 레벨 기본값 **밝기 −0.05·대비 1.5·감마 1.3**(개발 PC에서 화면을 보고 조절·저장한 값, [로그 2026-10-26-01](logs/2026-10-26-01-saved-defaults-2.md)). 회색조 유화에서는 화면 미리보기·결과 사진과 인쇄 데이터에 같은 레벨을 쓴다. 인쇄 해상도로 줄일 때는 면적 평균 |
| 감열지 화면 | 화면 종이색 `[246,242,233]`·잉크색 `[26,26,30]`. 화면 표시에만 "정수배 최근접 + 경계 1화소만 섞는" 확대(sharp bilinear 계열)로 미리보기와 결과 화면용 이미지를 결과 크기(1080×1920)에 같게 만든다. 결과 형식은 화면용 PNG + 인쇄용 1비트 데이터. 흑백 스타일 내부 상수는 합성 시험 이미지로 정한 값이고, 운영자가 바꾸는 값은 스타일·질감 세기·선 간격뿐이다 |
| 회색조 모드와 인쇄 | 회색조 모드(컬러 유화를 회색으로)는 인쇄 데이터 없이 회색 JPEG만 만든다. 인쇄 데이터는 감열지와 회색조 유화에서 만든다 |

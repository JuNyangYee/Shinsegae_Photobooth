# PROJECT — 체험 기획과 범위

## 1. 체험 개요

크리스마스 장식이 된 세로형 스크린 앞에 관람객(가족 등 여러 명 가능)이 서면, 화면에 거울처럼 비친 자신의 모습이 보이고 자동으로 촬영된다. 관람객은 화면을 만지지 않으며, 마지막에 출력물만 받는다.

```text
1. 스크린 앞에 서요        발자국 매트(스윗스팟)에 서면 감지
2. 3·2·1 자동 촬영         카운트다운 후 한 장 촬영
3. 특별한 사진으로 변해요   사진 효과 "유화 · 획" + 감열지 흑백 점 (미리보기에서부터 출력물 그대로 보인다)
4. 사진을 받아요           출력물 수령 (인쇄는 이후 범위)
```

## 2. 결정 현황

### 확정 (사용자 결정)

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹 기반. PC 한 대에서 `localhost` 웹을 띄우고 같은 PC의 브라우저·화면으로 운영 |
| 전체 구조 방향 | 이전 프로젝트 PickPod_FaceReading과 비슷한 로컬 실행 구조를 따르되, 뼈대부터 단순하게 만든다 (`docs/SYSTEM.md` 1절) |
| 현재 범위 | 카메라 촬영 → 결과 화면 표시까지 |
| 인쇄 | 최종 체험에는 포함되나 현재 개발 범위에서 제외 |
| 조작 방식 | **완전 비접촉.** 관람객용 버튼·터치·다시 찍기 없음. 관람객은 출력물만 받음 |
| 촬영 위치 | 바닥에 발자국 매트를 두어 촬영 스윗스팟을 고정 |
| 화면 | PC 화면을 세로로 돌려 사용. **화면·사진 비율 9:16.** 해상도는 FHD~4K 사이(현장 PC에 따라 결정) |
| 카메라 입력 | 웹캠 → OBS 가상카메라 → 브라우저. 9:16 크롭과 보정은 OBS에서 처리. OBS 출력 해상도는 PC 화면 해상도에 맞춤 |
| 감지 거리 | 스윗스팟 기준 약 2m 이내면 충분 |
| 감지기 | MediaPipe Face Detector(short-range)로 "인식됨 / 인식 안됨"을 판정한다 (2단계) |
| 라이브러리 관리 | npm은 개발 PC에서 라이브러리를 받아오는 용도로만 쓴다. 런타임 파일은 저장소 `lib/`에 커밋하고, 현장 PC는 Node 없이 clone만으로 오프라인 동작한다 |
| 좌우 반전 | 미리보기를 좌우 반전(거울)으로 표시하고, **결과(출력) 사진도 반전된 상태**로 만든다 |
| 카운트다운 | 3·2·1 후 사진 한 장 (설정값 `countdownSeconds`로 분리, 3단계 지시 2026-10-15) |
| 쿨타임 | 결과 화면이 끝나고 대기로 돌아온 뒤 **5초 동안 감지를 받지 않는다.** 스윗스팟이 비어 있는지는 보지 않는다 (사람이 계속 오가며 비우기 어렵기 때문). 쿨타임이 끝났을 때 사람이 계속 서 있으면 바로 다음 회차가 시작된다 (사용자 확정 2026-10-15) |
| 운영 입력 | 관람객용이 아닌 키보드 단축키: 수동 촬영 `S`, 강제 초기화 `X`(쿨타임 없이 바로 대기) (개발 및 현장 운영자 전용, 2026-10-15 결정). 사진 효과 조절 `E`(5-2, `R`과 같은 저장·닫기·자동 촬영 막기 규칙). 자동 촬영 일시정지 `P`: 인식으로 시작한 카운트다운은 취소, `S`는 계속 가능, **저장하지 않아** 재시작하면 다시 켜짐, 화면 구석에 작은 운영자 표시 (사용자 결정 2026-10-15, 구현 4-3) |
| 조절값 저장 | 운영자 조절값은 저장소 안 파일 `config/presence.local.json`에 둔다(Git 제외). 로컬 서버의 고정 경로 API 하나로만 읽고 쓰며, 다른 웹페이지가 쓰지 못하게 막는다. 기존 `localStorage` 값은 파일이 없을 때 한 번 옮긴다. 현장 PC를 옮길 때 이 파일을 복사한다 (사용자 결정 2026-10-15, 구현 4-3, `docs/SYSTEM.md` 1·5절). 효과 조절값도 같은 방식의 `config/effect.local.json`(불러오기는 파일 → 기본값, 5-2) |
| 하드웨어 가속 | 실행 스크립트가 Chrome 하드웨어 가속을 켠다(4-2). 소프트웨어 WebGL로 동작하면 감지가 되므로 장애로 보지 않고 D 화면 표시와 콘솔 경고 1회만 둔다 (사용자 결정 2026-10-15) |
| 결과 표시 시간 | 참고 프로젝트 방식: 출력 요청 중에는 "출력 중"을 표시하고 종료 시계를 멈춘다. 인쇄 서비스가 출력 완료를 알리면 그때부터 10초 뒤 대기로 복귀. 인쇄 연동 전에는 결과 표시 시작부터 10초 |
| 사진 효과 | **"유화 · 획 (세부 보존)"** 필터. 출처는 사용자가 지정한 필터 갤러리 `https://nau-filter-gallery.vercel.app/`의 프리셋 `oil2f`. 기본값은 사용자가 고른 세팅(강도 0.1, 붓 크기 1.25, 획 다시 그리기 0.1, 초당 24장, 보완 층 등 `oil2f` 그대로). **최종 출력에 쓸 이미지를 WebGL로 실시간으로 보여 준다:** 관람객은 미리보기에서 이미 필터가 적용된 모습을 보고, 촬영 결과도 같은 필터를 적용한 이미지다. 수치는 조절할 수 있어야 한다. 유화 뒤에 감열지 흑백 단계를 덧씌운다(아래 행) (사용자 결정 2026-10-16. 미리보기 구현 5-1, `docs/SYSTEM.md` 6절) |
| 감열지 흑백 시뮬레이션 | 유화 효과 뒤에 **감열지 흑백 시뮬레이션**을 적용한다. 감열지는 흰 바탕에 검은 점(1비트)으로 찍히므로 **화면에 보이는 것이 곧 출력물**이어야 한다. 미리보기와 촬영 결과 모두 같은 흑백 점 이미지다. 프린터 용지는 **80mm, 가로 576점(203dpi)**, 설정으로 바꿀 수 있다(58mm는 384점). 점 방식·밝기·대비는 `E` 화면에서 조절한다. 모드 3단계: **감열지(기본)** / 회색조 / 끔(컬러 유화) (사용자 결정 2026-10-19, 구현 6-1, `docs/SYSTEM.md` 6절 "출력 단계") |
| 유화 느낌 흑백 | 감열지 흑백은 **유화 느낌이 나야 한다**(6-1 블루 노이즈 점 그림은 붓 획 질감이 사라졌다). 1비트, "화면 = 출력물", 80mm·576점·203dpi는 그대로다. 1비트로 바꾸는 방식("흑백 스타일")을 `E`에서 고른다 (사용자 요구 2026-10-19, 구현 7-1, `docs/SYSTEM.md` 6절 "흑백 스타일") |
| 효과 결과 해상도 | 원본처럼 **짧은 변 1080 기준**(결과 1080×1920). 4K로 들어오면 효과를 입히기 전에 1080 기준으로 줄인다. 미리보기·원본 갤러리와 같은 그림이어야 하고, 감열지 해상도가 이보다 훨씬 낮기 때문이다. 결과는 셔터 순간 미리보기와 같은 그림(같은 프레임·그림 번호·seed) (사용자 결정 2026-10-16, 구현 5-2) |
| 효과 미리보기 처리 해상도 | 기본 **1.0**(결과 크기 대비). 미리보기와 결과가 같은 그림이어야 한다. 현장 PC가 느리면 **먼저 초당 그림(`fps`)을 낮추고, 그다음 처리 해상도를 낮춘다** (사용자 결정 2026-10-16) |
| 디자인 | 최종 콘텐츠·디자인 없이 개발하고 작은 단위로 조율. 관람객 화면은 **크리스마스의 따뜻한 톤**(크림·딥 레드·골드·솔잎 그린, 둥글고 읽기 쉬운 서체, 리본·솔가지 장식)으로 깔끔하게 한다. 미리보기·결과 사진이 흰 감열지 위 흑백 이미지가 되는 것을 전제로 한다 (사용자 요청 2026-10-19, 구현 6-2. 세부는 가안) |
| 식별 금지 | 신원 식별, 나이·성별·관계 추정은 하지 않음 |
| 현장 브라우저 | Chrome을 전용 프로필과 **`--kiosk`**로 띄운다 (사용자 결정 2026-10-15) |
| 현장 실행·종료 | `Launch.bat` 하나로 OBS → 서버 → Chrome 순서 실행, `Shutdown.bat`으로 키오스크 Chrome·서버 종료(OBS 종료는 설정, 기본 안 함), 부팅 시 자동 실행은 시작 프로그램 폴더 바로가기 (사용자 결정 2026-10-15, 구현 4-2) |

### 가안 (진행을 위한 제안, 변경 가능)

| 항목 | 내용 |
|---|---|
| 자동 시작 인식 | Face Detector 결과를 좌표 스무딩 대신 판정 단계의 시간 필터로 안정화. 시작은 그 시점의 인식 상태로 판단한다(레벨 판정). 인식으로 시작한 회차만 카운트다운 중 "인식 안됨"이 되면 취소한다(별도 유예 없이 인식 판정의 유예 시간을 쓴다). `R` 조절 화면이 열려 있는 동안, `P` 일시정지 중, 시작할 때 조절값을 불러오는 동안은 자동 시작을 막는다 (`docs/SYSTEM.md` 4절) |
| 인식 범위 | 얼굴이 **화면 영역(스윗스팟)** 안에 있고, 크기가 **최소 이상·최대 이하**(거리 대신, 9:16 화면 높이 대비)이며, 신뢰도가 최소값 이상이면 인정한다. 운영자가 숨김 화면(`R` 키)에서 영역·최소/최대 크기·최소 신뢰도·판정 시간을 조절한다 |
| 인식 기준 기본값 | 영역 가운데 0.8×0.8, 최소 얼굴 크기 0.05, 최대 얼굴 크기 0.6, 최소 신뢰도 0.7, 인식됨까지 0.5초, 인식 안됨까지 1초 (2026-10-15 결정. 현장 실측 후 조정) |
| 감지기 재시도·장애 기준 | 재시도 15초부터 두 배·최대 300초, 연속 3회 실패부터 장애, 반복 오류 로그 요약 60초 (4-1. 사용자가 이 값으로 진행하기로 함 2026-10-15. 현장 운영 뒤 조정) |
| 조절값 파일 | 시작할 때 읽기 제한 3초(넘으면 기본값), 쓰기 본문 상한 16KB, 일시정지 표시 켬 (4-3) |
| 인식 대안 | 실측에서 얼굴 누락이 잦으면 Object Detector(`person`)나 Pose Landmarker를 비교 |
| 로컬 서버 | PowerShell `HttpListener` 정적 서버, 빌드 없는 바닐라 ES 모듈 (`docs/SYSTEM.md` 1절) |
| 사진 처리 | 브라우저 메모리에서만 현재 회차용으로 유지. 외부 전송·자동 저장 없음 |
| 카메라 권한 | 키오스크 전용 Chrome 프로필에서 운영자가 처음 한 번 "허용"을 누른다. 자동 수락 플래그(`--use-fake-ui-for-media-stream`)는 경고 막대가 화면을 가려 쓰지 않는다 (4-2, `docs/SYSTEM.md` 1절 "현장 실행 스크립트") |
| 효과 장애 | WebGL2를 만들지 못하거나 컨텍스트를 잃으면 원본 미리보기로 돌아가고 D 화면에만 표시한다. 카메라·감지·촬영은 계속된다 (5-1). 결과 사진에 효과를 그리지 못하면 원본 사진(결과 크기)으로 대신하고 D 화면·경고 로그에 남긴다. 촬영 실패로 처리하지 않는다(관람객은 다시 찍을 방법이 없다) (5-2). 감열지 모드에서 효과를 그리지 못하면 원본 사진에 같은 감열지 단계를 CPU로 적용해 인쇄 데이터까지 만들고(사용자 승인 2026-10-19), 감열지 단계 자체가 실패하면 원본 컬러 사진으로 대신한다 (6-1) |
| 감열지 점 방식·표시 (6-1) | 점 방식 기본값 **블루 노이즈**(GPU 문턱값). 실제 카메라에서 그림 사이에 바뀌는 점이 0.6%(오차 확산은 17~27%)로 미리보기가 안정적이고, 비용이 효과 끔과 같다. Atkinson·Floyd–Steinberg·Bayer도 고를 수 있다. 밝기 0·대비 1·감마 1(중립). 화면 종이색 `[246,242,233]`·잉크색 `[26,26,30]`. 인쇄 해상도로 줄일 때는 면적 평균. 결과 형식: 감열지는 화면용 PNG + 인쇄용 1비트 데이터, 회색조·끔은 JPEG (로그 2026-10-19-01). 점 방식 기본값 블루 노이즈는 사용자 결정(2026-10-19)이며 실제 프린터 비교 전까지 가안 |
| 흑백 스타일 (7-1) | 톤 점(6-1 그대로) / 질감 강조 점(획 볼록 조명·국소 대비 + 점 방식) / 흐름 선(흐름장 LIC) / 붓 결 선(획마다 획 방향 선). **기본값은 붓 결 선·선 간격 4점·질감 세기 1을 제안해 가안으로 넣었다.** 붓 자국이 가장 잘 보이고 비용이 톤 점과 같다. 대신 boil 0.1에서 그림 사이에 점 5%가 바뀐다(톤 점 0.6%). **최종 선택은 사용자가 화면·비교 그림을 보고 한다** (로그 2026-10-19-04) |
| 감열지 화면 확대 | 화면 표시에만 "정수배 최근접 + 경계 1화소만 섞는" 확대(sharp bilinear 계열)를 쓴다. 미리보기와 결과 화면용 이미지를 같은 식으로 결과 크기(1080×1920)에 만들어 화면에서 같게 보인다. 인쇄 데이터(1비트 정본)는 그대로 (사용자 결정 2026-10-19, 구현 6-1) |

    - 결과 1080×1920이 셔터 직전 미리보기 그림과 같음을 수치로 확인했다(블록 평균 차이 0.32~0.48/255, JPEG 때문). 실제 OBS·가짜 카메라 모두.
    - `E` 조절 → 저장 → 새로고침 뒤 유지, 결과 효과 실패 시 원본 사진, 서버 API의 정상·거절 경우를 확인했다.
    - `npm run check:browser`가 실제 카메라 모드에서도 전부 통과한다(`S` 앞에 `P` 일시정지).
- 6단계 현황 (2026-10-19):
  - 6-1 감열지 흑백 출력 단계: 구현 완료, 검수 전(로그 2026-10-19-01, 브랜치 `stage6-thermal-bw`).

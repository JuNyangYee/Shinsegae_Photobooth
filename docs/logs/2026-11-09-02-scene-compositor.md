## 결정과 이유

- **Mirror 조사 결과와 이식 범위.** Mirror는 `public/filter/current.json`(엔진 JS 원문·해시·조절 정의·기본값)을 해시 확인 후 blob import하고 GPU 시험 뒤 실패하면 내장판을 쓴다. 틱마다 장면 전체를 소스 한 장으로 합성해 엔진을 한 번 돌린다. 합성 구조와 패키지 계약(검증 → 활성판, 실패 시 내장판, 운영자 명시 업데이트·복원)은 따랐다. **blob 모듈 실행은 이식하지 않았다**: CSP `script-src 'self'`와 13단계의 원격 JS 실행 금지 경계를 깨기 때문이다. 활성 번들은 13단계 GLSL 검증 경계를 그대로 쓰고, 없거나 실패하면 `filter-builtin.json`(Mirror 내장판과 같은 `7f58eaa`)이다.
- **유화 1회.** 합성 중 카메라 효과는 표시용만 유화 없이 출력 단계만 그리고(`setCompositeMode`·`drawCompositeFrame`), 화면 전체 유화는 1회다.
- **출력 계약 (사용자 확정 2026-11-09, 부모 전달):** 전체 화면 필터가 켜지면 "화면에서 본 유화 느낌을 사진에도 반영". 화면과 사진에 서로 다른 유화 수치를 쓰는 앞선 가안은 폐기했다. 구현(`273a03a`): 사진 전용 렌더러가 화면과 같은 번들·유화 수치·seed로 **셔터 순간 카메라 층만** 칠한다. 합성 그림을 자르지 않으므로 장식이 입력에 없다. 그 뒤 기존 흑백·1비트 경로다. 합성 중 필터 섹션의 유화 켬/끔·수치는 쓰지 않지만 저장값은 그대로이고 끄면 다시 쓴다. 끔·장애·사진 렌더 실패면 기존 카메라 효과 경로.
- **감열지 시험 (사용자 확정):** 앞선 전체 우회 가안을 폐기했다. 화면 필터(배경 포함)는 그대로 돌고, 같은 유화 결과의 1비트 점을 창 자리에만(`#screen-dots`, 틀·캐릭터 자리는 지움) 보인다. 점 위에 유화를 다시 입히지 않는다.
- **결과 화면은 고정 프레임.** 결과 Blob을 합성하면 이중 유화라, 셔터 순간 카메라 층(출력 단계만)과 seed를 회차 동안 메모리에 두고 합성한다(사진도 같은 층·seed). `CAPTURING`·`RESULT`를 벗어나면(취소·실패 포함) 비운다. 고정 중에는 효과 소스 프레임을 건드리지 않는다.
- **필터 밖:** 셔터 빛, 준비 중·직원 문의 글자, D·`P`, 운영자 UI(가독성·운영).
- **기본값 가안:** 켬, 처리 해상도 0.75(810×1440), 조절값은 활성 번들의 받은 기본값(level 50, flat, fps 15). 저장값 파일이 없으면 기본값.
- **게이지:** 사용자 허용으로 제거. 요소는 지우지 않아 기존 타이밍 검사를 유지한다.
- **작은 영어 줄 (채택):** 유화에 뭉개져 2.59cqw → 3.7cqw, 자간 0.2 → 0.12em. 합성 화면에서 읽히는 수준이다. 현장 설치 거리의 가독성은 미검증.

**비교 마스크:** 밝기 블록 비교는 1080 기준 화면 x330~780·y420~980만 쓴다(블록 20px, 표본 2px 간격). 채택 장면에서 이 구역은 키 그린 전부라 캐릭터·틀이 없다(`fit` 환산 이미지 x310~684·y389~857, 직접 확인). **블록 평균 차는 비슷한 그림을 뜻하며 화소 동일을 뜻하지 않는다.** 화면은 합성 위 810×1440, 사진은 카메라만 1080×1920이고 기준은 가짜 카메라의 단순 도형이다.

**감열지 창 점 = 인쇄 점:** 같은 사진 렌더러·설정·seed·셔터 층에서 `canvas`(창)와 `print`(인쇄) 출력을 만든다(구현). 결과 동안 `#screen-dots`와 결과 사진(인쇄 마스크를 잘라 확대한 PNG)을 사진 틀 전체 화소로 비교해 채택 장면에서 **80만 859화소 중 다른 화소 0**이었다. 비교 제외: 틀·캐릭터가 덮어 점을 지운 화소(알파 255 아님) 73,941화소. 가짜 카메라 기준이며 실물 인쇄 출력과의 비교는 아니다.

**합성 브라우저(가짜 카메라·합성 장면, 개발 PC RTX 5090, 실제 카메라 아님):**
- 새 계약 (`273a03a`, 가짜 카메라의 단순한 도형 영상이라 인물·복잡한 그림은 미검증): 결과 사진과 화면 창 안(캐릭터 없는 450×560 구역)의 밝기 블록 평균 차 **채택 장면 1.73·1.79/255**(2회 실행, 이전 임시 장면에서는 1.73~3.08, 기준 < 16, 화면은 합성 위 810×1440·사진은 카메라만 1080×1920이라 화소 동일 아님), 결과 사진 색 차 0(장식 색 없음), 사진 810×1080. 감열지 시험: 화면 필터와 창의 1비트 점이 함께 보이고 창 밖 점 0, 종이·잉크 외 화소 30%(확대 경계), 인쇄 데이터 생성.
- `최종 화면 필터` 시나리오 통과: 합성 캔버스가 1080×1920을 덮음, 카메라 효과 캔버스 숨김, `S` 회차 결과 동안 D `frozen`, 회차 뒤 해제, 인쇄 데이터 `576x768 1-bit`, `E` 화면 끔 → 기존 화면, 저장 없이 닫으면 되돌림, 저장 → 파일 반영, 끄면 `bypass (disabled)`.
- 눈 글씨 재현: 화면 필터 켬/끔 촬영에서 글자·숫자 위치와 숫자 모양이 일치.
- 기존 시나리오(화면 필터 끔으로 실행) 통과: 페이지 로드, 사진 효과 미리보기, 촬영 결과(결과 = 셔터 직전 미리보기 블록 비교), 효과 WebGL2 생성 실패, 시험 조합 4가지, 운영자 패널, 관람객 화면, 시안 데모, 외부 요청 0·CSP 위반 0·예외 0. **전체 시나리오는 실행하지 않았다**(사용자 간단 검수 정책, 출력 모드 전환·흑백 스타일·조절 저장·좌우 반전·카메라 변환·시간 섹션은 이번에 재실행하지 않음).
- 채택 장면 최종 실행(이미지 연결 뒤): `최종 화면 필터`·`관람객 화면` 시나리오 통과. 합성 화면을 눈으로 확인(대기·카운트다운·결과·감열지 시험).
- 성능(개발 PC): D `screen` 안정 뒤 15 그림/초, 프레임 표시 5.8ms. 이 값은 합성·GL 호출을 기록하는 메인 스레드 시간이고, 시작 직후 평균은 약 170~250ms다. **GPU 소요 시간은 재지 않았고** 현장 PC 값이 아니다.

**미검증:** 실제 카메라·OBS·4K·현장 PC 성능·실물 감열지·장시간 운영·`E` 화면 조절의 현장 값·감열지 시험의 현장 동작. 채택 장면의 합성 품질은 가짜 카메라로 확인했으며, 실제 현장 확인은 남아 있다.

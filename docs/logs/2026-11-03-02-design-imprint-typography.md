# 2026-11-03-02 — 디자인 IMPRINT (텍스트·타이포, 사용자 채택 확정 · 병합 전)

브랜치 `design-typography-claude`(`master` `81dc8f4`에서 분기). 디자인·구현 에이전트(Opus 5.5)가 독립적으로 정하고 만들었다(오케스트레이터는 디자인에 관여하지 않음, 다른 시안·참고 이미지는 보지 않음). 시안으로 만들었고 사용자가 골랐다(아래 "사용자 채택과 현장 저장값 대조"). 이 에이전트는 `master` 병합·push를 하지 않는다(독립 검수 뒤 오케스트레이터).

## 요청 (사용자 원문, 오케스트레이터 전달)

- "지금 보니까, 느낌이 너무 이상하다. 좀 그냥 세련된, 약간 텍스트/타이포 스타일의 디자인도 다른 에이전트 2개(gpt / claude) 해서 요청해봐봐." 후속: "참고 이미지는 전달하지 말고"
- 조건: 화면 9:16 고정, 사진은 9:16일 필요 없음, 최종 결과는 감열지 흑백, 흐름은 깔끔하게·모션은 세련되고 유니크하게, 완전 비접촉. 카운트다운·안내가 촬영 중 자기 모습을 가리지 않게. 카메라 없는 데모(실제 동작과 구분, 검토용 조작은 관람객 화면과 구분). 사진 비율을 바꾸면 캡처·효과·인쇄 데이터·감지 좌표가 맞는지 확인. 인쇄 완료를 가장하지 않음. 기존 E·D·S·X·P·촬영·취소·장애·자원 정리 유지.
- 작업 도중 세션이 끊겨 "이어서 진행해"로 같은 브랜치에서 이어 완성했다(처음부터 다시 만들지 않음).

## 시안: IMPRINT

화면을 **활자로 짠 한 쪽**으로 다룬다. 9:16 화면 안에 실제로 찍히는 **4:5 사진 틀**(화면 폭 전체)을 두고, 틀 밖 위·아래 여백은 영상을 어둡게 눌러 글자 자리로 쓴다. 감열지 출력물도 같은 쪽 구성(머리 날짜·시각 → 사진 → 꼬리 한 줄)이라 화면과 인쇄가 같은 모양의 쪽이다. 이름은 책의 판권 표기·찍힘(imprint)에서.

## 결정과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| 사진 비율 | **4:5**, 9:16 화면 폭 전체 × 높이 7/64~52/64 (`config.photoFrame`) | 글자를 사진 위에 얹지 않고 틀 밖 여백에 둘 수 있어 촬영 중 얼굴·몸을 전혀 가리지 않는다. 감열지 한 장이 짧아진다(사진만 1024줄 → 쪽 전체 912줄). 64분의 몇이라 결과 1920·인쇄 1024·4K 3840·감지 640줄에서 모두 정수 줄(결과 210~1560, 인쇄 112~832)이고 결과·인쇄가 같은 화면 줄을 덮는다. 화면 폭 전체라 결과 사진이 1080 화면 1:1·4K 2:1로 놓여 다시 보간되지 않는다 |
| 자르는 곳 | 효과 단계 마지막 한 곳(`photo-effect.js` `framed`)과 인쇄 데이터 한 곳(`printData` → `imprintPage`) | 미리보기·셔터 순간 그림은 9:16 그대로라 "결과 = 셔터 순간 그림"이 유지된다(틀 줄만 남김). 모든 결과 경로(효과·원본 대체·감열지·회색조·끔·효과 끔)가 같은 자르기를 거친다 |
| 감지 좌표 | 좌표계는 그대로(9:16 화면 영역), 감지 루프에 넣는 인식 영역만 틀과 겹친 부분으로 줄임(`clipRegionToFrame`) | 틀 밖(여백)에 얼굴 중심이 있으면 찍혀도 사진에 얼굴이 없다. 저장 값·편집 사각형은 운영자 값 그대로라 시안을 버려도 파일이 바뀌지 않는다 |
| 인쇄 쪽 | 머리(촬영 날짜·요일·시각) + 틀 사진 + 꼬리(세리프 "Set in light, printed in heat."·용지 폭), 글자는 캔버스 → 문턱 128 → 1비트 래스터로 인쇄 데이터에 넣는다 | 출력물이 "이 순간"의 기록이 되게(관람객 화면 머리 시각 = 인쇄 시각). 래스터라 화면과 같은 서체. 프린터 글꼴 명령으로 넣을지는 인쇄 연동 때 정한다(PROJECT TBD에 추가) |
| 촬영 시각 | `capture.js`가 프레임을 잡는 순간 `Date.now()`(`clock`)를 재어 효과 단계(`takenAt`)와 사진(`photo.takenAt`)에 같은 값 | 화면 머리와 인쇄 쪽 머리가 어긋나지 않게(초 경계에 걸려도) |
| 서체 | 한국어 = Pretendard 400(큰 줄), 영어·숫자 = Noto Serif KR Light의 라틴 글자, 작은 표기 = Pretendard 500 대문자 | 새 서체 파일 없이(저장소 부분 집합 그대로) 산세리프·세리프 짝을 만든다. 세리프 부분 집합은 U+0020–007E를 다 담고, 세리프 한글은 확정 문구 "준비 중입니다."뿐이라 문구를 바꿔도 서체를 다시 줄일 필요가 없다 |
| 색 | 무채색만(오프화이트·종이·먹·차콜) | 회색조 유화·감열지와 같은 흑백. 강조색 없이 굵기·크기·간격으로만 위계 |
| 모션 | 줄 짜 넣기(창 아래에서 올라와 자리 잡음)·빠지기(복제본이 위로), 3·2·1 숫자 넘기기, 틀 아래 선 = 진행선, 틀 안 셔터 빛, 머리 시각이 셔터에 멈춤, 결과 둘레가 종이로 번짐, 모서리 표시가 인식에 모임, 바닥 쪽 가는 선 | 활자 조판(줄을 짜 넣는다)과 기계식 숫자판에서 온 움직임. 모두 `transform`·`opacity`(미리보기·감지·효과 성능을 건드리지 않음). 상태(`hidden`)는 즉시 바뀌고 빠지는 움직임은 복제본이 맡아 확인 도구·테스트가 읽는 값이 늦지 않다 |
| 결과 화면 | 사진은 틀 자리에 움직임 없이(멈춘 그림처럼), 둘레가 종이가 되고 문구·남은 시간 선 | 셔터 직후 같은 자리 같은 그림이 멈추므로 끊김이 없다. 카드가 날아오는 움직임은 비정수 배율 보간을 피하려는 기존 규칙과도 맞지 않았다 |
| 결과 문구 | "사진이 완성되었습니다 / Your portrait is set." (출력 중이면 "사진을 출력하고 있습니다") | 인쇄 연동 전이라 "출력된 사진을 받아 가세요"는 인쇄 완료를 가장한다. 연동 뒤 출력 완료 다음 문구는 그때 정한다 |
| 동작 줄이기 | `main.js`가 `prefers-reduced-motion`을 `:root[data-motion]`으로, CSS·`guest-screen.js`가 이 값 하나를 본다 | 시스템 설정과 데모의 검토용 강제를 같은 길로. 정보가 되는 진행선은 그대로 둔다 |
| 데모 | `src/web/demo/`(새 폴더, 검토용 페이지): 앱 `#stage` 마크업을 `fetch('/')`로 그대로 불러오고, 도형 합성 장면을 `captureStream()`으로 실제 카메라 처리 경로·효과·촬영·인쇄 경로와 실제 상태 기계·자동 시작 판정에 넣는다. 감지기 대신 패널 조작으로 "인식됨" | 화면 마크업·CSS·모듈을 복사하지 않아 시안과 데모가 어긋나지 않고, 카메라 없이도 실제 회색조 유화 그림·실제 인쇄 데이터를 본다. 검토용 조작은 9:16 영역 밖 패널에만 |

## 장시간 걸린 효과 테스트 (이어 하기 전 기록, 원인 확인)

중단 전 `npm test`에서 `photo-effect.test.mjs` "회색조: 효과 실패 시 원본 사진(결과 크기)을 회색조·레벨로"가 **283초** 걸렸다(그때는 실패한 상태).

- **재현:** 그 테스트 파일을 실제 기본값(사진 틀·인쇄 쪽 켬)으로 돌리는 임시 사본(저장소 `test/effect/` 안, 끝난 뒤 지움)에서 그 테스트만 100초 제한으로 실행 → 제한 시간 초과로 재현.
- **원인:** 효과 처리 자체가 아니다. 같은 경로를 임시 스크립트로 재면 `apply` **21ms**, 실패한 `assert.equal(out, raw)`가 오류 메시지를 만드는 데 **225,769ms**(30자 메시지). 사진 틀로 잘라 결과가 원본 캔버스와 다른 객체가 되자 단언이 실패했고, Node `assert`가 두 값을 문자열로 펼치며 가짜 캔버스 기록(`ops`) 안의 1080×1920×4 화소 배열(830만 칸)을 끝까지 펼쳤다.
- **조치:** 그 묶음(효과·인쇄 마스크 자체를 보는 기존 검사)은 `frame: null, imprint: null`로 9:16 그대로 돌려 원래 뜻을 지키고, 실제 기본값 경로는 새 묶음 "사진 틀·인쇄 쪽"이 큰 배열을 단언에 넣지 않고 크기·호출·줄 값으로 본다. 지금 그 테스트 20ms, `photo-effect.test.mjs` 전체 약 0.5초.

**시간 섹션 간헐 실패 — 원인 확인 (확인 도구, 10단계부터 있던 경쟁):**

- 실패 기록은 `countdown` 단계·숫자 "5"·진행선 5000ms만 있고 `capturing`이 없었다. 수동(`S`) 회차를 대기로 되돌리는 것은 카메라 준비 해제·페이지 숨김·초기화뿐인데 최근 기록에 그런 것이 없었다.
- 확인 도구의 회차 기록기(`TIMELINE`, D `session` 줄을 `MutationObserver`로 본다)는 새로 연 페이지에서 `last = ''`로 시작했다. 기록기를 설치한 뒤 `S`를 누르기 전에 D가 0.5초 주기로 다시 그려지면 지금 상태 `idle`을 "바뀐 상태"로 남기고, `timedRound`는 "대기로 돌아옴"을 이미 본 것으로 여겨 카운트다운 시작 직후 끝낸다. 새로고침 직후 첫 회차(`reload+S`)에서만 생기고, 설치와 `S` 사이(CDP 두 번, 수 ms)에 D 갱신이 끼어야 하므로 드물다.
- **재현:** 기록에 대기로 돌아온 이유(D `last end`·`status`·`ignored`)와 단계 순서를 남기도록 보강한 뒤, 설치와 `S` 사이에 0.6초를 임시로 넣어(D가 반드시 한 번 다시 그려지게) 가짜 카메라로 돌리면 **매번 같은 모양으로 실패**: `states "idle@464 countdown@606"`, `idle {"end":"-","camera":"ready"}`(취소가 아니라 S 전의 대기를 센 것).
- **수정:** 기록기가 설치·초기화 순간의 상태를 `last`로 잡는다. 같은 0.6초 지연을 둔 채로 통과(`reload+S countdown 5030ms (54321, bar 5000ms), result 4002ms, cooldown 1006ms`)를 확인하고 임시 지연은 지웠다(백업과 비교해 의도한 줄만 바뀐 것 확인). 앱 코드는 고치지 않았다(앱 동작은 맞다).

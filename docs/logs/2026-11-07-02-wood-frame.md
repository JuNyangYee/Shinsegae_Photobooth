# 2026-11-07-02 — 16단계: 나무틀 3:4 사진 창

부모 지시에 따른 구도·UI 담당(Opus) 기록이다. 이미지는 이미지 담당이 만들었고 [로그 03](2026-11-07-03-wood-frame-image.md)에 있다. 브랜치 `stage16-wood-frame`(`master` `f386920`에서), 병합·push는 하지 않았다.

## 사용자 요청

"카메라 영역이 지금 좌우 꽉 차는데, 좌우에도 여백을 둬서 틀을 3:4 비율로, 나무틀 구조로 해보자."

## 좌표 결정 (가안)

- 9:16 화면은 그대로. 실제 카메라 개구부 = `config.photoFrame` `{ left: 1/8, top: 3/16, width: 3/4, height: 9/16 }` → 1080×1920에서 **x135~945·y360~1440, 810×1080, 정확한 3:4**.
- 고른 이유: 좌우 135px(기둥 36px + 배경 약 99px)이면 여백이 분명히 읽히고, 결과 1080·인쇄 격자 576×1024·4K·감지 360×640에서 모든 끝이 정수다(1080: 135·945·360·1440, 576×1024: 72·504·192·768, 4K: 270·1890·720·2880, 360×640: 45·315·120·480). 위 띠 360px는 캐릭터 자리, 아래는 들보·눈벽·넓어진 눈 바닥(글씨).
- 이 좌표와 나무틀(위 들보 y342~378, 아래 y1422~1458, 기둥 x117~153·x927~963), 눈벽 y1458~1560, 캐릭터 자리를 가이드 PNG와 함께 부모·이미지 담당에게 먼저 보냈다.

## 한 일

- **사진 틀 직사각형 (`core/photo-frame.js`):** `photoFrameCols`·`photoFrameRect`·`cropRect`·`padColumns`를 더하고 `clipRegionToFrame`·`photoFrameAspect`·`isFullFrame`이 가로도 본다. `left`·`width`가 없는 예전 틀은 화면 폭 전체로 읽는다.
- **결과·인쇄 (`effect/photo-effect.js`):** 결과 사진을 직사각형으로 자른다(810×1080, 4K 원본 대체는 1620×2160). 인쇄는 같은 576×1024 점 격자에서 72~504열·192~768줄을 잘라 432×576 사진을 용지 가운데에 놓고 좌우는 흰 종이다 → 쪽 576×768(약 96mm). 감열지 화면 미리보기의 점과 인쇄 점이 그대로 같다.
- **관람객 화면:** CSS 변수 `--frame-left/w`, 결과 카드·셔터 빛이 창 직사각형에, 대체 배경 좌우 여백 요소(`.frame-margin.is-left/right`), 눈 바닥 위끝 5/6(1600).
- **장면 맞춤 (`ui/scene-plate.js`):** 생성 개구부가 0.791(724×915)이라 3:4와 다르다. 원본은 그대로 두고 균일 배율(1080/915)로 개구부 높이를 창 높이에 맞추고 가로 가운데를 맞춘다(`fitPlacement`, 찌그러뜨림 없음). 창 밖 좌우에 남는 약 22px 그린은 기둥 안쪽 경계(줄마다 잰 가운데값) 축으로 나무를 거울 복사하고(`fillFrameGap`), 그 띠와 축 둘레의 초록 기를 누른다. 키 직사각형 중 창 밖은 늘 불투명(`sealOutsideFrame`). 캔버스 아래에 못 미치는 약 30px는 이미지를 거울로 잇는다. 키는 창 ± 30px 직사각형에서만.
- **D·인식:** D `frame` 줄 `photo 3:4 = stage cols 0.125-0.875 rows 0.1875-0.75 (result 1080x1920 -> 810x1080@135,360, print 576x1024 -> 432x576@72,192)`, 겹쳐 그리기는 틀 직사각형, 인식 영역은 가로·세로 모두 줄인다. 영역 끌기·저장값 형식은 그대로(운영자가 정한 영역을 저장하고 감지에 넣을 때만 줄인다).
- **데모·확인 도구:** 데모가 같은 CSS 변수·맞춤을 쓴다. `tools/browser-check.mjs`의 틀·결과·인쇄 기대값과 결과=미리보기 비교를 직사각형으로 바꿨다(0.5배 미리보기에서는 왼끝 67.5px라 블록 비교 시작을 반올림).

## 결정과 이유

- **인쇄 사진은 용지 가운데 432점:** 용지 폭을 꽉 채우려면 감열지 점 격자를 창 기준으로 다시 짜야 하고(셰이더·CPU 대체·화면 확대 모두), 그러면 지금의 "미리보기 점 = 인쇄 점" 확인을 새로 만들어야 한다. 이번에는 정확성을 지키고 액자처럼 흰 여백을 두었다. 용지를 채우는 쪽은 다음 후보로 남긴다.
- **카메라는 크롭:** 영상을 창에 맞춰 줄이거나 늘리지 않는다. 보이는 창 = 찍히는 사진이다. 대신 화각이 좁아진다.
- **장면 맞춤:** 생성 도구로 개구부 비율을 정확히 맞추기 어려워(이미지 담당 1회 생성, 0.791) 균일 배율 + 틀 밖 채우기로 정확한 3:4를 만들었다. 비등방 늘림은 하지 않았다. 처음에는 줄마다 경계를 재서 캐릭터가 걸친 줄에서 끊겨 카메라가 비치고 축에 초록 줄이 남았다 → 경계를 가운데값 한 열로, 띠 번짐 제거·창 밖 불투명을 더해 고쳤다.
- **곰 크기:** 이미지 담당 보고대로 푸빌라가 약간 커 보이지만 원형 키비(103:66:60:27) 안에서 크게 벗어나지 않는다고 보고 이번 판을 썼다. 사용자 원형 검수로 남긴다.

## 검증

카메라는 Chrome 가짜 장치(합성 영상), 임시 프로필 headless Chrome(GPU)이다. 실제 사진은 저장하지 않았다.

- `npm test`: 734개 통과(직사각형 자르기·4K·감지 정수 좌표, 인쇄 가운데 넣기, 맞춤·틀 밖 채우기·불투명 테스트 포함).
- `browser-check --only`: 관람객 화면(틀 x135~945·y360~1440, 결과 상자 = 틀, 인쇄 576×768, D `frame`, 위 띠 UI 없음, 장면 `fit x1.180 gap 42467 sealed 1591, oil painted`), 촬영 결과(회색조 유화 기본값, 0.5배 미리보기 블록 차 1.236/255, `gpu=cpu`), 시험 조합 4가지, 흑백 스타일 4가지(네 스타일 모두 셔터 순간 그림과 결과 화면용 PNG 0px 차이, 인쇄 576×768), 시안 데모(결과 810×1080, 인쇄 PNG 576×768) 모두 통과.
- 합성 화면을 직접 확인: 결과 사진이 좌우 기둥·위아래 들보 안에 정확히 들어가고, 좌우 여백에 눈 마을이 보이며, 기둥 안쪽 채운 띠에 초록 줄·카메라 비침이 없고(깨또·포코·후트 둘레 확대), 안내·숫자는 눈 바닥 홈. 캡처는 `artifacts/`(Git 제외)에만 있다.
- 실제 웹캠·OBS·4K 화면·현장 PC·실제 사람·실제 감열지는 **미검증**. 인식 영역 끌기·인식 섹션 시나리오는 이번에 다시 돌리지 않았다(좌표 계산은 Node 테스트, D 겹쳐 그리기는 코드만). 현장 `config/*.local.json`은 읽거나 바꾸지 않았다(저장 형식 변경 없음).

## 남은 문제

- 화각이 좁아져 현장 단체 촬영 폭이 충분한지 확인이 필요하다. 필요하면 운영자 카메라 확대·이동으로 맞춘다.
- 인쇄 사진이 432점 폭(약 54mm)으로 작아졌다. 용지 폭을 채우려면 점 격자 재설계가 필요하다.
- 이미지 담당 장면은 개구부·캐릭터 화소가 생성 재현이라 사용자 원형 검수가 남는다.

## 간단 검수 반영 (P2 1건 채택)

- **지적:** `photo-effect.js` `framed`가 자르기 캔버스를 못 만들면 9:16 전체(1080×1920)를 돌려주는데, 결과 창(810×1080)은 `object-fit: cover` + 예전 세로 `object-position`이라 원본 x0~1080·y205.7~1645.7이 보였다. 정상 창 x135~945·y360~1440과 달라 인물이 작아지고 화각이 넓어 보였다. 기존 Node 테스트는 전체 사진을 돌려주는지만 보아 화면 일치를 증명하지 못했다.
- **수정:** `ui/guest-screen.js`가 결과 사진 비율이 화면 비율(9:16)이면 `#result-card`에 `is-uncropped`를 붙인다(`stageAspect` 주입, `main.js`·데모). CSS는 그 사진을 9:16 전체 크기(`100cqw` × `--stage-h`)로 창 위치만큼 당겨 놓고 `.result-photo`(`overflow: hidden`)가 창 밖을 자른다. 정상 크롭 경로·자원 정리·결과 교체·인쇄 데이터는 그대로다. 예전 세로 `object-position` 규칙과 "세로 줄만 맞음" 주석·테스트 이름을 고쳤다.
- **검증:** Node `test/ui/guest-screen`·`test/effect/photo-effect` 36개 통과(정상 3:4는 클래스 없음, 1080×1920·2160×3840 대체는 클래스, 결과가 끝나면 지움). `browser-check --only "관람객 화면(14단계"` 통과: 결과 화면에서 클래스를 잠깐 붙여 잰 배치가 사진 0,0,1080×1920 · 창 자르기 135,360,810×1080 · `overflow hidden` · `object-fit fill`. 자르기 실패 자체는 앱에서 일으킬 수 없어(확인 전용 훅 없음) 클래스 배치만 잰 것이고, 실제 장애 사진의 화소 비교는 하지 않았다. 실제 카메라·전체 GPU·전체 회귀는 다시 돌리지 않았다.

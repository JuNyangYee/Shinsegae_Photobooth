# 2026-10-15-08 — 3-2 인식 결과로 자동 시작, 대상이 떠나면 취소

브랜치 `stage3-capture-cycle`, 기준 커밋 `40dc0cf`(3-1). 작업 에이전트(Opus 5.5)가 오케스트레이터가 지시한 3-2 범위만 진행했다. 사진 효과, 인쇄, 현장 실행, 최종 디자인은 넣지 않았다.

## 전제 (결정, 2026-10-15)

- 로그 07 질문에 대한 결정: `S`·`X` 유지, 쿨타임 문구 가안 유지, JPEG 0.92 유지. `R` 조절 화면이 열려 있는 동안 인식에 의한 자동 시작을 막고, `S`는 허용한다.
- **사용자 확정:** 쿨타임 5초가 지나면 스윗스팟이 비어 있지 않아도 진행한다. 그래서 자동 시작은 인식 상태가 바뀌는 순간(엣지)이 아니라 그 시점의 인식 상태로 판단한다(레벨 판정). 사람이 계속 서 있으면 쿨타임이 끝나는 즉시 다음 회차가 시작된다.
- 인식으로 시작한 회차는 카운트다운 중 "인식 안됨"이 되면 취소한다. `S`로 시작한 수동 회차는 인식 상태로 취소하지 않는다.

## 결정과 이유

- **카메라 준비·페이지 보임은 상태 기계 스냅숏 값으로 판정한다.**
  - 카메라 모듈을 따로 구독하면 구독 순서에 따라 상태 기계가 카메라 준비를 받기 전에 평가할 수 있다. 그러면 시작 요청이 `camera-not-ready`로 무시되고, 그 뒤 다시 평가되지 않는다.
  - 상태 기계가 값을 받아 알리면(`setCameraReady`·`setPageVisible` → `notify`) 그 알림을 계기로 같은 값으로 판정한다. 판정과 상태 기계가 늘 같은 값을 보므로 무시되는 시작 요청을 보내지 않는다.
- **평가 계기:**
  - 인식 상태 변화
  - 상태 기계 알림: 대기 진입(쿨타임 종료·취소·초기화), 카메라 준비 변화, 페이지 보임 변화
  - 조절 화면 닫기
  - 지시의 계기(인식 변화, 대기 진입, 카메라 준비, 조절 화면 닫기, 페이지 다시 보임)를 모두 덮는다.
- **시작은 한 번만:**
  - 받아들여지면 상태가 `countdown`이 되므로, 같은 순간의 다른 계기는 요청 자체를 보내지 않는다.
  - 상태 기계의 중복 무시에 기대지 않고, 요청이 1회만 나가는 것을 테스트로 확인했다.
  - 요청이 상태 기계 알림을 일으켜 다시 불리는 경우(재진입)는 지금 평가가 끝난 뒤 한 번 더 평가한다. 최대 3회로 제한했다.
- **이탈 유예를 따로 두지 않았다(권장안 채택).** "인식 안됨"이 되는 데 이미 `absentGraceMs`(기본 1초)가 걸린다. 실측 이탈 취소는 기준 변경 후 약 1.04초였다.
- **조절 화면을 열어도 진행 중인 회차는 취소하지 않는다.** 지시는 "자동 시작을 막는다"였다. 자동 회차는 열린 상태에서도 이탈하면 그대로 취소된다.
- **강제 초기화(`X`) 뒤 사람이 서 있으면 바로 자동으로 다시 시작한다.** 지시대로 초기화 후 대기 진입 때 평가한 결과다. 자동 촬영을 멈추려면 `R`을 연다(아래 질문 1).
- **D 화면의 자동 시작 계기 기록은 시작이 받아들여진 뒤 남는다.** 그래서 시작 직후 그리는 D 화면에는 한 번 이전 값이 보이고, 다음 갱신(0.5초)에 바뀐다. 개발용 표시라 그대로 두었다.

### 검증 중 고친 것

- **D 화면이 이탈 취소 순간 감지기를 `paused`·0fps로 보였다.**
  - 수정 전 실행에서 첫 자동 시작 이후 0fps 표본이 12개, 25개 나왔다. 시각은 두 번 모두 이탈 취소 순간이었고, 각 0.4초(다음 D 갱신)까지였다. 카메라는 `ready`였다.
  - 원인: 인식 알림은 감지 `tick()` 안에서 나간다. 그 알림이 일으킨 취소가 D 화면을 다시 그리는 순간에는 `timer`가 비어 있어, 상태가 `paused`로 계산됐다. 감지 자체는 멈추지 않았다.
  - 수정: `presence-monitor.js`에 `ticking` 표시를 두어 실행 중도 `running`으로 본다. 같은 경로에서 `sync()`가 감지를 두 번 예약하지 않도록 `tick` 중에는 예약하지 않게 했다.
  - 수정 후 같은 시나리오에서 0fps 표본 0개, 감지 11~16fps.

## 남은 문제

- 이탈 취소와 자동 시작은 실제로 사람이 움직여서 확인하지 않았다. 인식 기준을 바꿔 인식 상태를 만들었다. 매트 위 실측이 필요하다.
- 자동 촬영을 잠시 멈추는 운영 수단은 지금 `R` 열기뿐이다. `X`는 서 있는 사람이 있으면 바로 다시 시작한다(아래 질문 1).
- D 화면의 자동 시작 계기 기록이 시작 직후 한 번 늦게 보인다(개발용 표시).
- 로그 07의 남은 문제(4K 캡처 미측정, JPEG·`captureTimeoutMs` 가안, D를 켠 채 결과를 보면 감지 박스가 겹침)는 그대로다.

## 결정과 이유

### 행사 전체 시각 언어 맞추기 (ThrowSnow)

- **맞추기로 했다.** 같은 행사·같은 공간의 웹 체험이라 서체·색·종이 결이 같으면 한 행사로 보인다. ThrowSnow의 서체 대체(지정 서체 대신 OFL 서체)도 같은 이유로 그대로 따랐다.
- **가져온 것:** 서체 woff 2개와 OFL 라이선스 2개, 종이 결 `paper.webp`. 바이트 그대로 복사했다(ThrowSnow 커밋 `78175c4`, ThrowSnow는 읽기만 했다).
  - SHA-256: `GowunBatang-Bold.woff` `8b2624ca…bd8dc`, `GowunDodum-Regular.woff` `0c08523d…a84c7`, `paper.webp` `1baeb998…bf89`.
- **가져오지 않은 것:** `fonts.css`(절대 경로 `/common/...`이고 이 저장소 경로와 다름. 선언을 `style.css` 맨 위에 새로 썼다), `ribbon.css`(가로 화면 제목 리본. 이 화면에는 제목 리본이 없고, 리본은 세로 프레임에 맞게 SVG로 그렸다).
- **색:** 크림 `#f3e4d6`·솔잎 `#2f5f52`는 ThrowSnow 값을 그대로 썼다. 딥 레드·골드는 요청 색 계열로 새로 정했다. ThrowSnow의 키 컬러(`#f55433`, 캐릭터 IP 색)는 이 체험에 캐릭터가 없어 쓰지 않았다.
- 출처·라이선스 표는 SYSTEM 3절 "관람객 화면 → 에셋 출처와 라이선스".

### 흑백 감열지 전제

- 미리보기가 흰 바탕 위 검은 점이 되므로, 흰 글자나 반투명 바탕 글자는 읽히지 않는다. **글자는 모두 불투명한 종이 알약·원판·카드 위에 둔다.**
- 색은 장식과 카드에만 쓴다. 흑백 사진 둘레의 딥 레드·솔잎 그린·금색이 화면의 색을 맡는다.
- 결과 카드는 흰 종이로 했다. 흑백 감열지 출력물을 들고 있는 느낌을 주기 위해서다.
- 확인은 효과 캔버스에 흑백 필터를 임시로 건 모의 화면(흰 바탕, 검은 바탕 두 가지)으로 했다. 실제 흑백 효과(6-1)는 이 브랜치에 없다.

### 인식 표시

- **"인식됨/인식 안됨" 글자를 없애고 테두리 빛으로 바꿨다.**
- **"곧 촬영해요" 문구는 두지 않았다.** 자동 시작은 레벨 판정이라 인식되는 순간 카운트다운이 시작된다. 대기 상태에서 인식 문구가 보이는 시간은 한 화면 갱신 정도라 깜빡임만 생긴다.
  - 인식된 채 대기에 머무는 경우는 운영자 조건(`P`, 조절 화면, 촬영 실패 대기)뿐이다. 그때 "곧 촬영해요"를 띄우면 거짓 안내가 된다.
  - 빛은 카운트다운·쿨타임에도 인식 상태를 따른다. 카운트다운 중 사람이 떠나면 빛이 먼저 꺼지고 유예(1초) 뒤 취소된다.
- **`config.showPresenceIndicator`의 뜻:** 예전에는 글자 표시 전체를 껐다. 지금은 빛만 끄고 대기 안내는 그대로 보인다. 대기 안내는 인식 표시가 아니라 대기 화면의 일부라고 봤다.
- 카메라·감지기를 쓸 수 없을 때(안내 문구 중)와 결과 화면에서는 예전처럼 끈다.

### 카운트다운

- 숫자는 1초마다 커지며 나타나고 끝 무렵 작아지며 사라진다. 숫자 사이의 비는 순간에도 원판과 원형 진행이 남아 끊기지 않는다.
- **원형 진행은 `transform`만 쓴다.** 두 반원(테두리 두 변만 색칠한 원을 반쪽 창 안에서 `rotate`)을 앞 1.5초, 뒤 1.5초에 차례로 돌린다. SVG `stroke-dashoffset`은 매 화면 갱신마다 다시 그려야 해서 쓰지 않았다.
- 원판 크기는 영역 폭의 46%, 원판 중심은 높이의 약 52%다. 예전(가운데, 폭의 40% 글자)보다 조금 아래다. 원판이 불투명해 얼굴을 가릴 수 있어 가운데에 그대로 두지 않았다. 현장 카메라 높이에 따라 조절이 필요할 수 있다(가안).

### 플래시

- 예전 흰색 0.9 → 0.4초를 따뜻한 흰빛(`#fff8ec`) 최대 0.7, 0.32초로 바꿨다. 0에서 약 50ms에 올라가 갑자기 번쩍이지 않는다.
- 플래시는 촬영 상태에 들어갈 때 한 번이다. 프레임은 그 순간 이미 잡혀 있으므로 사진에는 영향이 없다.

### 결과 화면

- 출력물 카드가 위에서 내려와 놓이는 움직임은 "사진이 나왔다"를 보이기 위해서다. 프린터 위치를 모르므로 방향은 가안이다.
- **문구:** 지금은 인쇄가 없지만 최종 체험에는 출력이 있으므로 "출력된 사진을 받아 가세요"를 가안으로 둔다.
  - "사진이 출력되고 있어요"는 종료 시계가 멈춘 동안(`endsAt` = `null`) 보이도록 연결해 두었다. 인쇄를 연동해 출력 중 종료 시계를 멈추면(SYSTEM 4절 "출력 연동 시 참고 흐름") 문구가 바뀌고 막대가 숨는다. 지금 상태 기계는 결과에 들어가면 바로 시계를 시작하므로 이 문구는 보이지 않는다(Node 테스트로만 확인).
- 남은 시간은 숫자 대신 줄어드는 막대(`scaleX`)로 했다. 초 숫자가 바뀌는 것보다 차분하다.
- 결과에서 쿨타임으로 넘어갈 때 카드는 바로 사라진다. 사진 `src`를 먼저 지우고 Object URL을 정리하는 순서를 지키면 사라지는 애니메이션에 쓸 사진이 남지 않기 때문이다.

### 쿨타임·준비 중·직원 문의

- 쿨타임 문구를 위쪽에서 대기 안내 자리(아래쪽)로 옮기고, 문구를 "다음 촬영을 준비하고 있어요"로 바꿨다(가안). 화면의 안내가 늘 같은 자리에 나오게 하기 위해서다.
- 준비 중·직원 문의 문구는 확정이라 그대로 두었다. 첫 줄은 `::first-line`으로 제목처럼 보인다. 확인 도구가 `#status` 글자로 상태를 읽으므로 글자를 나누지 않았다.
- 두 안내는 모양이 같고 방울의 움직임만 다르다(준비 중: 흔들림, 직원 문의: 멈춤). 직원 문의는 기다려도 풀리지 않는다는 뜻이다.
- 안내 막은 영상을 덮지만 장식 프레임보다 아래에 둔다. 장애 중에도 같은 체험 화면으로 보이게 하기 위해서다.

### 해상도 독립과 성능

- 관람객 화면의 길이·글자 크기는 모두 `cqw`(9:16 영역 폭의 1%)다. 예전 `clamp(16px, 4cqw, 48px)`는 4K에서 상한에 걸려 비율이 달라졌다. 새 화면에는 px 상한·하한이 없다.
- 움직임은 `transform`·`opacity`만 쓴다. 인식 빛은 `will-change: opacity`인 층의 투명도만 바꾼다. 그림자 블러는 움직이지 않는 요소에만 있다. 큰 블러·필터 애니메이션은 없다.
- 장식 SVG는 정적 이미지라 처음 한 번만 그린다. SVG 안 애니메이션은 쓰지 않았다.
- 결과 사진 `<img>`에 `decoding="async"`를 주었다. 아래 측정에서 결과 화면이 처음 그려질 때 한 프레임이 더 밀리는 경우가 있어 넣었다.
- 서체는 숨겨진 화면(카운트다운·결과)에서 처음 쓰여도 바로 보이도록 `<link rel="preload">`로 미리 받는다.

### 구조

- `ui/guest-screen.js`가 표현을 맡고, 무엇을 보일지는 지금처럼 `main.js`가 정한다. `main.js`에 애니메이션 코드를 더 쌓지 않기 위해 나눴다. 표현 규칙(카운트다운 회차마다 원형 진행 한 번, 같은 숫자로 다시 알려도 다시 움직이지 않음, 플래시 한 번, 결과 막대 시간)을 Node로 시험할 수 있다.
- `ui/` 폴더의 뜻을 "운영자용 DOM 화면"에서 "DOM 화면 표현(관람객·운영자)"으로 넓혔다(지시의 폴더 안내). `guest-screen`은 `core/session`의 상태 이름만 불러온다.
- `assets/`를 새 폴더로 만들어 SYSTEM 폴더 표·트리에 더했다. JS가 없는 폴더다.
- CSP는 넓히지 않았다. 서체·이미지가 같은 출처이고, 인라인 스타일 없이 `style.css`와 Web Animations·CSSOM만 쓴다.
- 서버 MIME에 `.woff`를 더했다. 없으면 `application/octet-stream` + `nosniff`로 나간다.
- SVG 가랜드는 저장소 밖 임시 스크립트로 솔잎 묶음 배치를 계산해 만들었다. 결과는 솔잎 한 묶음 기호(`<symbol id="tuft">`)를 `<use>`로 놓은 SVG라 손으로 고칠 수 있다. 생성 스크립트는 넣지 않았다.

### 화면 확인 (가짜 카메라, 임시 프로필 headless Chrome, 저장소 밖 임시 스크립트)

- 상태별 스크린숏을 저장소 밖 임시 폴더에 찍어 눈으로 확인하고 지웠다. 대기, 인식(모의), 카운트다운 3·2·1, 플래시, 결과(들어올 때·중간·끝 무렵), 쿨타임, 준비 중(모델 요청 404), 직원 문의(카메라 권한 거절)다.
  - 인식은 가짜 카메라에 얼굴이 없어 `#stage`에 `is-present`를 직접 붙인 **모의**다. 실제 인식은 아래 실제 카메라에서 DOM으로 확인했다.
  - 플래시는 애니메이션을 만들어지는 순간 60ms 지점에서 멈춰 찍었다.
  - 준비 중·직원 문의는 실제 경로(모델 요청 404, 권한 거절)로 띄웠다. 첫 줄 서체는 계산 스타일로 `"Gowun Batang", serif`, 79.92px(1080 폭의 7.4%)임을 확인했다.
- **창 크기:** 1080×1920, 가로 1920×1080, 2160×3840(장치 배율 1)에서 한 사이클을 찍었다. 가로 창에서는 9:16 영역만 꾸며지고 좌우는 검정이다.
  - 대기·결과 화면의 9:16 영역 안 요소 27개를 영역 폭 대비 위치·크기·글자 크기로 비교했다. 글자가 있는 요소는 세 크기에서 **차이 0.05% 이하**다. 차이가 난 것은 글자 없는 요소의 상속 기본 글자 크기(16px)뿐이다.
  - 2160×3840은 스크린숏이 느려 쿨타임 장면을 놓쳤다(앞 장면들은 확인).
- **흑백 모의:** 효과 캔버스에 `grayscale(1) contrast(6) brightness(2.2)`(검은 바탕)와 여기에 `invert(1)`(흰 바탕)을 임시로 걸어 찍었다. 두 바탕에서 모든 글자가 읽히고, 흰 바탕에서도 인식 빛(굵은 금선과 크림빛)이 보였다. 이것도 **모의**다.

### 실제 OBS 카메라 (성능, 이미지 저장 없음)

임시 프로필 headless Chrome, 저장소 밖 임시 스크립트. 변경 전 코드는 `git archive 76367be`로 저장소 밖에 풀어 같은 스크립트로 번갈아 쟀다. 화면 앞에 사람 1명이 인정 상태(`PRESENT`)였다. D 화면은 숫자를 읽을 때만 잠깐 켰다.

| 구간 | 변경 전 (`76367be`) | 변경 후 |
|---|---|---|
| 열자마자 15초 (자동 회차의 결과·쿨타임) | 59.9fps, 최대 33.3ms, 25ms 넘는 간격 1 (3회 모두) | 59.9~60fps, 최대 17~33.4ms, 0~2 (4회) |
| `P`로 멈춘 대기 10초 (대기 안내·인식 빛 보임) | 60fps, 최대 16.9~17ms, 0 (2회) | 60fps, 최대 16.9ms, 0 (2회) |
| 감지 | 14~16fps | 14~16fps |
| 효과 초당 그림 | 23~25장 | 23~24장 |
| 효과 그리기 CPU (평균) | 7.0~9.1ms | 6.9~7.7ms |
| 결과 효과 렌더 | 15.9~19.8ms | 15.4~20.0ms |
| 긴 작업 (50ms 이상) | 0 | 0 |

- 효과 CPU는 측정 때마다 흔들렸다(변경 전 첫 측정 8.3~9.1ms, 나중 측정 7.0~7.3ms). 다른 작업 에이전트가 같은 PC에서 동시에 작업 중이었을 수 있다.
- **촬영 순간 끊김:** `P`를 켜고 `S`를 4~6번 눌러, 25ms 넘는 화면 갱신 간격이 언제 생기는지 셔터(카운트다운 숨김) 시각과 비교했다.

| 코드 | 사이클 | 33ms 간격 |
|---|---|---|
| 변경 전 | 4 + 4 + 6 = 14 | 3 + 0 + 2 = **5** (사이클당 0.36) |
| 변경 후, `decoding` 없음 | 4 | **6** (두 사이클에서 연속 2개) |
| 변경 후, `decoding="async"` | 4 + 4 + 4 + 6 + 6 = 24 | 2 + 3 + 2 + 4 + 3 = **14** (사이클당 0.58) |
| 위 + 결과 바탕·카드 그림자를 단색·없음으로 (측정 전용 CSSOM) | 6 | **4** |

  - 모두 셔터 ±20ms 안의 33ms(화면 갱신 한 번 놓침)다. 그보다 긴 간격은 없다. 변경 전에도 같은 자리에서 생긴다(결과 효과 렌더가 메인 스레드 동기 15~20ms, 로그 03 "남은 문제").
  - 결과 화면 그리기를 단순하게 해도 줄지 않아, 남은 차이는 결과 화면 비용보다 셔터 순간 처리의 흔들림으로 판단한다. 표본이 작아 단정하지 않는다. 연속 2개는 `decoding="async"` 뒤에는 6사이클 중 1번이다.
  - 셔터 순간은 플래시가 화면을 덮는 때다.
- **인식 표시 (실제 사람, DOM만 읽음):**
  - 자동 회차가 돌며 카운트다운·쿨타임 동안 `#stage.is-present`가 켜지고, 결과 중에는 꺼졌다. 쿨타임 문구, 카운트다운 숫자 3·2·1과 안내, 쿨타임 뒤 자동으로 다음 회차가 시작됐다.
  - `P`로 멈춘 대기에서 대기 안내가 보이고 빛이 켜져 있었다.
  - `showPresenceIndicator: false`(설정 파일 응답만 CDP로 바꿔 보냄, 저장소 파일은 그대로)에서는 사람이 인정 상태여도 빛이 없고 대기 안내만 보였다.

### 정리

- 확인 도구와 임시 스크립트가 띄운 Chrome·서버를 모두 종료했다. 임시 프로필, 스크린숏, 변경 전 코드 사본, 임시 스크립트 폴더를 지웠다. 저장소 루트 `config/`·`logs/`는 없다. 사용자 OBS·Chrome은 그대로다.
- 정리할 때 다른 작업 에이전트(`stage6-thermal-bw` worktree)의 확인 도구 Chrome·서버(04:15 시작)가 돌고 있어 건드리지 않았다. 위 성능 측정 시간대에도 그쪽이 같은 PC·OBS를 썼는지는 확인하지 못했다. 효과 CPU 시간이 측정마다 흔들린 원인일 수 있다.

### 미검증

- 실제 흑백 감열지 효과(6-1)를 입힌 미리보기·결과 위의 화면. 흑백 필터 모의로만 봤다.

- 결과 "출력 중" 문구는 인쇄가 없어 화면에 나오지 않는다(Node 테스트로만 확인).
- 현장 PC 성능. 특히 촬영 순간 끊김 빈도.

## 남은 문제

- 촬영 순간 33ms 한 프레임 끊김 빈도가 변경 전보다 조금 높게 측정됐다(사이클당 0.36 → 0.58, 표본 작음). 원인인 결과 효과 동기 렌더는 로그 03의 남은 문제와 같다.
- 6-1(흑백 효과)과 합칠 때 `main.js`·`index.html`·`style.css`가 겹칠 수 있다. 이 작업은 `main.js`의 관람객 화면 부분과 `index.html` 9:16 영역 안, `style.css` 앞부분만 고쳤다.
- 카운트다운 원판 위치(높이 약 52%)·크기, 리본 크기, 결과 카드 기울기는 현장 카메라 높이·화면 크기를 보고 다시 정해야 할 수 있다.
- ThrowSnow 서체·종이 결이 바뀌면 다시 복사해야 같은 모양이 된다.

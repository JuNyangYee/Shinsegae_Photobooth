## 2. 운영자 화면 디자인

### 방향과 구조

- 관람객 화면과 같은 서체·색(고운바탕·고운돋움, 크림·딥 레드·골드·솔잎). 반투명 어두운 패널 대신 **크림 종이 카드**(종이 결, 금선 테두리) 위 딥 레드 제목. 숫자는 고정폭·오른쪽 정렬. 움직임은 없다(미리보기 성능).
- 표현은 `ui/`에 두었다: `ui/dev-panel.js`(D 표), `ui/save-state.js`(저장 상태). 판정·저장 규칙은 그대로 `effect-tuning.js`·`presence-tuning.js`가 갖는다.
- 크기: 9:16 영역 밖 패널은 글자 크기 하나(`clamp(13px, 1.45vmin, 34px)`)에 `em`으로 맞췄다. 6-2의 해상도 독립 원칙(px 상한 없이 비율 유지)을 따르되, 운영 도구라 아주 작은 창에서 읽히도록 하한만 두었다. 9:16 영역 안(`P` 표시·편집 사각형)은 `cqw`.

### 조절 패널 `R`·`E`

- **묶음:** `E` = 효과 / 출력 단계 / 미리보기. `R` = 영역 / 얼굴 크기 / 신뢰도 / 고급(접힘) / JSON(접힘). 지시의 예대로다. 초당 그림은 "미리보기"에 넣었다(느릴 때 먼저 낮추는 값이라 처리 해상도와 함께 둔다).
- **줄:** [이름 + 한 줄 도움말] [슬라이더·선택] [값 + 단위]. 단위는 세기·배·비율·거리·장/초·±·γ·점수, ms는 값에 이미 붙어 있다.
- **저장 상태:** 패널 `data-save` + 칩. 저장됨(초록)·저장 안 된 변경(주황, 닫으면 취소)·저장 중·저장 실패(빨강, 파일에는 이전 값). 실패는 값을 다시 바꾸거나 저장에 성공하면 풀린다. 예전 글자("저장된 값과 같습니다" 등)를 이 네 가지로 바꿨다. 저장 버튼은 주 버튼(딥 레드)이고 저장할 것이 없으면 차분한 모양이다(누를 수는 있음, 동작 그대로).
- 머리에 제목·키 안내·`위·아래`·`닫기`, 아래(늘 보임)에 상태·저장·취소·기본값·알림. 몸통만 넘긴다.
- **얼굴을 가리지 않게:**
  - 세로 화면: 기존 `위·아래` 기능을 그대로 두고 높이를 화면의 절반(`50vh`)까지로 줄였다. 기본 아래라 9:16 영역 위쪽 절반(얼굴 자리)을 가리지 않는다.
  - 가로 화면: 9:16 영역 옆 빈 곳에 세운다(기본 오른쪽, `위·아래`면 왼쪽). 1920×1080에서 패널 625px, 영역 608px로 겹치지 않음을 확인했다.
- `R` 영역 줄의 글자를 값만(`x 0.100 · y 0.100 · 폭 0.800 · 높이 0.800`)으로 줄이고, 끄는 방법은 도움말로 옮겼다.
- 선택자(`#effect-panel`·`#tuning-panel`, `[data-key]`, `button[data-action]`, `[data-live]`·`[data-state]`·`[data-message]`·`[data-json]`·`[data-region-text]`)는 그대로라 확인 도구·테스트는 고치지 않았다.

### 개발 정보 `D`

- `<pre>`를 `<section id="dev-info">`로 바꾸고 구역(카메라·인식·효과 · 출력·촬영)별 표로 그린다. 정보 내용은 그대로다(`main.js`가 줄을 만들고, 줄을 구역 넷으로 나눠 넘길 뿐).
- **`textContent`는 예전 글자와 같다**(줄 `\n`, 구역 사이 빈 줄). 확인 도구가 이 글자를 줄 머리말로 읽기 때문이다. 구역 제목은 `data-title` + CSS `::before`라 글자에 들어가지 않는다. Node 테스트와 확인 도구(두 모드 14/14)로 확인했다.
- 상태 색: 정상(초록 글자·왼쪽 선), 주의(주황 바탕), 오류(빨강 바탕). 줄 머리말별 규칙(`devLineTone`)이다.
- 가로 화면에서는 9:16 영역 왼쪽 빈 곳에 맞춘다.

### `P` 표시

- 9:16 영역 오른쪽 위의 작은 크림 종이 알약(딥 레드 글자, 금선, 일시정지 기호). 글자 크기를 영역 폭의 2.1% → **1.7%** 로 줄였다(1080 폭에서 약 18px). 처음 크기는 캡처에서 관람객 눈에 띄었다. 문구는 그대로다.

### 편집 영역·겹쳐 그리기

- 편집 사각형: 노란 3px 선 → 금빛 선에 안팎 어두운 테두리(흑백 점 위에서도 보이게), "인식 영역" 알약, 핸들은 28px 노란 사각 → 크림 원(딥 레드 테두리, 영역 폭의 3.4%).

## 6단계 단위 검수 (GPT-6.1-Sol xhigh)

의견 "수정 후 병합 가능", 높음 등급 없음. 감열지 출력 정확성(GPU·CPU 비트 일치, 인쇄 데이터 형식), 결과 수명, 대체 경로, CSP, 라이선스, 폴더 규칙은 문제없다고 확인됐다. 오케스트레이터가 1·2·4를 채택하고 3을 보류했다.

### 수정 내용

- **1 저장 상태:** 바꾸지 않았을 때의 상태를 시작할 때 불러온 결과로 정한다(`loadedSaveState`). 문구는 가안이다.
  - 파일에서 읽음(고친 것 없음)·브라우저 저장값을 파일로 옮김·이번 실행에 저장 → `saved` "저장됨 · 파일과 같은 값입니다"
  - 파일 없음(`no file`) → `defaults` "기본값 사용 · 저장된 파일 없음"
  - 읽기 실패·시간 초과·형식 오류 → `load-failed` "불러오기 실패 · 기본값 사용"
  - 범위·없는 키를 고쳐 씀, 또는 브라우저 저장값을 파일로 옮기지 못함 → `adjusted` "파일 값을 고쳐 사용 · 저장 필요"
  - 바꾸는 중의 `dirty`·`saving`·`failed`는 그대로 앞선다. 값을 바꿨다가 불러온 값으로 돌아오면 불러온 상태로 돌아간다. 저장에 성공하면 `saved`.
  - 저장·되돌리기·닫기 규칙은 바꾸지 않았다.
- **2 배치·`D`:**
  - 옆 배치는 화면 비율(`min-aspect-ratio: 1/1`)이 아니라 **실제 남는 폭**으로 정한다. `main.js` `updateOperatorRoom`이 처음과 창 크기가 바뀔 때마다 9:16 영역 옆 빈 폭을 재서, 패널 최소 폭과 여백(26em, 패널 글자 크기 기준)이 들어가면 루트에 `.op-side-room`을 붙인다. CSS 미디어 쿼리는 `em`·`vmin` 기준 패널 폭과 남는 폭을 비교할 수 없어 JS로 쟀다.
  - `D`는 화면보다 길면 세로로 넘긴다(`overflow-y: auto`, 휠). 그래서 `D`가 마우스를 받는다. `R` 조절 화면이 열려 있는 동안만 영역·핸들 끌기를 막지 않게 마우스를 통과시킨다(그동안은 넘기지 못한다). `textContent`는 그대로라 확인 도구는 바꾸지 않았다.
- **4 문서:** SYSTEM 6절 "출력 단계"를 실제 형식으로 고쳤다. `RGBA8` (Pw/4)×Ph에 가로 4점씩(0 또는 255), 줄은 GL 방향(아래 줄부터). GPU 디더 결과(`bits`)와 같은 형식이라 표시 셰이더 하나가 둘 다 읽는다.
- **3 (보류):** 검수자가 제안한 예열을 한 번 시험했다. 시작 뒤 카운트다운(원판·숫자·안내 알약)을 투명도 0.01로 1.5초 실제로 보였다가 숨긴 뒤 첫 `S`를 눌렀다(가짜 카메라, long-animation-frame).
  - 예열 없음 149·146ms, 예열 147·150ms. **효과가 없어 코드는 넣지 않았다.** 위 "성능"의 다른 시도(장식 하나씩 빼기 등)도 효과가 없었다.
  - **현장 확인 항목**으로 PROJECT 4단계 "남은 것"에 적었다. 현장 PC에서 하루 첫 회차의 체감을 본다.

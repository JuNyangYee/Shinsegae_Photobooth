## 수정 내용과 결정

### 1. 조절값 파일 복원 (확인 도구)

- 도구가 시작할 때 `config/presence.local.json`을 바이트 그대로 백업한다. 파일이 없으면 "없음"과 폴더가 있었는지를 기억한다(`backupFile`).
- 다음 정리 경로에서 **파일 시스템으로 직접** 되돌린다(`restoreFile`). 서버 API를 거치지 않는다.
  - 조절값 시나리오 직후
  - 마지막 정리(`finally`)
  - Ctrl+C(`SIGINT`)
  - 처리 안 된 예외
- **되돌리는 방법:**
  - 있던 파일: 같은 폴더 임시 파일에 쓰고 rename으로 바꾼 뒤, 바이트가 같은지 확인한다.
  - 없던 파일: 지우고, 도구가 만든 빈 `config/`도 지운다.
  - 여러 번 불러도 된다. 실패하면 결과 표에 실패로 나온다.
- 백업·복원은 테스트하려고 `tools/browser-check-lib.mjs`로 나눴다.

### 2. CDP 끊김과 제한 시간 (확인 도구)

- `createCdpSession`(lib)으로 바꿨다.
  - 요청마다 제한 시간이 있다(기본 15초, 생성 실패 시나리오의 `Runtime.evaluate`는 60초).
  - `onclose`·`onerror`가 오면 기다리던 요청을 모두 실패시키고, 이후 요청은 바로 실패한다.
  - 연결 자체도 10초 안에 열리지 않으면 실패한다.
- 대기 루프(`waitFor`)는 연결이 끊긴 것을 보면 바로 실패한다. 그래서 남은 시나리오가 각자 제한 시간을 기다리지 않는다.
- 어떤 실패에서도 Chrome·서버·프로필 정리는 같은 `cleanup()` 하나로 한다.

### 3. 조절값 요청 본문의 제한 시간

- `settings-file.js`의 요청 함수가 본문까지 읽어서 돌려준다. 제한 시간과 취소 신호는 본문을 다 읽을 때까지 유지된다.
- 본문 읽기가 신호를 무시해도 시간이 되면 `timeout 3000ms`로 끝난다(`Promise.race`).

### 4. 저장 중 닫기

- **고른 방식: 저장 중에 닫기를 요청하면 저장이 끝난 뒤 닫는다.**
  - "저장 중입니다. 저장이 끝나면 닫습니다."를 보인다.
  - 응답(최대 3초)이 오면, 기존 규칙대로 "마지막으로 파일에 저장된 값"으로 맞추면서 닫는다. 성공하면 저장한 값, 실패하면 이전 파일 값이다. 어느 경우든 실행 중인 판정값과 파일 값이 같다.
- **이유:** 닫기를 막기만 하면 운영자가 키를 한 번 더 눌러야 하고, 막힌 줄 모르고 지나갈 수 있다. 저장 중이라는 문구가 보이고 길어야 3초라서 미루는 쪽이 자연스럽다.
- 저장 중에 슬라이더를 더 움직였다면, 그 값은 닫을 때 버리고 파일 값(누른 순간의 값)으로 맞춘다.

### 5. 장시간 실측 통과 조건

다음을 모두 만족해야 통과다.
- 모든 1분 기록에서 카메라 `ready`, 감지기 `health ok`
- `S`를 누르기 직전(대기 상태)마다 사진 자원 0이고 `taken = released`. 4-4 실측에서는 기록 시점이 늘 카운트다운 중이라 이 확인이 비어 있었다. 이제 회차마다 대기 상태에서 본다.
- 측정값을 모두 읽음: 숫자가 아닌 값이나 Chrome 메모리를 못 읽으면 실패
- 외부 요청·CSP 위반(통계 차단 제외)·페이지 예외 0
- 완료 회차 1 이상

### 6. 감지기 생성 실패 정리의 소유자 구분

- **타이머:**
  - 진행 중인 시도가 하나뿐이고, 60초 간격이고, `setInterval`을 부른 바로 위 프레임이 번들 파일(`vision_bundle.mjs`, `?retry=N` 포함)일 때만 그 시도의 것으로 기록한다.
  - 다른 코드가 같은 시간에 만든 60초 타이머는 지우지 않는다.
- **로더 `<script>`:**
  - 첫 시도가 시작될 때 이미 있던 같은 URL의 요소는 기억해 두고 건드리지 않는다.
  - 겹친 시도가 모두 끝난 뒤에만 그 사이 생긴 요소를 지운다. 아직 불러오는 중인 로더 요소를 지우면 그 시도가 멈추기 때문이다.
- **감싼 `setInterval`:** 모듈에 하나만 둔다(겹쳐도 다시 감싸지 않음). 마지막 시도가 끝나면 되돌린다.
- **남는 한계:** 시도가 겹친 동안 생긴 타이머는 누구 것인지 몰라 지우지 않는다. 앱에서는 `detector-keeper`가 생성을 하나씩만 하므로 생기지 않는다.
- **테스트 구성:** 가짜 번들을 `tests/fixtures/fake-vision-bundle.mjs`로 나눴다. 라이브러리 코드를 파일 이름으로 알아보므로, 실제처럼 다른 파일에 있어야 한다.
- **호출 스택에 기대는 이유:** MediaPipe가 실패한 인스턴스를 돌려주지 않아 직접 `close()`할 수 없다. 그래서 그 시도가 만든 타이머라는 것을 알 수 있는 다른 공개 경로가 없다. Chrome의 `Error().stack` 형식에 기대는 점은 SYSTEM 5절에 적었다.

### 7. `Local State` 원자적 쓰기

- `hardware_acceleration_mode.enabled`만 `true`로 바꾼 내용을 같은 폴더 임시 파일(`Local State.<guid>.tmp`)에 쓴다.
- 그 임시 파일을 `JavaScriptSerializer`로 다시 읽어 JSON 객체이고 값이 `true`인지 확인한 뒤, `[IO.File]::Replace($temp, $path, [NullString]::Value)`로 바꾼다.
- 확인에 실패하거나 예외가 나면 원본을 그대로 두고 경고를 남긴다. Chrome 실행은 계속한다. 임시 파일은 항상 지운다.
- 파일은 ASCII·CRLF(297줄, CR 없는 LF 0), PowerShell 5.1 구문 오류 0이다.

### 8. 결과 사진 표시

- `S` 사이클의 결과 상태에서 다음을 확인한다.
  - 결과 `<img>`: 숨김 아님, `display` 있음, 화면 크기 0 아님, `blob:` 주소
  - 디코딩 완료 뒤 `naturalWidth`·`naturalHeight`가 D `capture` 줄의 캡처 크기와 같음
- 가짜 카메라 결과는 이미지 1215×2160, 화면 1080×1920 CSS px였다.

### 정리

- 도구가 띄운 Chrome·서버·임시 프로필: 매 실행 뒤 0. 확인할 때는 자기 자신의 검사 명령을 빼고 셌다. 한 번은 검사 명령줄 자신이 잡혀 1로 보였다.
- 실행 스크립트 확인의 임시 프로필, 저장소 `logs/`(원래 없던 폴더), `%TEMP%`의 확인·편집 스크립트를 지웠다.
- 조절값 파일: 이 작업 전 상태(없음)로 되돌렸다. `config/` 없음.

## 남은 문제

- 감지기 생성 실패 정리는 Chrome `Error().stack` 형식(바로 위 프레임의 파일 이름)과 MediaPipe 1.1.1 내부 동작(60초 통계 타이머)에 기댄다. 버전을 올리면 다시 확인한다. 확인 도구의 생성 실패 시나리오가 그 확인을 맡는다.
- 시도가 겹친 동안 생긴 통계 타이머는 지우지 않는다(앱에서는 생기지 않음).
- 확인 도구는 D 화면 줄 형식에 기댄다(로그 13).

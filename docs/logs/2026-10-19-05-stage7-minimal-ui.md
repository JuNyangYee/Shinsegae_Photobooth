## 결정과 이유

### 숫자는 화면을 가리지 않는다

- 관람객 화면의 모든 글자·숫자를 **9:16 영역 아래 15%(26.67cqw) 안**에 넣었다. 지시의 "위아래 15%를 뺀 가운데 영역"을 기준으로 삼았다. 숫자를 아래에 두면 안내 한 줄과 진행선이 한 묶음이 되어 시선이 한 곳에 모인다. 위쪽은 비워 두었다.
- 숫자는 9.6cqw다. 9.6 + 진행선 여백 + 안내 줄 + 아래 여백 6.4cqw가 25.4cqw라 15% 안에 들어간다.
- **읽히게 하는 방법:** 불투명한 판 대신 아래 18%의 그라데이션 띠(아래 0.62 → 위 0)와 글자 그림자를 썼다. 띠는 대기 안내·카운트다운·쿨타임 문구가 보일 때만 켠다(`:has`, 투명도 전환). 띠 위끝 3%(영역 82~85%)는 투명도 0~0.12라 가운데를 덮는다고 보지 않았다.
  - 처음 띠(숫자 높이에서 0.25~0.05)는 흰 바탕 모의에서 숫자가 약했다. 숫자 높이에서 0.48~0.22가 되도록 진하게 하고 숫자 그림자를 키웠다(`19b2cf0`). 가짜 카메라의 흑백 점 위에서는 처음 값도 읽혔다.
- 밝은 흑백 미리보기에는 오프화이트 글자 + 어두운 띠, 어두운 미리보기에는 띠가 거의 보이지 않아 글자만 남는다. 반대(어두운 글자 + 밝은 띠)는 검은 점이 많은 장면에서 안개처럼 보일 것이라 고르지 않았다.

### 가는 선 프레임과 인식 표시

- 테두리는 1080 폭에서 1px 밝은 선 + 바깥 1px 어두운 선 한 겹이다. 흰 종이 바탕에서도 검은 점 바탕에서도 보이게 하려고 두 겹으로 했다. 장식 대신 "갤러리 액자의 매트 선" 정도로 둔다.
- 인식 표시는 이 선의 투명도만 바꾼다(0.3 → 0.95). 지시의 "가는 선의 밝기 변화"다. 하단 글자 변화는 쓰지 않았다. 자동 시작이 인식되는 순간 카운트다운을 시작하므로 대기 안내가 바뀐 채로 보이는 시간이 거의 없다(6-2와 같은 이유).
- 결과 화면에서는 선을 숨긴다. 결과는 벽 위 출력물 한 장이라 둘레 선이 필요 없다.

### 결과 화면

- 6-3의 "사진 폭을 인쇄 점과 화면 화소 1:1로" 결정(폭 53.333cqw = 576/1080, 회전 없음)을 그대로 두었다.
- 더해서 **1080 폭에서 카드 왼쪽·위 끝이 정수 화소**에 놓이게 여백·테두리를 정했다: 여백 2.2222cqw(24px), 테두리 0.0926cqw(1px), 카드 626px → 왼쪽 227px, 사진 왼쪽 252px. 세로는 아래 여백 7.4074cqw(80px)로 카드 위 383px, 사진 위 408px. 측정에서 사진 `x 252.000`, 폭 575.984px(=576)였다. 소수 위치면 화면에 그릴 때 다시 보간될 수 있어서다.
- 나타나는 움직임은 아래에서 1.6cqw 떠오르는 0.6초 페이드다. 회전·확대는 쓰지 않는다(Node 테스트가 확인). 6-2의 "위에서 내려와 놓임"은 장식적이라 뺐다.
- 진행선·안내는 카운트다운과 같은 자리·같은 폭이다. 상태가 바뀌어도 안내가 늘 같은 곳에 나온다.

### 서체

- **Pretendard(본문), Noto Serif KR Light(숫자·준비 중 제목).** 둘 다 SIL OFL 1.1이고 공식 배포처에서 받았다. 버전·출처·크기는 SYSTEM 3절 "관람객 화면 → 서체".
- Pretendard는 공식 배포본에 있는 부분 집합 woff2(한글 2,780자)를 **바이트 그대로** 넣었다. 다시 줄이지 않은 이유: 운영자 패널·`D`·확인 도구 문구까지 한글 569자를 쓰는데 공식 부분 집합이 모두 담고 있었고(확인함), 공식 파일을 그대로 두면 출처 확인이 쉽다. 두 굵기 합 535KB.
- Noto Serif KR은 원본 OTF가 7.8MB라 `fontTools` `pyftsubset`으로 `guest-text.js` 문구 글자(한글 52자)와 영숫자·문장 부호만 남겼다(30,988바이트). 세리프는 확정 문구("준비 중입니다.")와 숫자에만 쓰여 문구가 바뀔 일이 적다. 그래도 문구를 바꾸면 빠질 수 있어 Node 테스트(`test/config/guest-text.test.mjs`)가 WOFF `cmap`을 읽어 검사한다. 줄이는 스크립트는 저장소에 넣지 않았다(빌드 도구를 들이지 않는 원칙). 명령은 SYSTEM에 적었다.
  - Light를 고른 이유: 숫자를 작게 쓰므로 획이 가는 쪽이 더 정돈돼 보였다. 흰 바탕 모의·흑백 점 위에서 읽힘을 확인했다.
  - woff2로 만들려면 `brotli` 모듈이 필요한데 개발 PC에 없어서 woff(zlib)로 만들었다. 31KB라 차이가 작다.
- 서체 합계 566KB로 6-2(680KB)보다 작다.

### 문구

- "특별한 사진이 완성됐어요"(결과 제목)와 "잠시 후 처음 화면으로 돌아가요"는 지웠다. 결과 화면은 안내 한 줄과 진행선만 둔다는 지시에 따랐다. 진행선이 돌아가는 시간을 보여 준다.
- 결과 출력 중 "사진이 출력되고 있어요" → "사진을 출력하고 있습니다", 쿨타임 "다음 촬영을 준비하고 있어요" → "다음 촬영을 준비하고 있습니다". 확정 문구("준비 중입니다.")와 같은 합쇼체로 맞춰 담백하게 했다. 나머지("발자국 위에 서 주세요", "화면을 보며 웃어 주세요", "출력된 사진을 받아 가세요")는 유아적이지 않다고 보고 두었다. 모두 가안.

### 크리스마스 표현

- 넣지 않았다. 지시가 "정말 필요하면 아주 은은하게만"이고, 사용자가 요소가 많다고 한 상태라 먼저 빼고 확인받기로 했다(아래 "질문").

### 운영자 화면

- 차콜 반투명(`rgba(22,22,22,0.965)`). 처음 0.94에서는 세로 화면 아래쪽 대기 안내 글자가 패널 뒤로 비쳐 올렸다. 블러(`backdrop-filter`)는 미리보기 성능 때문에 쓰지 않았다.
- 상태 색은 채도를 낮춘 초록·호박·빨강을 작은 점·글자·왼쪽 선에만 쓴다. 저장 상태 칩의 바탕색을 없앴다. 주 버튼만 오프화이트라 패널에서 강조는 하나다.
- `color-scheme: dark`로 선택 상자 목록과 넘김 막대를 어둡게 했다.
- 구조·마크업·선택자는 6-3 그대로라 확인 도구·테스트의 운영자 시나리오는 고치지 않았다. `R` 도움말의 "금빛·청록·분홍" 색 이름만 바꿨다.
- 겹쳐 그리기 색: 영역 금빛 → 오프화이트, 최소 가이드 청록 → 파랑(`#8fb6d6`), 최대 분홍 → 붉은색(`#e0a39a`). 둘은 서로 구별되어야 해서 무채색으로 하지 않았다.

### 성능

- 움직임은 `transform`·`opacity`만 쓴다. 늘 도는 애니메이션은 준비 중 가는 선 하나다(6-2의 안내 알약 떠오름, 별 반짝임, 방울 흔들림은 없앴다). 그림자 블러는 글자 `text-shadow`뿐이고 움직이는 큰 그림자는 없다.

## 남은 문제

- 7-1과 합칠 때 `index.html`·`style.css`·`main.js`가 겹칠 수 있다. 이 작업은 `index.html`의 9:16 영역 안·`R` 패널 도움말 두 줄·서체 미리 받기, `style.css` 전체(공용 운영자 스타일 포함), `main.js`의 `OVERLAY`·주석 두 줄만 고쳤다. `E` 패널 마크업은 그대로다. 7-1이 `E`에 새 줄을 더해도 같은 `.op-row` 구조면 스타일이 그대로 적용된다.
- 세리프 부분 집합은 문구에 묶여 있다. 문구를 바꾸면 Node 테스트가 알려 주고, 다시 줄여야 한다.
- 숫자 크기(9.6cqw), 띠 진하기, 가는 선 투명도는 현장 화면·거리에서 다시 정할 수 있다(가안).
- 6단계 남은 문제(실제 프린터 출력, 결과 화면용 PNG 크기, 촬영 순간 33ms 한 프레임)는 그대로다.

## 결정과 이유

- **모듈 셋으로 나눔:**
  - 감지기(MediaPipe를 아는 유일한 곳), 판정(브라우저 없이 테스트할 수 있는 순수 함수), 루프(타이머·카메라·페이지 상태)로 나눴다.
  - 좌표·점수는 루프 안에 머물고, 밖으로는 `{ present }`만 알린다.
  - D 화면용 `getDebugSnapshot()`은 이름과 주석으로 용도를 한정했다.
- **판정은 화면 좌표로:**
  - 영역은 관람객이 보는 9:16 화면(반전 후) 기준으로 정한다. 그래서 2-3에서 운영자가 화면 위에 그리는 영역과 그대로 맞는다.
  - 최소 얼굴 크기는 9:16 영역 높이 대비 박스 높이다. 지시대로 높이 하나만 쓴다. 9:16 화면에서 폭 기준을 쓰면 같은 얼굴도 값이 약 1.8배가 되어 운영자가 헷갈릴 수 있다.
- **감지기 신뢰도는 낮게(0.3), 판정 신뢰도는 0.6:** 지시대로 감지기를 다시 만들지 않고 조절할 수 있게 했다.
- **안정화는 감지 프레임이 들어올 때만 판정한다:**
  - 타이머 없이 `(state, raw, now, timing)` → `state` 순수 함수로 두어 Node에서 시간 경계를 정확히 테스트할 수 있다.
  - 대가로 전환이 최대 한 감지 간격(15fps면 약 67ms) 늦다.
- **루프는 `setTimeout`으로 돈다:**
  - `requestVideoFrameCallback`은 카메라 감시 모듈이 이미 같은 `<video>`에 걸어 쓰고 있다. 재연결 때 `srcObject`가 바뀌면 콜백이 남는지도 불확실하다.
  - 간격은 `1000 / maxFps`에서 처리 시간을 뺀 값이다.
- **입력은 프레임 전체를 축소:**
  - 보이는 9:16 부분만 잘라 넣으면 가로 영상에서 해상도 면에서 유리하다. 하지만 현장 입력(OBS 9:16)에서는 차이가 없어 단순한 쪽을 택했다.
  - 긴 변 640px이다. 모델(short-range)은 내부에서 128×128로 줄이므로 더 키워도 이득이 작다고 판단했다.
- **감지 실패 처리(작업 중 추가):**
  - 검증 중, WebGL을 쓸 수 없으면 CPU delegate도 생성은 되지만 매 프레임 `detectForVideo`가 실패하는 것을 발견했다. 상태는 `running`인 채 콘솔에 초당 약 15건 경고가 쌓였다.
  - 또 이전 판정이 남아 인식됨이 풀리지 않을 수 있었다.
  - 그래서 실패한 프레임은 "없음"으로 판정하게 했다. 15번 연속 실패하면 `error`로 표시하고 1초 간격으로 다시 시도한다. 경고는 연속 실패의 처음과 `error` 진입 때만 남긴다.
- **CSP:**
  - 정책은 `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`이다.
  - `wasm-unsafe-eval`은 MediaPipe WASM 컴파일에 필요하다. `unsafe-eval`·`unsafe-inline`·`blob:`·`worker-src`는 넣지 않았고, 아래 검증에서 텔레메트리 외 위반은 0건이었다.
  - meta CSP는 `frame-ancestors`를 지원하지 않지만 이 앱에는 필요 없다.
- **인식 표시는 카메라 준비 중에는 숨긴다:** "준비 중" 문구와 겹치지 않게 하기 위해서다.
- **`node --test` glob:** Node 24에서는 디렉터리 인자(`tests/`)가 동작하지 않아(`MODULE_NOT_FOUND`) glob(`"tests/**/*.test.mjs"`)을 쓴다. glob 인자는 Node 21부터 지원하므로 테스트 요구 버전은 Node 22 이상으로 적었다.

## 남은 문제

- **WebGL이 없으면 감지할 수 없다.** CPU delegate도 입력을 WebGL로 처리한다. 현장 Chrome은 하드웨어 가속(WebGL)이 켜져 있어야 한다. 4단계 실행 스크립트·현장 점검 항목에 넣어야 한다. 지금은 `D` 화면에 `error`로만 보인다.
- **감지기를 다시 만들지 않는다.** WebGL 컨텍스트 손실 등으로 감지가 계속 실패하면 1초 간격 재시도만 하고 감지기를 새로 만들지는 않는다. 4단계 안정화에서 다룬다.
- **기본값 근거 부족:** 가짜 카메라 오검출 중 점수 0.6을 넘는 것이 있었다(최고 0.663, 영역으로 걸러짐). 실제 얼굴은 0.95였다. `minScore`를 0.7로 올리거나 최대 얼굴 크기 조건을 둘지는 실측 후 정하는 것이 좋다(질문).
- 인식됨 상태에서 페이지 숨김은 같은 해제 경로(`pause()`)를 트랙 종료로 확인했다. 숨김 자체로는 인식됨 상태에서 재현하지 못했다(랜덤 오검출이 그 시점에 인식됨까지 이어지지 않음).
- 실제 Chrome 백그라운드 탭 전환으로 `document.hidden`이 바뀌는 경우는 흉내만 냈다.
- 시작할 때 0.7~1.0초짜리 긴 작업이 한 번 생긴다. 미리보기 시작 직후라 눈에 띄지 않을 수 있지만, 현장 PC에서 확인이 필요하다.
- 1단계 로그 03의 "사용자 실측 필요" 시나리오는 여전히 미실측이다.

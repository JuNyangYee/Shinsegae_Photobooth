# 2026-10-26-02 — 좌우 반전을 운영자 설정으로

브랜치 `task-mirror-toggle`(`master` `3e3d537`에서 분기). 작업 에이전트(Opus 5.5). 병합·push는 오케스트레이터가 한다.
같은 때 브랜치 `task-saved-defaults-2`가 `config.effect`의 효과 기본값(strength·size·refine·brightness·contrast·gamma)과 관련 테스트·문서를 바꾸고 있어, 그 값들은 건드리지 않았다.

## 요청 (2026-10-26, 사용자)

> "카메라 설정에 좌우 반전 기능도 추가해서 같이 병합·푸쉬해 줘"

좌우 반전은 `config.mirror = true` 상수로 고정돼 있었다(1단계 확정: 미리보기와 결과 모두 반전, 반전은 웹 한 곳에서만). 현장 카메라 배치·OBS 설정에 따라 반전이 필요 없을 수 있어, 운영자가 켜고 끌 수 있는 설정으로 바꾼다. 기본값은 지금처럼 켬.

## 결정과 이유

|---|---|---|

| 예전 파일 | `mirror` 키가 없으면 켬으로 채우고 **알리지 않는다**(`adjusted`·"저장 필요"가 뜨지 않음) | 키가 없는 파일은 반전이 늘 켜져 있던 때 저장한 것이라 기본값(켬)이 그 파일의 뜻과 같다. 현장 파일이 업데이트만으로 "고쳐 씀"으로 보이지 않게. `mirror`가 참·거짓이 아니면 켬으로 바꾸고 알린다 |
| 바꾸는 순간: 미리보기 | 효과 미리보기는 다음 화면 갱신에 새로 그리고, `<video>` CSS(`is-mirrored`)와 인식 좌표는 효과 설정이 바뀌는 즉시(`main.js` `applyMirror()`) | 반전은 경로마다 한 번: 효과는 입력 uv, `<video>`는 CSS, 캡처는 캔버스, 인식은 좌표 변환. 이중 반전·누락 없음 |
| 바꾸는 순간: 인식 | 인식 상태를 처음부터 다시 잰다(`presence-monitor.js` `setMirror()`, 판정 기준 변경과 같은 처리, D `criteria resets` +1, 얼굴 박스도 지움) | 인식 영역은 관람객 화면 기준이라 반전이 바뀌면 같은 얼굴이 영역 반대쪽에 온다. 이전 좌표로 안정된 "인식됨"이 남아 자동 시작되지 않게 |
| 바꾸는 순간: 카운트다운 | 인식으로 시작한 카운트다운은 위 재측정으로 "떠남" 취소(`left during countdown`). `E`가 열려 있는 동안은 다시 시작하지 않는다(기존 규칙). `S` 수동 카운트다운은 그대로 이어지고 셔터 순간 값으로 찍는다 | 기존 자동 시작 규칙을 바꾸지 않고 결과가 정해진다. 수동 회차는 인식으로 취소하지 않는 규칙 그대로 |
| 바꾸는 순간: 결과 화면 | 이미 보이는 결과 사진은 다시 만들지 않는다 | 그 셔터 순간의 값으로 만든 사진이다 |
| 셔터 순간 값 | 캡처는 `getMirror()`로 프레임을 잡는 순간 읽고, `renderStill`은 마지막 그림 뒤 반전이 바뀌었으면(다음 화면 갱신 전, 길어야 한 화면 갱신) 그 그림을 쓰지 않고 지금 프레임·지금 설정으로 그린다(D `new drawing`) | 결과 = 셔터 순간 미리보기 규칙을 지키면서, 효과 결과와 원본 대체 사진(효과 장애 때)이 같은 순간의 값을 읽어 방향이 어긋나지 않는다. 캡처와 `renderStill`은 같은 작업 안에서 이어져 그 사이에 값이 바뀔 수 없다 |

### 브라우저 확인 시나리오 (좌우 반전)

`E`를 열고: 켬(기본) 상태 확인 → `S` 한 장 → 끔 → 상태 확인·`criteria resets` +1·얼굴 위치 → `S` 한 장 → 저장 → 새로고침(끔 유지, 파일 `mirror: false`) → 켬(저장 없이) 확인 → 닫으면 끔으로 되돌아감. 끝나면 조절값 파일을 원래대로.

- **방향 측정:** 페이지 안에서 효과 그림(새로 그린 화면 갱신마다)과 같은 순간의 `<video>` 프레임(보이는 9:16, 반전 전), 결과 사진을 18×32 밝기 격자로 줄여 비교한다(이미지를 저장하지 않음). 판정은 **비대칭 성분의 상관**(`anti`, 각 격자에서 자기 좌우 뒤집음을 뺀 것끼리의 피어슨 상관): 같은 방향 +, 거울 방향 −, 기준 ±0.3(가안).
- 처음에 쓴 "그대로 상관 − 뒤집음 상관" 여유 판정은 가짜 카메라에서 갈리지 않았다(결과 ↔ 영상 0.863 / 0.890). 가짜 카메라 화면이 거의 좌우 대칭이라서다.
- 고친 확인 도구 문제 둘: (1) "이번 화면 갱신에 새로 그렸나"를 가운데 화소 알파로 보면 알파가 늘 255라 지워진 검은 버퍼를 읽어 상관이 0이 됐다 → `EFFECT_READER`와 같은 가운데 8×8 RGB 합으로. (2) 셔터 순간에 영상을 새로 읽으면 셔터 그림과 다른 프레임이라 움직이는 가짜 카메라에서 상관이 0.3까지 떨어졌다 → 셔터 그림과 같은 순간에 읽은 영상을 짝으로 남긴다.

### 미검증

- 실제 OBS에서 **효과를 쓸 수 없을 때(원본 미리보기)의 반전 끔 화면**은 눈으로 보지 않았다. `<video>` CSS(`is-mirrored`·`transform`)가 바뀌는 것은 브라우저 확인에서, 원본 대체 사진의 캡처 반전은 Node 테스트에서 확인했다.
- D 겹쳐 그리기의 박스 위치는 판정 좌표 그대로 그리므로(코드 변경 없음) 좌표 변화(0.42 → 0.58)로 대신했고, 화면에 그려진 박스를 눈으로 보지는 않았다.
- 인쇄용 1비트 데이터의 방향은 결과 그림에서 만들므로 결과 방향으로 대신했고 따로 재지 않았다.
- 현장 카메라 배치에서 켤지 끌지는 현장 확인 항목(PROJECT 5절).

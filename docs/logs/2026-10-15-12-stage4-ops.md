## 결정과 이유

### 서버 API

- **정확한 URL 하나만 받는다.** `RawUrl`을 대소문자까지 그대로 비교한다. 쿼리, 끝 `/`, 퍼센트 인코딩 변형, 그 밖의 `/local-api/*`는 모두 404다. 파일 경로는 서버 상수뿐이라 클라이언트가 정할 여지가 없다.
- **CSRF 방어:**
  - `PUT`은 다음을 모두 만족할 때만 받는다: `X-Photobooth: 1`, `Content-Type: application/json`(`charset`이 있으면 `utf-8`만), `Host == localhost:<port>`, `Origin`이 있으면 같은 출처, `Sec-Fetch-Site`가 있으면 `same-origin`.
  - CORS 허용 헤더는 어떤 응답에도 보내지 않는다. `OPTIONS`는 405다.
  - `Sec-Fetch-Site` 확인은 지시에 없던 것을 더했다. 같은 출처가 아닌 브라우저 요청을 한 번 더 거르기 위해서다.
- **`Origin`이 없는 요청은 받는다.** 브라우저가 아닌 같은 PC 프로그램의 요청이다. 이런 프로그램은 파일을 직접 쓸 수도 있으므로 막을 이유가 없다.
- **값의 의미는 검사하지 않는다(지시대로).**
  - 서버는 `JavaScriptSerializer`로 JSON 객체인지만 본다.
  - 이 파서는 표준보다 너그러울 수 있어, 서버를 통과해도 브라우저 `JSON.parse`가 실패하는 내용이 저장될 수 있다. 그래도 클라이언트가 기본값으로 안전하게 불러오므로 그대로 두었다.
  - 저장은 받은 바이트 그대로다. 그래서 `GET`이 `PUT` 본문과 바이트 단위로 같다.
- **원자적 쓰기:**
  - 같은 폴더 임시 파일에 쓰고, `Flush(true)`로 디스크까지 내린 뒤 `File.Replace`(처음이면 `File.Move`)로 바꾼다.
  - 다른 프로세스가 잡고 있으면 50ms 간격으로 5번까지 다시 시도한다.
  - 서버는 요청을 하나씩 처리하므로 한 서버 안의 동시 `PUT`은 차례대로 처리된다. 같은 저장소를 가리키는 서버가 둘(다른 포트) 떠도 파일이 깨지지 않는 것을 따로 확인했다(아래).
- **검증 중 발견한 버그:** 처음에는 `File.Replace(..., $null)`로 썼다. PowerShell 5.1은 문자열 매개변수의 `$null`을 `""`로 넘겨 "경로 형식이 잘못되었습니다"로 실패했다(첫 저장은 `Move`라 통과했다). `[NullString]::Value`로 고쳤다.
  - 실패하는 동안에도 기존 파일은 바뀌지 않았고, 임시 파일이 남지 않았고, 서버는 계속 응답했다. 원자적 쓰기와 오류 처리가 의도대로 동작했다는 뜻이다.

### 불러오기 순서와 `localStorage`

- **순서:**
  1. 파일 `GET`
  2. 404이고 `localStorage`에 쓸 수 있는 값이 있으면 파일로 옮긴다
  3. 둘 다 없으면 기본값
- **읽기 실패·시간 초과(3초)는 기본값이고, 옮기지 않는다.** 파일이 있는데 서버가 잠깐 답하지 않았을 수 있다. 이때 옮기면 `localStorage`의 옛 값으로 파일을 덮어쓸 위험이 있다.
- **파일 내용이 잘못됐으면 기본값을 쓰고 파일은 덮어쓰지 않는다.** 운영자가 고치거나 다시 저장할 때까지 원본을 남겨 두기 위해서다.
- **옮긴 뒤 `localStorage`는 지운다.**
  - 다시 `GET`해 내용이 같은지 확인한 다음에만 지운다.
  - 남겨 두면, 운영자가 초기화하려고 파일을 지웠을 때 옛 값이 말없이 다시 옮겨진다. 앱은 `localStorage`에 더 쓰지 않는다.
  - 옮기기가 실패하면 지우지 않는다. 이번 실행은 그 값을 쓰고 다음 시작에 다시 옮긴다.
- **불러오기가 끝날 때까지 자동 시작을 막는다.**
  - 시작을 늦추는 대신 `decideAutoRequest()`에 `settingsReady` 조건을 두었다. D `auto` 줄에 `blocked: settings-loading`이 보이게 하기 위해서다. 끝나면 `evaluate('settings-loaded')`.
  - 그동안 감지 루프는 기본값으로 돈다. 불러온 값을 넣으면 기준이 바뀌어 인식 상태를 다시 재므로(3-3), 기본값으로 인식된 상태가 남지 않는다.
- **조절 화면은 불러오기가 끝난 뒤 만든다.** 그 전에는 `R`이 열리지 않는다(최대 약 3초). 조절 화면이 열려 있는 동안 저장 출처가 바뀌는 복잡한 경우를 없애기 위해서다.
- **D `settings` 출처:** 3-3까지의 `stored`를 다음으로 바꿨다: `file`, `migrated (...)`, `localStorage (migration to file failed: ...)`, `defaults (no file | file is invalid | file read failed: ...)`, `saved`, `loading`.

### 일시정지 `P`

- **판정:** `decideAutoRequest()`에 `paused` 조건 하나를 더했다.
  - 대기에서는 시작하지 않는다(사람이 없어도 이유는 `blocked: auto paused (P)`).
  - 인식 카운트다운은 취소한다(`auto paused during countdown`).
  - 수동 카운트다운과 촬영·결과·쿨타임에는 관여하지 않는다.
- **키 처리:** 켜고 끌 때 `evaluate('paused (P)'·'resumed (P)')`를 부른다. 해제하는 순간 사람이 서 있으면 바로 시작한다(레벨 판정).
- **저장하지 않는다.** 페이지 메모리 변수 하나뿐이다.
- **운영자 표시:** 9:16 영역 오른쪽 위에 작게 둔다(어두운 바탕, 노란 글씨, 1080 폭에서 200×31px). 관람객 시선을 덜 끌면서도 운영자가 화면을 보면 바로 알 수 있게 하기 위해서다(가안). D `auto` 줄 앞에는 `PAUSED (P) |`가 붙는다.
- 키는 `P`(Pause)다. `D`·`R`·`S`·`X`·`Esc`와 겹치지 않는다.

## 사용자 실측 필요 (미실측)

| 항목 | 기대 동작 |
|---|---|
| `Launch.bat`으로 띄운 키오스크에서 `R` → 조절 → 저장 → `Shutdown.bat` → `Launch.bat` | 같은 값. 저장소 `config\presence.local.json`이 생긴다 |
| 예전에 개발 브라우저(`localStorage`)에만 저장한 값이 있는 경우 | 키오스크 프로필은 다른 프로필이라 옮겨지지 않는다. 필요하면 개발 브라우저로 한 번 열어 옮기거나, 키오스크에서 다시 조절해 저장한다 |
| 사람이 서 있을 때 `P` | 카운트다운이 바로 취소되고, 서 있어도 다시 시작하지 않음. 다시 `P`를 누르면 곧 시작 |
| `P`로 멈춘 뒤 새로고침 또는 `Launch.bat` | 자동 촬영이 다시 켜짐(표시 없음) |
| 오른쪽 위 표시의 크기·위치가 현장 화면(FHD~4K 세로)에서 적당한지 | 운영자는 알아보고 관람객 시선은 덜 끄는 정도. 필요하면 `config.showPauseIndicator`로 끈다 |

## 남은 문제

- **4-2 이전 값:** 키오스크 프로필(4-2)은 개발 브라우저 `localStorage`와 다르다. 개발 중 저장한 값은 그 브라우저로 한 번 열어야 파일로 옮겨진다(위 실측 표).
- **너그러운 JSON:** 서버의 JSON 확인은 표준보다 너그럽다. 그런 내용은 저장은 되지만 불러올 때 기본값이 된다. 이 페이지는 `JSON.stringify` 결과만 보내므로 실제로 생기지 않는다.
- **서버가 꺼진 동안의 저장:** 실패를 안내만 한다. 다시 시도는 운영자가 "저장"을 다시 누르는 것뿐이다.
- **브라우저 확인 하나 남음:** 인식 카운트다운 중 `P` 취소(위)
- **가안 값:** 불러오기 제한 3초, 본문 상한 16KB, 운영자 표시 위치·크기
- 브라우저 검증은 이번에도 저장소 밖 임시 하네스로 했다. 저장소 안 하네스는 4-4다.

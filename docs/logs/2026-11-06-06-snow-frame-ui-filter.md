### 관람객 화면

- 사진 창을 4:5 그대로 60줄 올렸다: `config.photoFrame` 10/64~55/64 → **8/64~53/64**(1080×1920에서 240~1590). 결과 1080×1350·인쇄 사진 576×720·인식 영역 줄이기는 같은 규칙이다.
- 제목(표제·필기체)·솜송이 SVG·날짜·시각·창 모서리 금 표시를 없앴다. `guest-screen.js`에서 머리 시계(타이머 포함)를 지웠다.
- 생성 장면 한 장을 `#scene-plate` 캔버스에 처음 한 번 그리고, 사진 창 줄(± 1/64)에서만 그린 키를 뺀다(`ui/scene-plate.js`, `core/chroma-key.js`). 키 식은 그린 우세 d = G − max(R, B), d ≤ 60 불투명·d ≥ 140 투명. 1차 시험에서 캐릭터 둘레에 연두빛 테두리가 보여 키 둘레 2화소의 불투명 화소도 G를 max(R, B)로 누르게 했다.
- 생성 이미지가 들보 줄을 맞추지 못해(3차 장면: 1920 환산 그린 267.6~1518.1) 원본은 그대로 두고 그릴 때만 위·아래 띠를 평행이동한다(`config.scene.layout`, 크기 그대로). 자르는 줄은 전부 그린인 줄(285·1258)이라 캐릭터가 잘리지 않는다. 결과: 위 들보 중심 240, 아래 1590, 눈 바닥 1710부터.
- 안내 글·3·2·1·쿨타임·결과 문구를 모두 눈 바닥(57/64 아래)에 새긴 글씨로 같은 자리에서 바꾼다. 위 띠에는 관람객 UI가 없다. `P` 표시도 눈 바닥 오른쪽 아래로 옮겼다. 진행선은 바닥 맨 아래 가운데 홈이다.
- 장면을 못 읽으면 창 밖 띠에 1차 배경 사진(`snow-village-bg.png`)과 글자만 보인다.
- 데모(`/demo/index.html`)가 같은 장면을 쓰고, 감열지 흑백 스타일·질감 세기 선택을 더했다. "현장 저장값 대조본"을 현장 `filter.local.json` revision 3 적용 수치로 바꿨다(부모가 읽기 전용으로 전달한 값, 파일은 읽거나 쓰지 않음).

### 감열지 톤 점 × 유화

- 감열지·톤 점·유화 켬·질감 세기 b > 0이면(`toneOilBlend`) 회색에 질감 강조 점의 획 볼록 조명·국소 대비를 b × 0.6만큼 더하고, 블루 노이즈면 문턱을 붓 결 선과 블루 노이즈를 b × 0.25 : 나머지로 섞는다(`stroke-tone`). 새 저장 항목은 없고 기존 질감 세기·선 간격을 쓴다.
- 유화 끔·b 0·다른 스타일·회색조 유화의 인쇄 데이터는 예전과 같다. 원격 필터 업데이트 형식은 바꾸지 않았다.
- `E`에서 톤 점일 때 질감 세기(늘)·선 간격(블루 노이즈일 때)을 연다.

## 결정과 이유

- **창 폭은 화면 폭 그대로:** 스케치처럼 창을 좁히면 인식 영역 끌기·D 겹쳐 그리기·결과 좌표를 모두 바꿔야 해서 기능 보존을 우선했다. 캐릭터는 창 모서리 위로만 걸친다.
- **통합 장면 한 장 + 창만 키:** 사용자 확정("카메라 들어갈 부분만 크로마키, 바깥 배경은 한 번에"). 처음 계획한 배경·전경 두 장을 대체했다.
- **띠 맞춤을 런타임 평행이동으로:** 이미지 생성을 세 번 해도 정확한 좌표가 나오지 않았다. 늘리기 없이 두 띠만 옮기면 캐릭터·바닥 비율이 그대로이고, 나중 영상에도 같은 네 값을 쓸 수 있다. 사진·감지·인쇄 좌표는 바뀌지 않는다.
- **숫자도 눈 바닥:** 사용자 확정("숫자도 눈에 써지는 걸로, 상단에는 UI 아무것도 안 보이게"). 숫자 동안 안내 줄은 숨겨 겹치지 않게 했다.
- **톤 점 섞기 세기:** 합성 장면에서 질감 세기 0·1·2를 비교했다. 처음 값(0.5·0.18)은 1에서 거의 보이지 않아 0.6·0.25로 올렸다. 1은 고른 점에 붓 방향이 보이고, 2는 붓 결 선에 가깝다.
- 1차 배경 사진은 부모가 복사를 허락한 생성물이라 대체 배경으로 커밋했다. 최종 장면 PNG는 이미지 담당 커밋 `1e2b088`을 그대로 cherry-pick했다(바이트 동일 SHA-256 `1d2a88c7…f9e452e` 확인).

## 남은 문제

- 캐릭터 원형·상대 크기는 이미지 담당 육안 확인뿐이고 사용자 검수 전이다. 생성 장면이 바뀌면 `config.scene.layout` 네 값을 다시 재야 한다(전부 그린인 첫·끝 줄, 두 들보 중심).
- 캐릭터가 창 모서리를 화면에서만 가리므로 인쇄·결과 사진의 모서리에는 화면에서 안 보이던 부분이 있다(의도된 동작, 현장 체감 확인 필요).
- 알파 없는 캐릭터 영상 교체는 규격만 있고 프레임마다 키를 빼는 구현은 없다.
- 톤 점 × 유화 상수는 가안, 실제 용지 확인 전이다. 현장 저장값은 붓 결 선이라 톤 점을 고를 때만 보인다.

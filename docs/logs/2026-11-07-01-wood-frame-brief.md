# 16단계 — 좌우 여백과 3:4 나무틀

## 사용자 요청과 범위

- 현재 좌우를 꽉 채우는 카메라 영역에 여백을 만들고, 안쪽 카메라 창을 **3:4**로 바꾼다. 전체 화면은 9:16을 유지한다.
- 상하 들보에 좌우 나무 기둥을 연결한 틀로 구성하고, 틀 바깥 좌우에 장면 배경을 보인다. 구체 크기·위치·두께는 Opus 디자인 담당이 결정해 이미지 담당과 맞춘다.
- 화면만 찌그러뜨리지 않고 실제 카메라 크롭·결과·인쇄 사진 영역을 동일한 창에 맞춘다. 좌우 여백 도입에 따른 감지 영역 교차, D 오버레이, 편집 좌표, 크로마키 범위도 연결한다.

## 유지할 기준

- 캐릭터 원형·포즈·상대 크기, 압설 눈블록 벽, DOF 눈마을, 장면 전체 유화.
- 상단 관람객 UI 없음. 안내와 숫자는 아래 눈바닥에 파인 홈으로 교체한다.
- 카메라 유화·흑백 독립 시험과 톤점 혼합, 촬영·취소·복구 기능, 현장 저장값 유지.
- 화면 장식은 촬영·인쇄 데이터에 들어가지 않는다. 사진 영역의 비율이 바뀌면 실제 출력 치수와 관련 기준 문서를 갱신한다.
- 기준 master는 `f386920`이다. 이전 단계와 이 커밋을 보존하며 현장 설정 파일은 수정하지 않는다.

## 분담과 완료 기준

- Opus 5.5: 좌우 여백·나무틀 구도, 3:4 창 좌표, UI와 관련 크롭·감지·출력 연결, 자산 통합.
- GPT-6 Astra medium: Opus 좌표 합의 후 기존 장면 이미지 수정. 개구부만 크로마키로 비우고 글씨·유화는 굽지 않는다. 생성 원본과 전체 프롬프트·오차를 기록한다.
- GPT 6.1 Sol xhigh auto: 구현 후 변경 범위의 간단 검수. 필요 수정 뒤 해당 경로만 간단 확인하며 본격 검수는 별도 요청 때 한다.
- 담당자는 단계 브랜치에서 작은 커밋·문서·검증 결과를 보고하고 멈춘다. 부모가 검수와 로컬 master 통합을 맡는다. push하지 않는다.

## 남은 문제와 바로 다음 작업

- Opus가 창 크기·좌표와 나무틀 구도를 정해 Astra에 전달한다.
- 구현과 이미지 합성을 마친 뒤 주요 크롭·키·좌표 경로 및 합성 화면을 확인한다.
- 아직 구현 완료나 사용자 미감 채택을 뜻하지 않는다. 실제 장치·4K·실물 출력은 확인한 경우에만 완료로 보고한다.

> **상태: 구현·관련 검사 완료, 간단 검수 대기.** 병합·push는 부모 담당이다. 이미지 제작 기록은 [07 로그](2026-11-09-07-open-frame-image.md)다.

- 창 비율은 후보 900×1200·945×1260·990×1320을 거친 레이아웃 가이드로 비교해 정했다. 990은 위 띠가 좁아 캐릭터 머리가 잘리고, 945는 1080 화면에서 x가 반 화소, 900은 확대 폭이 작았다. 960×1280은 화면·결과·4K 좌표가 모두 정수다.

## 결정과 이유

- **자산 원본 보존과 표시 변환 분리.** 생성 도구가 3:4 개구부를 3회 모두 만들지 못했다(그린 비율 0.841·0.852·0.834, 허용 0.75~0.77). 부모 지시로 교정 1차 `exec-1d2649f1`을 **바이트 그대로** 납품받고(`src/web/assets/scene/snow-frame-plate.png`, 941×1672, SHA256 `9D56DB4A…0848`, 커밋 `470f2ab` → cherry-pick `7f95ac6`) PNG는 고치지 않았다. 맞춤은 전부 런타임 표시 코드다(`ui/scene-plate.js` `stretchPlacement`).
- **세로 늘림 맞춤.** 가로 배율 하나(그린 폭 785 → 960, 1.2229)만 쓴다. 위 띠(원본 y<340)·아래 띠(원본 y≥960)는 균일 배율로 각각 창 위끝·아래끝에 붙여 캐릭터·눈벽 비율을 지킨다. 원본 y340~960만 세로로 약 1.2배(`middleScale/scale` 1.198) 더 늘린다. 절단선은 Astra 후보 y400·y900보다 늘림이 작은 쪽으로 정했고, 안쪽 폭 전체가 그린인 줄 y321~984 안이다(직접 화소 확인). `fit` 값은 줄·열 가운데값 기준 x77~862(끝 제외)·y310~1233이다(Astra bbox 끝 862는 일부 줄만 해당).
- **눈벽은 자르지 않는다.** 균일 배율 때문에 눈벽이 약 206px가 되어 눈 바닥이 170px로 줄었다. 눈벽을 눌러 줄이면 블록 모양이 달라지고 절단선이 벽을 지나므로, 대신 글자 묶음을 바닥 + 0.56cqw, 숫자를 바닥 + 0.74cqw로 올리고 결과 진행선을 y1898로 내렸다. 운영자 일시정지 표시가 긴 영어 결과 줄과 겹쳐 아래로 내렸다.
- **인쇄 반올림.** 인쇄 격자 576×1024에서 위끝 133.33줄만 정수가 아니어서 `photoFrameRect` 한 규칙으로 133줄이 된다(열 32~544, 줄 133~816, 사진 512×683, 쪽 576×875). 화면 창의 첫 줄·끝 줄·첫 열·끝 열은 인쇄 사진의 첫 줄·끝 줄·첫 열·끝 열과 같다(Node 테스트). 위끝 차이는 약 0.6 화면px이고 인쇄 첫 줄의 일부가 창 밖으로 잘릴 뿐이다.
- 유화 번들·seed·셔터 층, 장식 미인쇄, 1비트 점 위 유화 없음은 17단계 그대로다. 현장 `*.local.json`은 건드리지 않았다.

## 검증

**Node:** 전체 **749개 통과**(마지막 코드 수정 뒤 실행).

**브라우저 (`tools/browser-check.mjs`, 임시 프로필, 가짜 카메라, 합성 장면):**

| 시나리오 | 결과 | 확인한 값 |
|---|---|---|
| 페이지 로드 | 통과 | 서체·자산 200 |
| 촬영 결과(회색조 유화 기본) | 통과 | 960×1280 JPEG, 셔터 순간 미리보기 블록 차 1.143/255, 인쇄 576×875 |
| 결과 효과 렌더 실패 3가지·인쇄 읽기 실패 2가지 | 통과 | 대체 경로에서도 틀 960×1280, 인쇄 576×875 |
| 관람객 화면 | 통과 | 틀 x60~1020·y250~1530, 글자·숫자는 눈 바닥에만, 결과 칸 = 틀, 자르지 못한 9:16 대체는 창 60,250,960,1280로 잘림 |
| 최종 화면 필터 | 통과 | 합성 810×1440, 창/사진 블록 차 1.38/255, **감열지 창 점 = 인쇄 기반 사진 1,185,005화소 차이 0**, 필터 끔 → 기존 화면 |
| 시안 데모 | 통과 | 결과 960×1280, 인쇄 PNG 576×875 |

- 앞 세 시나리오·`최종 화면 필터`는 일시정지 표시 CSS를 고치기 전에 실행했다. 그 뒤 `관람객 화면`·`시안 데모`를 다시 실행했다. 고친 것은 표시 위치 한 줄뿐이다.
- 전체 25개 시나리오는 실행하지 않았다(간단 검수 정책). ROI는 Node `clipRegionToFrame` 테스트와 D `frame` 줄로 확인했다.
- 처음의 `관람객 화면`·`최종 화면 필터`·`시안 데모` 실패는 모두 검사 도구에 남은 옛 좌표(1/8, 0.125, 576×768)였고, 앱 동작 문제가 아니었다. 설정값을 읽도록 고쳤다.

**합성 화면 육안 확인 (가짜 카메라 도형 영상):** 대기·카운트다운·결과(필터 끔), 대기·결과·감열지(필터 켬)를 보았다. 위 띠에 푸빌라·후트, 아래 눈벽에 깨또·포코가 있고 창이 화면 대부분을 차지한다. 절단선(화면 y약 287·1196) 주변을 3배 확대해 기둥 이음새·나뭇결 끊김·배경 DOF 띠가 없음을 확인했다. 얼굴 자리는 비어 있고 안내 글자는 눈 바닥 안에 있다. 인쇄 PNG는 데모의 합성 사람 도형으로만 확인했다.

## 미검증과 남은 문제

- 실제 카메라·인물, OBS, 현장 PC 성능, 4K 실제 화면, 실물 감열지, 설치 거리 가독성은 **미검증**이다.
- 창이 넓어져 카메라 화각이 달라졌다. 현장에서 `E` 카메라 섹션으로 맞춰야 할 수 있다. 저장된 인식 영역이 틀 밖이면 틀 안으로 줄어든다.
- **포코가 공식 척도보다 크다.** 화면 환산 약 153px로 목표 123px보다 약 24% 크다(Astra 시각 근사 기준). 원본 PNG를 고치지 않는 범위라 그대로 두었고 사용자 확인 항목이다. 깨또는 약 309px로 목표 301px에 가깝다.
- 필터를 끄면 포코·깨또 털 둘레에 얇은 올리브색 테가 확대 시 보인다(유화를 켠 기본 화면에서는 눈에 띄지 않음). 합성 키 수치는 이번 범위에서 바꾸지 않았다.
- 후트 폼폼이 화면 위끝에서 약 14px로 가깝다. 잘리지는 않는다.
- 눈 바닥이 170px로 좁다. 영어 줄 아래 여백은 약 35px이고 현장 가독성은 미검증이다.
- 인쇄 쪽 높이가 576×768(약 96mm)에서 576×875(약 109mm)로 늘어 용지 사용량이 는다. 실물 확인 항목이다.

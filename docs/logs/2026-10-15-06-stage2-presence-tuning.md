## 결정과 이유

- **단축키 `R`:** "Range(인식 범위)"에서 따왔고 `D`와 겹치지 않는다. 수정 키 없이 한 키로 연다. 현장 키보드는 운영자만 쓰고 관람객은 화면을 만지지 않으므로 오조작 위험이 작다고 봤다. `Esc`는 닫기만 한다.
- **저장하지 않고 닫으면 저장된 값으로 되돌린다:**
  - 실행 중인 판정값과 다시 시작했을 때의 값이 늘 같게 하기 위해서다. 무인 운영 중 저장하지 않은 값이 남아 있다가 재부팅 때 말없이 바뀌는 일을 막는다.
  - 키오스크에서 확인 창은 띄우지 않는다. 대신 패널에 "저장하지 않은 변경이 있습니다 (닫으면 취소됩니다)"를 늘 보인다.
- **불러오기 보정은 항목 단위:**
  - JSON 자체가 깨졌거나 버전이 다르면 전체 기본값을 쓴다.
  - 그 외에는 잘못된 항목만 기본값으로 바꾸거나 범위 안으로 맞춘다.
  - 저장소의 원래 값은 운영자가 다시 저장할 때까지 고치지 않는다. 고친 내용은 콘솔·D 화면·패널에 보인다.
- **버전은 키(`.v1`)와 값(`version: 1`) 둘 다:** 키는 형식이 크게 바뀔 때 새 키로 옮기기 위해, 값의 버전은 같은 키에 다른 형식이 들어 있는 경우를 걸러내기 위해 둔다.
- **최소 신뢰도 하한 0.3:** 감지기 자체 기준(`detectorMinConfidence` 0.3)보다 낮추면 효과가 없어서 맞췄다.
- **최소·최대 크기 충돌:**
  - 슬라이더는 움직인 쪽이 상대값에서 멈춘다.
  - 불러오기에서 최소가 최대보다 크면 최대를 최소에 맞춘다. 최소 크기는 거리 조건이라 운영자 의도가 더 분명하다고 봤다.
- **영역 끌기는 이동량 기준 + `window` 이벤트:**
  - 처음에는 포인터 위치를 그대로 변 위치로 썼다. 그러면 핸들 안쪽을 잡을 때 변이 최대 핸들 크기(28px)만큼 튀어서, 시작 위치 대비 이동량으로 바꿨다.
  - 검증 중 headless Chrome에서 `setPointerCapture`가 적용되지 않는 것을 발견했다(이벤트 기록: `cap=false`, 포인터가 영역을 벗어나면 `pointermove`가 `<video>`로 감). 그래서 끌기 동안에는 `window`에서 `pointermove`·`pointerup`을 받는다. 실제 마우스에서 포인터가 패널 위나 화면 가장자리로 나가도 끌기가 이어지는 이점도 있다.
- **크기 가이드:** 영역 가운데에 최소(파랑)·최대(보라) 정사각형을 그린다. 한 변은 기준 높이 × 9:16 영역 높이(px)다. 얼굴 박스가 거의 정사각형이라 실제 박스와 바로 비교할 수 있다.
- **조절 중에는 캔버스에 영역 점선을 그리지 않는다:** 편집 사각형과 겹치지 않게 하기 위해서다.
- **패널 위치:** 세로 화면에서는 9:16 영역이 화면 전체라 패널이 영상을 가린다. 아래에 두고 "패널 위·아래" 버튼으로 옮긴다.

### 검증 중 고친 것

- 처음 실행에서 일부 영역 테스트가 실패했다. 원인은 셋이었다.
  - 하네스가 뷰포트 밖 좌표로 마우스를 옮겼다. headless에서는 이 이벤트가 전달되지 않았다(하네스 수정).
  - D 화면 텍스트를 갱신(0.5초) 전에 읽었다(하네스 수정).
  - 포인터 캡처가 적용되지 않았다(**앱 수정**: 위 "`window` 이벤트").
- 수정 후 위 표의 모든 항목을 다시 실행해 통과했다.

## 사용자 실측 필요 (미실측)

사용 방법:

1. 서버를 띄우고 Chrome에서 `http://localhost:8765/`를 연다.
2. `R`을 누른다(필요하면 `D`도 켠다).
3. 노란 사각형 안을 끌어 옮기고, 모서리·변의 노란 핸들로 크기를 바꾼다.
4. 슬라이더를 움직인다. "고급: 판정 시간"을 열면 시간 두 개가 있다.
5. "저장"을 누른다. 저장하지 않고 `R`·`Esc`·"닫기"로 닫으면 저장된 값으로 돌아간다.

| 항목 | 기대 동작 |
|---|---|
| 실제 마우스로 영역 끌기·크기 조절 (창 모드·전체화면) | 포인터가 패널 위나 화면 밖으로 나가도 끌기가 이어지고, 놓으면 멈춘다 |

### 수정 내용

- **#1 감지기 재생성:**
  - 생성·재시도·폐기를 `detector-keeper.js`로 분리했다. 생성 함수와 타이머를 주입받아 Node에서 테스트한다.
  - 생성에 실패하면 `faceDetection.detectorRetryMs`(15초, 가안) 뒤 다시 만든다. 생성은 한 번에 하나만 진행하고, 생성 중 요청은 진행 중인 생성을 기다린다.
  - 감지기가 없을 때 카메라가 다시 준비되거나 페이지가 다시 보이면 간격을 기다리지 않고 바로 만든다. 처음 카메라가 준비되는 것은 계기에서 뺐다(넣었더니 시작할 때 생성이 두 번 시도됐다).
  - 로그 05의 "실행 중 WebGL 컨텍스트 손실"도 같은 경로로 처리했다. 15번 연속 감지에 실패하면 감지기를 `close()`로 닫고 버린 뒤 같은 간격 뒤 다시 만든다. 이전의 "1초 간격 감지 재시도"는 없앴다. 범위가 크지 않아 나누지 않았다.
  - **검증 중 발견:** Chrome은 실패한 동적 `import()` 결과를 기억해, 원인을 없앤 뒤 다시 시도해도 네트워크 요청 없이 같은 오류를 돌려줬다(수정 전 재시도 2회, 요청 0건). 그래서 `face-detector.js`는 불러오기에 실패한 적이 있으면 `?retry=N`을 붙여 새로 받고, 성공한 bundle은 재생성 때 다시 쓴다.
  - 간격 15초의 이유: 생성이 메인 스레드를 약 1초 막는다. WebGL이 끝내 없는 환경에서는 생성 → 실패 → 폐기가 되풀이되므로, 미리보기가 자주 끊기지 않게 간격을 길게 뒀다. 그런 환경은 4단계 하드웨어 가속 점검으로 막는다.
- **#2 끌기 종료:**
  - 끌기를 `region-drag.js`로 분리했다. 요소와 창을 `EventTarget`으로만 받는다.
  - 끌기를 끝내는 경우: 놓기, `pointercancel`, 창 `blur`, `lostpointercapture`, 이동 중 주 버튼이 떼어져 있음(`(buttons & 1) === 0`, 그 이동은 반영하지 않음), 조절 화면 닫기.
  - 끝날 때 창과 요소에 붙인 리스너를 모두 해제한다.
- **#3 설정 출처:**
  - `stored`(시작할 때 읽음), `defaults`(저장값 없음·사용 불가), `saved`(이번 실행 중 저장)로 나눴다. 저장하지 않은 변경이 있으면 `+ unsaved changes`를 붙인다.
  - 시작할 때의 보정 내용은 저장하기 전까지만 붙인다.

## 남은 문제

- **저장값은 Chrome 프로필에 묶인다.** 현장 전용 프로필을 지우거나 다른 프로필로 실행하면 기본값으로 돌아간다. 복사해 둔 JSON을 다시 넣는 기능은 범위 밖이다. 4단계에서 파일 저장을 검토할 때 함께 정한다.
- 패널이 세로 화면에서 영상 일부를 가린다. 위·아래 이동으로 피한다. 실제 운영자 사용성은 확인이 필요하다.
- "복사" 버튼의 클립보드 동작은 확인하지 않았다(headless 하네스에서는 클립보드 권한을 다루지 않음).
- 로그 05의 남은 문제 중 "감지기 재생성 없음"은 검수 #1로 해결했다. WebGL 필수(4단계 점검 항목)와 시작할 때의 긴 작업(생성 약 1초, 재생성 때마다 생김)은 그대로다.
- 재생성 간격 15초는 가안이다. 현장에서 감지기 회복이 늦다고 느끼면 조정한다.

# 2026-11-06-11 — 15단계: 눈벽·장면 유화·눈에 파인 글씨

부모 지시(10번 로그, 부모 통합 때 추가)에 따른 구도·UI·WebGL 담당(Opus) 기록이다. 벽 이미지 수정은 이미지 담당이 맡았고 [로그 12](2026-11-06-12-snow-wall-image.md)에 있다. 브랜치 `stage15-snow-relief`(`master` `63d4687`에서), 병합·push는 하지 않았다.

1. 얼음벽 → 눈던지기 시퀀스의 이글루 같은 눈벽.
2. 전체 씬(캐릭터·배경)에 유화 필터.

## 한 일

- **분담:** 이미지 담당에게 벽만 국소 수정하고 유화·글자는 이미지에 굽지 않도록 범위를 먼저 전했다(참고 `03_ThrowSnow/versions/v09/01_Keyframes/TS_IDLE_t003_r01.png`의 압설 블록 벽, 띠 위·아래 줄·941×1672·그린 범위 보존). 결과 `446e3c8`(벽 2단 압설 블록, 그린 경계 변화 0~1줄)을 임시 사본과 바이트 동일 확인 후 cherry-pick했다. 벽 아랫선이 원본 약 1455줄(화면 1718)이라 띠 맞춤 값은 그대로 쓴다. 벽 밖 화소도 미세하게 다시 생성되었다(12번 로그).
- **장면 유화 (`effect/scene-paint.js`, `ui/scene-plate.js`):** 장면을 1080×1920으로 띠 맞춤해 그리고 창 줄 키를 뺀 뒤, 알파는 따로 두고 창 자리를 중립 밤빛으로 채운 불투명 그림을 별도 WebGL 컨텍스트의 oil2f(기본 제공판 원본 기본값, 출력 끔, seed 7)로 한 번 칠해 알파를 다시 씌운다. 렌더러·컨텍스트는 바로 놓는다. 카메라 효과와 렌더러·설정을 공유하지 않는다.
- **둘레 키 보강 (`core/chroma-key.js`):** 칠하자 캐릭터 둘레의 노란·연두 빛 테가 넓어졌다. 원인은 생성 이미지 자체의 둘레 빛 번짐(예: `(224,222,63)`, d ≈ 0이라 기존 키로는 불투명)이다. 키 둘레 3화소 안에서는 평균 기준 e = G − (R + B)/2로 알파를 줄이고(`RIM_KEY` 20~90) G를 (R + B)/2로 눌러 노랑을 털색으로 돌렸다.
- **파인 글씨 (`index.html` `#snow-carve`·`#snow-carve-lg`, `style.css`, `main.js` `scaleSnowCarve`):** 글자 모양을 높이로 뒤집어 SVG 조명으로 비추는 필터. 홈 벽 그늘·밝은 벽·바닥 그늘·눈 알갱이·둘레의 밝은 테. 글자 색과 텍스트 그림자를 없앴고 DOM 문구·상태 교체·움직임은 그대로다. 영어 줄은 홈이 보이게 Cinzel 600으로 올렸다.

## 결정과 이유

- **유화는 런타임 1회:** 이미지에 구우면 카메라 효과 수치와 따로 놀고 다시 생성해야 바꿀 수 있다. 기존 렌더러를 그대로 써서 새 셰이더·프레임워크가 없고, 정적 장면이라 시작할 때 한 번이면 된다(개발 PC 약 0.2초).
- **기본 제공판 원본 기본값:** 운영자 저장값·원격 업데이트와 묶으면 필터를 바꿀 때 장면도 바뀌고 갱신 경로가 복잡해진다. 장면은 고정 그림이 낫다고 판단했다. 장면용 덮어쓰기 자리(`config.scene.paint.settings`)만 두었다(가안, 비어 있음).
- **창 자리 채움색:** 그린을 그대로 칠하면 획이 초록을 캐릭터 둘레로 끌고 온다. 알파를 다시 씌우므로 채움색은 둘레 획에만 섞인다. 합성 화면에서 채움색 테두리는 보이지 않았다.
- **글씨는 SVG 조명 필터:** 글자가 정확해야 해서 생성 글자 이미지는 쓰지 않았다. CSS 그림자 대신 높이 → 법선 → 빛 계산이라 실제 오목 형상이 나온다. 첫 수치는 그늘이 짙어 잉크처럼 보여, 그늘 색을 눈 그림자 쪽으로 옅게 하고 상한을 두었다.

## 검증

카메라는 모두 Chrome 가짜 장치(합성 영상), 임시 프로필 headless Chrome(GPU)이다.

- `npm test`: 728개 통과(장면 칠하기·둘레 키·장면 유화 설정 테스트 포함).
- `browser-check --only "관람객 화면(14단계"`: 통과. D `scene 1080x1920, bands top -8 bottom +47, keyed rows 210-1620 (…), oil painted 221ms`. 관람객 글자·숫자·진행선은 눈 바닥에만, 결과 = 틀, 인쇄 576×912.
- `--only "시안 데모"`: 통과. 감열지 톤 점 화면에서 창 안 1비트 점 미리보기는 그대로이고 장면만 칠해진 것을 캡처로 확인.
- 합성 화면을 직접 보고 확인: 장면 전체에 붓질이 보임, 압설 눈벽, 창 경계·캐릭터 둘레에 초록·채움색·노란 테 없음(깨또·후트·포코 확대), 안내 두 줄과 숫자가 눈에 파인 홈(위 왼쪽 벽 그늘·아래 오른쪽 밝은 벽·둘레 테)으로 보이고 읽힘. 캡처는 `artifacts/`(Git 제외)에만 있다.
- 실제 웹캠·OBS·현장 PC·4K·실제 사람은 **미검증**. 현장 `config/*.local.json`은 읽거나 바꾸지 않았다. 별도 전체 회귀·GPU 결정성 검사는 하지 않았다(카메라 경로 변경 없음).

## 남은 문제

- 파인 글씨의 영어 줄(작은 글자)은 한국어보다 흐리다. 현장 거리에서 가독성 확인이 필요하다.
- 4K에서는 필터 길이를 화면 폭에 맞춰 곱하지만 실제 4K 화면 모양은 미확인.
- 장면 유화 세기는 원본 기본값 그대로다. 붓질을 더 세게·약하게 할지는 사용자 확인 뒤 `config.scene.paint.settings`로 정한다.
- 벽 밖 화소가 미세하게 다시 생성되어 캐릭터 원형 검수는 이 판으로 다시 본다.

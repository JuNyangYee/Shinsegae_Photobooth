# 2026-10-27-01 — 인식·이탈 반응 시간 250ms, "반응 속도" 묶음

브랜치 `task-presence-timing`(`master` `c525d7a`에서 분기). 작업 에이전트(Opus 5.5). 병합·push는 오케스트레이터가 한다.

## 요청 (2026-10-27, 사용자)

> "인식 기준을 좀 바꾸자. 지금은 사실 1초 남았을 때 자리 비우면 촬영이 되는 느낌인데, 인식 간격을 기본 0.25초로 두고 설정할 수 있게 해서, 이탈·인식을 좀 빠르게 반응할 수 있게 수정해 줘."

이전 기본값은 인식까지 `presentHoldMs` 500ms, 이탈 유예 `absentGraceMs` 1000ms였다. 카운트다운 마지막 약 1초 안에 떠나면 "인식 안됨"이 셔터보다 늦어 그대로 찍혔다(아래 측정으로 확인).

### 실제 OBS 측정 (반응 시간·셔터 직전 이탈·깜빡임)

- 환경: 실제 `OBS Virtual Camera` 1080×1920(OBS 실행 중), 화면 앞에 **실제 사람 한 명이 앉아 있었다**(얼굴 점수 0.93~0.98, 감지 14.6fps, 입력 360×640). 저장소 밖 임시 측정 스크립트(`%TEMP%`)로 서버·headless Chrome(임시 프로필)을 띄웠고, 설정은 조절값 API로 바꾼 뒤 새로고침했다. 끝난 뒤 스크립트·프로필·조절값 파일(없던 상태로)을 모두 지웠다. 이미지·프레임은 저장하지 않았다.
- **이탈 흉내:** 감지 입력 캔버스(긴 변 640 이하에 `drawImage(video)`)를 그린 직후 검게 칠했다(감지기 입장에서 화면이 갑자기 빈다). 미리보기·사진은 그대로다. **사람이 실제로 걸어 나간 것이 아니다.** 실제로는 몸이 점점 빠지며 얼굴이 영역·크기 밖으로 나가는 시점이 이보다 늦거나 들쭉날쭉하다.
- 시각은 페이지 시계(`performance.now()`). "떠남" = 검게 칠하기 시작한 순간, "인식 안됨" = 화면 `is-present`가 빠진 순간, "취소" = 카운트다운이 숨는 순간(MutationObserver). 인식은 검게 칠하기를 멈춘 순간부터 `is-present`가 붙고 자동 카운트다운이 시작되는 순간까지.

**반응 시간 (자동 카운트다운 0.6~1.3초 지점에서 떠남)**

| 설정 (인식/이탈 ms) | 떠남 → 인식 안됨 = 카운트다운 취소 | 다시 들어옴 → 인식됨 = 자동 시작 |
|---|---|---|
| 500 / 1000 (이전) | 8회 **1028~1140ms, 평균 1077** | 7회 542~611ms, 평균 576 (+1회 2345, 아래) |
| **250 / 250 (새 기본값)** | 6회 **276~318ms, 평균 300** | 4회 281~347ms, 평균 306 (+4회 1077~2827, 아래) |
| 100 / 100 (참고) | 4회 150~215ms, 평균 174 | 4회 144~184ms, 평균 168 |
| 0 / 0 (참고, 프레임 판정 그대로) | 6회 19~71ms, 평균 48 | 5회 17~46ms, 평균 31 (+1회 1681) |

- 떠남 → 인식 안됨 ≈ 다음 감지 프레임까지(0~67ms) + 유예 + 판정 프레임 맞춤. 카운트다운 취소는 같은 순간(같은 알림 안)이다.
- 들어옴이 긴 회차(250에서 1077~2827ms 등)는 그때 사람의 얼굴 높이가 최소 얼굴 크기 0.185 바로 근처(0.184~0.209)라 `small`로 빠진 프레임이 섞였기 때문이다(D `face 1 ... -> small` 확인). 시간 설정이 아니라 앉은 거리 때문이다.
- 250/250 반응 측정 중 2회는 떠나기 전에 자연 깜빡임(위 `small`)으로 카운트다운이 이미 취소돼 있어 측정에서 뺐다.

| 설정 | 취소됨 | 찍힘 |
|---|---|---|
| 500 / 1000 | 남은 1299·1136ms | 남은 1034·996·943·881·790·593·400ms |
| **250 / 250** | 남은 591·436·341ms | 남은 291·238·191·146·99ms |

- 떠나도 찍히는 마지막 구간: **약 1.04~1.14초 → 약 0.29~0.34초**(약 70% 줄어듦). 경계는 이탈 반응 시간(위 1028~1140 / 276~318ms)과 같다. 사용자가 느낀 "1초 남았을 때 비우면 촬영된다"가 측정으로 맞았다.
- 셔터 시각은 카운트다운 시작 뒤 3017~3038ms.

**깜빡임 (자동 촬영 일시정지 `P`, 사람이 앉은 채 60초, 인식 상태가 바뀐 횟수)**

| 설정 | 바뀐 횟수 | 인식 안됨으로 머문 시간 |
|---|---|---|
| 0 / 0 (프레임 그대로) | 60 (끊김 30) | 66~999ms. 1프레임(66~80ms) 14회, 2~3프레임(131~202ms) 5회, 250ms 넘음 11회 |
| 500 / 1000 | 2 | 1523ms 1회 |
| 250 / 250 | 4 | 3784·1402ms |
| 100 / 100 | 8 | 328·1302·950·1800ms |

- 네 측정은 서로 다른 1분이라 사람 자세가 같지 않다. 끊김 원인은 대부분 얼굴 높이가 최소 얼굴 크기 경계(0.185)를 오간 것이고(감지기 누락이 아님), 인식 안됨이 1초 넘게 이어진 것은 실제로 기준 밖에 있던 시간이다.
- 0/0 1분의 끊김 길이로 셈하면(첫 없음 프레임 ~ 다시 있음): 유예 100ms면 약 12회, 250ms면 약 9회, 500ms면 2회, 1000ms면 0회가 "인식 안됨"이 된다. 1프레임 누락(14회)은 100ms 이상이면 모두 흡수한다.
- 정리: **경계에 걸친 사람 앞에서는 250ms가 1000ms보다 확실히 자주 바뀐다.** 다만 1~3프레임 누락은 흡수하고, 남는 깜빡임은 "기준 밖에 0.3초 넘게 있었다"는 뜻이라 기준(최소 얼굴 크기·영역)을 현장 서는 위치에 맞추는 것이 해결책이다. 발자국 매트에 선 사람은 얼굴이 기준 안쪽에 넉넉히 있어야 한다(현장 확인).

### 미검증

- **실제로 사람이 걸어 나가고 들어오는 이탈·인식**은 재지 않았다(감지 입력을 검게 칠한 흉내). 몸이 점점 빠지는 실제 이탈은 위 수치보다 늦게 "인식 안됨"이 될 수 있다.
- 현장 매트 위에서 선 사람의 깜빡임(개발 PC에서는 앉은 사람, 얼굴 크기 경계).
- 현장 PC의 감지 빈도(15fps보다 낮으면 250ms가 더 적은 프레임이 되어 반응이 약간 늦고 누락 흡수가 줄어든다).

## 제안 (구현하지 않음)

1. **하한:** 지금 0 그대로 두되, 운영 중 실수를 막으려면 **하한 100ms**를 권한다. 0~50ms는 감지 한 프레임 누락(이번 1분에 14회)에도 카운트다운이 취소된다. 100ms면 1프레임 누락은 모두 흡수된다. 250ms 아래로 줄일 이유가 생기기 전까지는 필요 없다고 본다.
2. **셔터 순간 재확인:** 넣지 않는 쪽을 권한다. 남는 구간은 약 0.3초이고, 그 사이 떠나는 사람은 대개 아직 화면에 걸쳐 있다. 셔터 순간에 마지막 프레임 하나로 다시 보면 이 구간은 약 0.07초로 줄지만, 한 프레임 누락(위 0/0에서 1분 14회)에도 서 있는 사람의 촬영이 취소된다. 현장에서 0.3초 구간이 문제로 보이면 "셔터 순간 마지막 2프레임이 모두 없음이면 취소"처럼 좁게 검토한다.
3. **두 값 합치기:** 위 결정 표 이유로 지금 구조를 권한다.

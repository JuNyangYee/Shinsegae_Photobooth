# 2026-10-15-11 — 4-2 현장 실행 스크립트

브랜치 `stage4-launch`(기준 `c7b0a15`, 1~3단계 병합된 `master`). 작업 에이전트(Opus 5.5)가 오케스트레이터가 지정한 4-2만 수행했다. 같은 시각 다른 작업 에이전트가 `stage4-stabilize`에서 `src/web/js/`를 고치고 있어 `src/web/`는 건드리지 않았다.

## 사용자 결정 (2026-10-15)

- 현장 Chrome은 `--kiosk`로 띄운다.
- 부팅 시 자동 실행과 `Shutdown.bat`을 넣는다.
- 조절값 파일 저장과 자동 촬영 일시정지 키는 4-3 범위다.

## 결정과 이유

### OBS 플래그와 안전 모드 대화상자

- 이 PC의 OBS는 `C:\Program Files\obs-studio\bin\64bit\obs64.exe` 32.2.1이다(파일 속성).
- 실행하지 않고 실행 파일 안 `--help` 문구로 지원 플래그를 확인했다. `--startvirtualcam`, `--minimize-to-tray`, `--disable-updater`, `--disable-missing-files-check`를 쓴다.
- **참고 프로젝트가 쓰던 `--disable-shutdown-check`는 OBS 32.2.1에 없다**(ASCII·UTF-16 모두 문자열 없음). 쓰지 않는다.
- OBS 32의 비정상 종료 감지는 `%APPDATA%\obs-studio\.sentinel\run_<id>` 표식이다.
  - 실행 파일 문자열 `obs-studio/.sentinel`, `run_`, `Crash or unclean shutdown detected`와 언어 파일 `CrashHandling.Labels.Text`("did not properly shut down ... Run in Safe Mode?")로 확인했다.
  - 실행 중인 사용자 OBS의 `run_*` 표식이 실제로 있는 것도 확인했다(읽기만 함).
- 그래서 **`obs64` 프로세스가 하나도 없을 때만** 남은 `run_*` 표식을 지우고 시작한다. 32.x가 아니면 경고를 남긴다.

### 카메라 권한: 운영자가 전용 프로필에서 한 번 허용

- `--use-fake-ui-for-media-stream`을 실제로 시험했다. 같은 500×800 앱 창에서 창 안쪽 높이가 763 → 707px로 줄었다. **"지원되지 않는 명령줄 플래그" 경고 막대가 뜬다**는 뜻이고, 키오스크 화면 위쪽을 가린다.
- 키오스크는 `localhost` 앱만 띄우므로 자동 수락의 보안 위험 자체는 작다. 그래도 관람객 화면이 가려지는 것이 결정적이어서 쓰지 않았다.
- `Preferences`에 권한을 미리 쓰는 방법은 내부 형식에 기대고, 정책(레지스트리)은 HKCU면 일반 Chrome에도 걸리고 HKLM이면 관리자 권한이 필요해 제외했다.
- 비교표는 `docs/SYSTEM.md` 1절에 있다. 포트나 프로필을 바꾸면 다시 허용해야 한다는 점을 README 첫 설치 절차에 적었다.

### Chrome 플래그

- `--user-data-dir`, `--kiosk`, `--no-first-run`, `--no-default-browser-check`, `--hide-crash-restore-bubble`, `--disable-features=Translate`, `--disable-pinch`, `--overscroll-history-navigation=0`, (설정 시) `--window-position`
- 각 이유는 SYSTEM 1절 표에 있다.
- Chrome 155 `chrome.dll` 문자열로 스위치 존재를 확인했다. `--disable-session-crashed-bubble`은 없어서 `--hide-crash-restore-bubble`을 쓴다.
- 같은 프로필 Chrome이 떠 있으면 닫고 다시 띄운다. 같은 프로필로 다시 시작하면 기존 인스턴스에 창만 늘기 때문이다. 창 닫기를 먼저 요청해 정상 종료되게 한다.

### 하드웨어 가속

- Chrome은 설정에서 가속을 끄면 프로필 `Local State`에 `"hardware_acceleration_mode":{"enabled":false}`를 남긴다. 기본(키 없음)은 켜짐이다.
- 실행 전에 이 값이 `false`면 `true`로 바꾸고 경고를 남긴다. JSON 전체를 다시 쓰지 않고 그 부분만 바꾼다.
- GPU를 끄는 플래그는 쓰지 않는다.

### 그 밖의 결정

- **서버 숨김 실행:** `Start-Process -WindowStyle Hidden -RedirectStandardOutput/-Error`를 쓴다. 부모가 끝나도 자식이 살아 있고 창이 없으며 출력이 파일로 남는 것을 먼저 시험했다.
- **이전 서버 식별:** `-File <이 저장소 serve.ps1 전체 경로>` 명령줄만 대상으로 한다. 상대 경로로 띄운 개발 서버나 다른 worktree 서버는 건드리지 않는다.
- **포트 점유:** 이전 서버를 정리한 뒤에도 `GET /`에 무엇이든 응답하면 다른 프로그램으로 보고 실패한다.
- **실패 시 되돌리지 않음:** 참고 프로젝트의 롤백은 가져오지 않았다. 예를 들어 Chrome 단계에서 실패하면 서버는 남고, 다음 `Launch.bat`이나 `Shutdown.bat`이 정리한다.
- **OBS 종료(선택):** `obs_path`(또는 자동 탐색 경로)와 실행 파일 경로가 같은 `obs64.exe`만 종료한다. 다른 경로의 OBS는 대상이 아니다.
- **프로필 위치:** 기본 `%LOCALAPPDATA%\ShinsegaePhotobooth\ChromeProfile`. 저장소 안을 가리키면 실패한다(브라우저 자료가 Git에 섞이지 않게).
- **설정 파일:** 주석은 영어(ASCII)로 썼다. 키 설명은 README에 한국어로 있다.

### 검증 중 있었던 일

- 내 검증 명령이 `Launch.bat` 출력을 파이프(`| Select-Object`, `> $null`)로 받자 명령이 끝나지 않았다. 숨겨 띄운 서버가 그 파이프 핸들을 물려받아 서버가 끝날 때까지 파이프가 닫히지 않기 때문이다. `Shutdown.bat`으로 서버를 멈춰 풀었다. 콘솔에서 실행하면 생기지 않는다. 제약으로 SYSTEM과 README에 적었다.

## 미검증 (사용자 실측 필요)

이 PC에서 실행하면 기본 프로필 `%LOCALAPPDATA%\ShinsegaePhotobooth\ChromeProfile`이 만들어진다. 아래 순서를 권한다.

| 순서 | 할 일 | 기대 동작 |
|---|---|---|
| 1 | `settings.ini` 없이(또는 기본값으로) `Launch.bat` | `settings.ini` 생성. Chrome이 전체화면 키오스크로 열림. 첫 실행이면 카메라 권한 창 → 마우스로 "허용" → 미리보기 |
| 2 | `Launch.bat` 한 번 더 | 키오스크가 닫혔다 다시 열림. 권한을 다시 묻지 않음 |
| 3 | 키오스크에서 `Alt+F4` (선택) | 닫히는지 확인 |
| 4 | `Shutdown.bat` | 키오스크와 서버만 종료. 일반 Chrome과 OBS는 유지 |
| 5 | OBS를 정상 종료한 뒤 `Launch.bat` | OBS가 트레이로 시작, 가상카메라 켜짐, 화면이 OBS 카메라로 연결 |
| 6 | OBS를 작업 관리자로 강제 종료한 뒤 `Launch.bat` | 로그에 "Removed N leftover OBS crash marker(s)", 안전 모드 대화상자 없이 시작 |
| 7 | (다중 모니터면) `window_position`을 대상 모니터 좌표로 | 그 모니터에 키오스크 |
| 8 | `Setup-Startup.bat` → 로그아웃·로그인(또는 재부팅) | 로그인 뒤 `Launch.bat` 자동 실행. 확인 뒤 필요 없으면 `Setup-Startup.bat -Remove` |

- 키오스크에서 권한 창이 실제로 뜨고 누를 수 있는지, 번역 제안·복원 말풍선·핀치·제스처가 실제로 막히는지도 이 실측으로만 확인할 수 있다.
- OBS를 새로 띄우는 경로(순서 5·6)는 사용자 OBS가 실행 중이라 실행하지 않았다. 코드와 위 흉내 검증으로만 확인했다.
